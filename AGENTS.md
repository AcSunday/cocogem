# Development rules

- Product scope and acceptance criteria: `docs/product.md`. The unified collaboration, worktree, two-tier permission, engineering-skill and task-state contract is `docs/2026-11-13-unified-collaboration-and-engineering-skills.md`; where it conflicts with `docs/redesign.md` or `docs/2026-11-08-permissions-and-ui-redesign.md`, the newer contract wins. `docs/context-engineering.md` is historical. Deliver and verify each migration phase before updating current behavior in `docs/product.md` and the affected rules here. Do not describe proposed or fixture-only behavior as shipped or platform-verified.
- The global permission and UI migration is specified in `docs/2026-11-08-permissions-and-ui-redesign.md`; it supersedes the older workspace permission, member tool-grant and task-settings rules in the redesign RFC. Track actual validation and remaining platform limits in `docs/2026-11-08-permissions-and-ui-acceptance.md`.
- Use `cc-skills-golang:golang-how-to` for Go work and load applicable skills.
- Go 1.26.9 or newer in the 1.26 line; standard library HTTP and explicit constructor injection.
- Keep command entry points in `cmd/` and implementation in `internal/`.
- The Web workspace is the only product surface. Do not add or preserve a standalone terminal command; native CLI behavior and tests belong in `internal/nativecli/`.
- The local Claude/Codex/Antigravity/Pi/OpenCode CLIs are already usable. Reuse their existing API key, endpoint, provider and model settings; do not require login, OAuth or extra Cocogem keys. Diagnose configuration forwarding and the actual error before suggesting credential changes.
- Implement each feature with behavioral tests; commit only after its checks pass.
- Write all commit messages, pull request titles and pull request descriptions in English. Use scoped Conventional Commits `<type>(<scope>): <imperative summary>` with lowercase type (`feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `build`, `ci`, `chore`) and primary package/subsystem scope (`workflow`, `httpapi`, `nativecli`, `project`, `execution`, `contextplan`, `store`, `tools`, `workspace`, `skills`, `agent`, `server`, `contract`, `web`, `docs`, `ci`), without a trailing period (for example `feat(workflow): add relay handoffs`, `fix(nativecli): preserve selected provider endpoint`).
- Follow the project layout in `docs/product.md` and co-locate tests with their implementations.
- Keep API/OpenAPI, frontend generated types, fixtures and tests in sync.
- Never commit credentials, captured user data, databases or build output.
- Do not mark real-provider/platform verification complete based on fake tests.

- Web access uses a password set during first initialization and a local session afterward. This is independent of native CLI credentials; never require CLI login for Web access.

- Composer: Enter sends, Shift+Enter inserts a newline; preserve IME confirmation and `@` member completion. There is no `/` method menu and no preset-workflow selector. The input's top-right hint icon explains the `@` trigger on hover, focus or touch, stays within the visible viewport and has no filled hover background. Completion and modal focus restoration must not override a newer draft or caret. Picking attachments stages local files and must not create a conversation or upload them before the user sends. A run uses the single dynamic collaboration kernel: explicit `@` recipients dispatch directly, an unaddressed message goes to the conversation coordinator, and the coordinator organises further work through `handoff_task`. Do not reintroduce a data-sharing checkbox or consent gate.
- Explicit user recipients take precedence over the conversation coordinator for that submission; an unaddressed message goes to the coordinator. Show conversation errors and routing clarifications above the Composer with a dismissible circular close control in the notice's top-right corner; dismissal preserves the draft and does not submit or authorize work.
- Failed replies offer a retry for the exact member step beside that member's reply and, once per user turn, in a dismissible Composer notice. Replace the unfinished reply in the original turn with the retry's result while preserving completed peers, exact upstream references, verified candidate files and immutable step/attempt history; continue only blocked work and deduplicate accepted retries even after completion. Never replay an unverified native process or reset the root budget.

- Global member profiles are reusable across workspaces; membership manages links and enablement. Effective tools follow the global permission policy, current task and step role, conversation operation grants and actual adapter capabilities. Legacy member tool arrays and workspace Grants are historical data, not hidden permission settings for new execution. Preserve member IDs and immutable history during migrations. Deleting a global profile requires confirmation and removes its workspace links, current thread rosters and stale defaults while historical snapshots stay readable.
- Permission is a global two-tier mode saved with the Composer and Settings → Permissions: `workspace_autonomous` (default) and `full_access`. New installations default to `workspace_autonomous`; creating a workspace never resets it. Field-merge settings PATCHes preserve unrelated fields. Tool approvals offer once, conversation-wide (file or explicit parent directory) or deny; conversation grants cover all eligible members in that thread, match a three-tier action level (`read < write < execute`) plus a physical directory subtree, and never store a broad root (`/`, `$HOME`, `/Users`, top-level `/tmp`). A sensitive credential path is a one-shot `Risk="sensitive_path"` acknowledgement with no conversation grant. Revalidate live authority before effects, consume once atomically and keep uncertain effects non-replayable. Revocation and conversation deletion must not revive grants on restore.
- The Composer's per-turn 仅规划 switch sends `plan_only: true` and makes the step read-only: no write candidate is derived, native write/shell tools are withheld, file writes and side-effecting commands return a deterministic refusal without a prompt, and neither the global mode nor the permission epoch changes. Multi-recipient fan-out is read-only the same way.
- Shell-derived approval scopes use a POSIX AST parser (`mvdan.cc/sh/v3/syntax`), not whitespace splitting: device redirects (`2>/dev/null`), `jq '//'`, awk/regex literals and executables are never path targets; an unparseable command falls back to the conservative scan. A shell interpreter's `-c` script (`/bin/zsh -lc "<command>"`, including `-lc`/`-ec` clusters) is parsed as a nested command — bounded to three levels — so its redirects and path arguments are the real targets.
- Host engineering evidence: `run_test` builds its argv only from a validated enum (`auto|go|npm|pnpm|yarn|pytest|cargo`, `test|typecheck|lint|build`, bounded `filter`, relative `target`); only `test` verifies behaviour and any other kind is labelled supporting evidence. `git_inspect` is a fixed read-only `status|diff|log|show` with hooks, external diff and textconv disabled. Linux must run a real `bwrap` probe and report `linux_bwrap_userns_unavailable` instead of claiming an unverified boundary.
- `preview_page` takes no URL or port: the host serves a project-relative entry on a single ephemeral loopback origin, or runs the exact preview argv on an assigned port in its own process group. A CDP interceptor aborts everything except that one origin and `data:/blob:`; the screenshot becomes an image source and nothing is written into the project or candidate worktree. Read-only turns may only use `static` mode; a missing browser engine reports `browser_engine_unavailable`.
- A candidate diff with three or more net added fallback branches carries a non-blocking hygiene hint in the write observation and the candidate verdict; the hint never changes `verified` into a failure.
- Show each member's actual tool activity in their reply, collapsed by default. Pending authorization stays visible outside all process disclosures. Treat permission waiting as an intermediate state of the same invocation and preserve run/step/attempt/call identity. The collaboration sidebar retains sources and artifacts; it has no process tab.
- Every run uses the existing scoped MCP bridge for bounded handoff_task (delegate or peer-to-peer relay), read_skill and get_task calls. Plain assistant @ text never dispatches work. Independent review uses submit_review_verdict; the same reviewer may request at most two rework rounds for one author and issue before the host requires delivering the remaining disagreement.
- Collaboration staffing keeps explicit user recipients first; an unaddressed message goes to the conversation coordinator, which may then choose teammates from the runtime roster by responsibility, capabilities and actual tool grants. The host validates membership, tools and identity (an independent reviewer may not be the author). Deterministic roster order is only a fallback.
- Shared skills have one source under internal/skills/library and use runtime roles/capabilities. Never bind skill text to concrete members, handles, CLI brands or model names. Track enabled skill versions per Run.
- The built-in library is exactly ten skills; every description states `Use when` / `Not for` / `Output` within 240 characters and every body stays within 90 lines, enforced by `library_test.go`. Cross-skill method lives in `library/_shared/references/` and is readable via `read_skill(skill_id="_shared")`; any skill or `_shared` change invalidates the run snapshot. Project skills under `.agents/skills/<id>/SKILL.md` are read-only, capped at eight, never shadow a built-in and reject symlink escapes and sensitive paths.

- File tasks follow the user's requested result and format. Project-autonomous native operations use the verified adapter/OS boundary and request an exact extra scope before an outside effect; full_access retains trusted native file/command/image tools and scoped host fallbacks. Research output does not require engineering/develop mode. Use the task directory when no project directory is bound, and preserve read-only/reviewer restrictions. Installation, protocol fixtures, OS boundary checks and real-provider tasks are separate evidence.
- Accept attachment originals independently of text extraction. Publish actual output bytes as immutable, authenticated downloads; a path or Markdown response cannot replace a requested file. Never automatically replay trusted native execution after an uncertain effect.

- Ordinary unpromoted single-member chats (`thread.TaskID == ""`) write directly to the bound `Workspace.Root` inside the OS sandbox so lightweight edits stay zero-friction. Durable tasks (including `promote_to_task` upgrades) and parallel delegated subtasks keep the bound project byte-identical until the reader applies a candidate: derive writable work with `git worktree add --detach` (bounded file copy for non-git or unborn HEAD) and record a `BaseSnapshotOID`, carrying the user's uncommitted tracked and untracked non-sensitive files. One owning scope may hold only one live candidate per source root, reused across turns until Apply or Discard. Preview live changes via `GET .../candidates/{id}/diff`, export a local Git branch (`cocogem/cand-<shortID>`) via `POST .../export-branch` for conflict recovery, and Apply by comparing only affected files against `BaseSnapshotOID` (preserving agent `git commit`s, allowing non-overlapping parallel subtasks, refusing external edits/deletions with 409) before reclaiming the worktree. Both Apply and Discard require explicit confirmation and stay locked while a run is active. Show `CandidateVerification` (`verified` only with a diff and a passing test after the last write) beside the candidate; never present an unverified mutation as verified.
- Attachments and deliverables live under `$COCOGEM_DATA_DIR/io/<thread|task>/{inputs,outputs}`, never inside the code candidate. Reviewer and critic steps run in a disposable `verify_dir` copy of the author's exact tree with a fresh native session, and the author candidate digest must be unchanged afterwards.
- Soft-deleting a conversation to the trash freezes its unapplied candidates and IO area; permanent delete, retention purge and workspace deletion reclaim them plus `git worktree prune`. A root change with pending candidates returns 409 and seals the old native sessions.
- Never delete or rewrite the user's native CLI session directories. Resumable sessions live in each CLI's own home; do not override `CODEX_HOME`/`CLAUDE_CONFIG_DIR` with a temp root or add a routine ephemeral flag. Only a disposable reviewer `verify_dir` run is ephemeral. Revocation seals only the Cocogem ledger (`status=revoked`, cleared native session id) so no `--resume` is attempted again.

- Task workspace: home and every conversation belong to the first rail icon; only task lists/details belong to tasks. Keep direct links, reload and history navigation consistent.
- The task board is one batched read transaction, never a per-task query: pending authorizations, open questions, active and attention-bearing child counts and an unapplied candidate summary all come from bulk reads. A task-blocking question writes `WaitingReason="question"` atomically with the question, and answering the last one restores ready. Active children keep a parent out of review. Every surface shares the single `taskPhaseMeta` classifier; there is no duplicate category module. A completed task's conversation reopens by advancing a new revision instead of returning 409.
- Simple chat must not create a Task. Use the first model invocation and scoped promote_to_task for semantic promotion; the host validates the actual user instruction, binds state atomically and either dispatches teammates in that same turn (via handoff_task) or starts a fresh execution step in the same conversation. Mentions and tool use alone are not promotion criteria.
- Tasks may be saved before a conversation exists. First launch creates/binds the conversation and queues actual execution; creation/launch retries must not duplicate work or replay uncertain effects. Preserve historical task/member IDs, messages, revisions and root budgets. Run success means pending acceptance; acceptance of a reply requires an exact successful Delivery from that Task.
- Task details have no task-settings or reference-sources feature, related forms or source-processing path. Keep conversation sidebar sources and actual artifact downloads. The human acceptance button opens a dialog with a frozen task/revision/evaluation/candidate snapshot; changed targets require a fresh review. Remove task-page manual pause/cancel/goal/budget editors. Configure future root budgets only in Settings → Collaboration; roots keep separate cumulative ledgers and their existing policy and usage.
