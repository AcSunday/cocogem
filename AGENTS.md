# Development rules

- Product scope and acceptance criteria: `docs/product.md`.
- For the approved redesign, read `docs/redesign.md` as the target implementation contract; `docs/context-engineering.md` is historical. Deliver and verify each migration phase before updating current behavior in `docs/product.md` and the affected rules here. Do not describe proposed or fixture-only behavior as shipped or platform-verified.
- The global permission and UI migration is specified in `docs/2026-11-08-permissions-and-ui-redesign.md`; it supersedes the older workspace permission, member tool-grant and task-settings rules in the redesign RFC. Track actual validation and remaining platform limits in `docs/2026-11-08-permissions-and-ui-acceptance.md`.
- Use `cc-skills-golang:golang-how-to` for Go work and load applicable skills.
- Go 1.26.9 or newer in the 1.26 line; standard library HTTP and explicit constructor injection.
- Keep command entry points in `cmd/` and implementation in `internal/`.
- The Web workspace is the only product surface. Do not add or preserve a standalone terminal command; native CLI behavior and tests belong in `internal/nativecli/`.
- The local Claude/Codex/Gemini CLIs are already usable. Reuse their existing API key, endpoint, provider and model settings; do not require login, OAuth or extra Cocogem keys. Diagnose configuration forwarding and the actual error before suggesting credential changes.
- Implement each feature with behavioral tests; commit only after its checks pass.
- Write all commit messages, pull request titles and pull request descriptions in English. Commit messages follow Conventional Commits (`feat: ...`, `fix: ...`, `test: ...`).
- Follow the project layout in `docs/product.md` and co-locate tests with their implementations.
- Keep API/OpenAPI, frontend generated types, fixtures and tests in sync.
- Never commit credentials, captured user data, databases or build output.
- Do not mark real-provider/platform verification complete based on fake tests.

- Web access uses a password set during first initialization and a local session afterward. This is independent of native CLI credentials; never require CLI login for Web access.

- Composer: Enter sends, Shift+Enter inserts a newline; preserve IME confirmation, `@` member completion and `/` method completion. The input's top-right hint icon explains both triggers on hover, focus or touch, stays within the visible viewport and has no filled hover background. Completion and modal focus restoration must not override a newer draft or caret. Picking attachments stages local files and must not create a conversation or upload them before the user sends. Free collaboration uses `@` or natural-language routing without an automatic-assignment control; the coordinator decides the method when the user selects none, and a chosen method shows a dismissible chip. Do not reintroduce a data-sharing checkbox or consent gate.
- Explicit user recipients and natural-language assignments take precedence over the selected workflow and default roles for that submission; use the workflow when no new assignment is given. Show conversation errors and routing clarifications above the Composer with a dismissible circular close control in the notice's top-right corner; dismissal preserves the draft and does not submit or authorize work.
- Failed replies offer a retry for the exact member step beside that member's reply and, once per user turn, in a dismissible Composer notice. Replace the unfinished reply in the original turn with the retry's result while preserving completed peers, exact upstream references, verified candidate files and immutable step/attempt history; continue only blocked work and deduplicate accepted retries even after completion. Never replay an unverified native process or reset the root budget.

- Global member profiles are reusable across workspaces; membership manages links and enablement. Effective tools follow the global permission policy, current task and step role, conversation operation grants and actual adapter capabilities. Legacy member tool arrays and workspace Grants are historical data, not hidden permission settings for new execution. Preserve member IDs and immutable history during migrations. Deleting a global profile requires confirmation and removes its workspace links, current thread rosters and stale defaults while historical snapshots stay readable.
- Permission mode is global and synchronized between the Composer and Settings → Permissions. New installations and the one-time legacy migration default to project_autonomous; creating a workspace never resets it. Field-merge settings PATCHes preserve unrelated fields. Tool approvals offer once, conversation-wide or deny; conversation grants cover all eligible members in that thread and the exact tool/action/resource scope. Revalidate live authority before effects, consume once atomically and keep uncertain effects non-replayable. Revocation and conversation deletion must not revive grants on restore.
- Show each member's actual tool activity in their reply, collapsed by default. Pending authorization stays visible outside all process disclosures. Treat permission waiting as an intermediate state of the same invocation and preserve run/step/attempt/call identity. The collaboration sidebar retains sources and artifacts; it has no process tab.
- Free collaboration uses the existing scoped MCP bridge for bounded handoff_task (delegate or peer-to-peer relay), read_skill and get_task calls. Plain assistant @ text never dispatches work; built-in workflows keep their accepted plans while allowing structured submit_review_verdict convergence.
- Built-in workflow staffing keeps explicit user assignments and configured role defaults first, then asks the coordinator to fill only open roles from the runtime roster by responsibility, capabilities and actual tool grants. The host validates membership, tools and exclusive roles; deterministic roster order is only the fallback. The coordinator may fill a worker role only when no other eligible member exists.
- Shared skills have one source under internal/skills/library and use runtime roles/capabilities. Never bind skill text to concrete members, handles, CLI brands or model names. Track enabled skill versions per Run.

- File tasks follow the user's requested result and format. Project-autonomous native operations use the verified adapter/OS boundary and request an exact extra scope before an outside effect; full_access retains trusted native file/command/image tools and scoped host fallbacks. Research output does not require engineering/develop mode. Use the task directory when no project directory is bound, and preserve read-only/reviewer restrictions. Installation, protocol fixtures, OS boundary checks and real-provider tasks are separate evidence.
- Accept attachment originals independently of text extraction. Publish actual output bytes as immutable, authenticated downloads; a path or Markdown response cannot replace a requested file. Never automatically replay trusted native execution after an uncertain effect.

- Task workspace: home and every conversation belong to the first rail icon; only task lists/details belong to tasks. Keep direct links, reload and history navigation consistent.
- Simple chat must not create a Task. Use the first model invocation and scoped promote_to_task for semantic promotion; the host validates the actual user instruction, binds state atomically and either dispatches teammates in that same turn (via handoff_task or choose_workflow) or starts a fresh execution step in the same conversation. Mentions, workflow choice and tool use alone are not promotion criteria.
- Tasks may be saved before a conversation exists. First launch creates/binds the conversation and queues actual execution; creation/launch retries must not duplicate work or replay uncertain effects. Preserve historical task/member IDs, messages, revisions and root budgets. Run success means pending acceptance; acceptance of a reply requires an exact successful Delivery from that Task.
- Task details have no task-settings or reference-sources feature, related forms or source-processing path. Keep conversation sidebar sources and actual artifact downloads. The human acceptance button opens a dialog with a frozen task/revision/evaluation/candidate snapshot; changed targets require a fresh review. Remove task-page manual pause/cancel/goal/budget editors. Configure future root budgets only in Settings → Collaboration; roots keep separate cumulative ledgers and their existing policy and usage.
