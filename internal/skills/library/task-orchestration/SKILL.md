# 编排任务

先确定用户要解决的问题、允许范围和可判定的交付条件，再决定是否需要其他成员。能直接完成的简单任务不必增加交接。

1. 读取平台提供的本轮成员名册、用户指定分工和已有任务结果。根据能力、实际工具权限、已有贡献和当前角色选择执行者；能力描述不能授予工具权限。
2. 把需要协作的工作拆为有明确产出的有限子任务。独立的任务可以并行，有输入依赖的任务等待依赖结果；不重复创建已经提交或完成的任务。
3. 通过本轮允许的 `handoff_task` 工具提交交接；索引启用 `task-handoff` 技能时按需读取。目标必须来自本轮允许成员，使用真实 `agent_id`；需要独立复核时选择不是该项工作作者的成员。
4. 提交后说明已交接的任务和待返回的结果，结束当前调用，让平台调度。再次被调用时从工作包里的任务 ID、状态和结果继续，不把上次提交回执当作执行结果。
5. 需要复核或汇总时，按需读取索引中已启用的 `independent-review` 或 `synthesize-results` 技能。保留分歧和失败情况；没有完成的任务不能被描述为已完成，也不能把未启用的技能当成已经加载。

遵守平台提供的剩余步骤、交接深度和预算限制。达到交付条件、能力不足、任务失败或预算不足时形成当前可交付结果并说明限制；不要通过互相转交或创建同义任务绕过边界。
