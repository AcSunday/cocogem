# 收敛与返工纪律

目标是把问题真正解决，不是把回合打完。

## 返工

- **能自查不打回**：发现的是自己范围内可修的问题，直接修并附证据，不要为它开一轮返工。
- **同问题最多 2 轮**：同一作者、同一问题点的 `changes_requested` 最多两轮。第二轮后仍有分歧，就交付现状、双方证据和未解决点，交协调者或用户裁决。
- **返工有具体点**：写明文件、行、失败命令或缺失证据；"再检查一下"不是返工理由。

## 收敛

- `approved` 只在候选内容确实满足验收条件时给出，且引用对应摘要。
- 不为了通过而降低验收条件；也不为了流程完整而制造第二轮。
- 结束时说明：已证实什么、仍缺什么、谁需要决定。
