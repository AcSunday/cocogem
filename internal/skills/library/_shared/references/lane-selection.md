# 车道选择（五轴风险）

用五个轴判断这一轮需要多重的流程，不要默认走完整流程，也不要默认单干。

1. **可逆性**：改动能否一步撤回？不可逆的外部写入（发布、部署、系统安装、`git push`）至少需要独立复核。
2. **影响面**：只影响一个局部函数，还是跨模块契约、数据迁移、权限边界？跨契约时先写方案再动手。
3. **证据可得性**：能否用现有测试、`git_inspect`、`preview_page` 得到客观结论？拿不到客观证据时要升到独立复核。
4. **异构性**：作者与复核者的模型、CLI 或职责是否真的不同？同一成员换个角色名不算独立。
5. **持续性**：一次问答能收尾，还是需要多轮、多个子目标、跨会话推进？后者应升级为持久任务。

## 结论

- 局部、可逆、证据充分 → 单人快车道直达。
- 有风险但边界清楚 → 执行者 + 独立复核（`relay`）。
- 跨阶段、可并行、需持续跟踪 → 升级为持久 `Task`，用 `delegate` 并行子任务。
