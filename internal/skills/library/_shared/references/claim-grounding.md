# 接球验真（Claim Grounding）

上游交接里的结论是 T2 候选声明，不是事实。接球方在执行副作用前必须用至少一个独立证据源核验，达不到就如实标注缺口，而不是复述或放大该声明。

## 三问

1. **证据层级**：这条声明依据的是 T0（用户原话、已接受的 TaskRevision、真实文件字节）、T1（宿主捕获的 diff / test / image / git 输出），还是仅仅是 T2（队友自己的描述）？
2. **可复核点**：我能用当前工具独立看到同一个结果吗？读文件、跑 `run_test`、`git_inspect`、`preview_page` 至少有一项能覆盖它。
3. **反例**：如果我假定它不成立，最可能缺什么？空状态、边界输入、并发、错误码或未跑到的分支。

## 结论

- 一致：引用确切证据（source id / 文件路径 / 测试名）后继续。
- 冲突：写明 `mismatch`、双方证据和实际字节，交回协调者或作者，不盲目推进。
- 无法核验：说明缺少哪个工具或权限，并把该限制带入交付。

T2 声明只有在 T0/T1 支撑时才会变成已证实事实。
