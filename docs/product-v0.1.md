# Cocogem v0.1 产品与实现规格

版本：0.1 / 2026-10-20。状态：CLI 执行路径已修正并有实际页面协作样例，发布验收仍有门禁；证据见 [实现进度](development-progress.md)。面向本地单用户的开源应用。

本文是第一版的范围、交互、接口与验收依据。勾选完成项必须附实现和验证证据；修改范围时先更新本文，再调整代码与测试。新增依赖和跨模块契约变更需在 PR 中说明理由。

## 1. 产品定位

**Cocogem 是一个由 Go 驱动、带交互式 Web 前端的多 Agent 协作工作空间。** 用户围绕一个主题组织多个 Agent，开展讨论、Research、资料整理和代码分析，保留协作过程、来源与产物，并继续追问。

工作空间和会话是产品的核心。代码分析是工作场景之一；系统的会话、角色、编排、工具、事件、资料和产物不绑定软件开发领域。

第一版要回答三个问题：

1. 多个 Agent 如何围绕同一个问题分工、交流并交付结果？
2. 用户如何看清过程、补充问题、控制执行，并核对结果依据？
3. 新贡献者能否在没有模型凭证的情况下测试和理解项目？

### 1.1 目标用户与成果

| 用户 | 核心需求 | v0.1 交付 |
| --- | --- | --- |
| 个人知识工作者 | 组织资料研究、比较观点、生成报告 | Research 会话、来源查看、报告导出 |
| 开发者 | 理解仓库、定位问题、独立复核结论 | 本地代码读取、分析与复核、文件证据 |
| Agent 学习者与贡献者 | 理解并扩展 Agent 的运行机制 | CLI 原生循环、Go 协作与工具边界、隔离自动化测试 |

首版成功标准：用户能在网页完成创建工作空间、选择成员、发起三类协作、观察真实执行、查看来源与产物、取消、继续追问和重新打开历史的完整流程。

## 2. 范围与明确取舍

### 2.1 v0.1 必交付

| 编号 | 能力 | 交付边界 |
| --- | --- | --- |
| F01 | 工作空间 | 创建、编辑名称和说明、确认后永久删除；可在页面浏览选择或填写本机资料目录，保存时校验存在和可读，遵守显式配置的目录范围 |
| F02 | Agent 成员 | 内置角色；创建、编辑、停用成员；设置显示名、handle、别名、职责、模型和允许工具 |

| F04 | 协作编排 | 自由协作、协作讨论、Research、代码分析；有限串行与并行步骤 |
| F05 | 原生 Agent | 本机 CLI 执行、复用现有连接配置、CLI 工具循环、流式输出、按现有授权派生的原生只读工具和受控宿主工具 |
| F06 | 工具与来源 | 本地读取/搜索、公共网页检索/读取、来源记录及证据查看 |
| F07 | 交互前端 | 实时过程、工具详情、来源面板、产物面板、取消与重试 |
| F08 | 产物 | 笔记、Research 报告、代码分析报告；历史版本、人工标记、Markdown 导出 |
| F09 | 可靠性 | 持久记录、有限排队、幂等提交、断线续读、取消与启动恢复 |
| F10 | 开源工程 | 文档、许可证、贡献说明、CI、契约测试、浏览器端到端测试 |

网页执行以本机已可用的 Claude/Codex/Gemini CLI 为载体，直接复用 CLI 现有连接与模型配置，不要求额外登录或配置模型 API Key。成员显式选择 CLI，模型默认沿用该 CLI 的默认值，也可指定。已有 API Key/服务地址/供应商设置按连接字段白名单复用，不强制改为 OAuth，也不要求重新登录。安装与版本探测不等于连接或模型已验证。

CLI 负责模型调用和工具循环，Go 负责成员身份、路由、上下文工作包、流程调度、权限、来源和产物。网页运行只从成员现有工具授权派生 CLI 原生只读能力，不新增授权开关：`read_file→Read`、`list_files→Glob`、`search_content→Grep`；仅在 `auto`/`web_discovery` 范围下 `web_search→WebSearch`、`fetch_url→WebFetch`。`given_sources` 和空 scope 不启用原生联网，宿主 `fetch_url` 范围保持不变。原生工具与本步受控 MCP 工具并存：系统提示按本步实际启用项列出原生工具名及对应 MCP fallback，并只把这些 MCP 工具说明为在该原生工具失败（引用确切错误）或无可使用内容后使用；这是提示与工具描述层面的优先约束，不是硬性拦截，MCP 后备始终保留。`Bash`/`Edit`/`Write` 及内置 `Task`/`Agent`/`Skill` 等不暴露。Claude 原生文件读取使用 `--restricted`、独立配置目录、工作区根作为 cwd 和敏感路径 deny；实测 deny 只对 cwd 生效、不覆盖 `--add-dir`，因此文件步骤不使用 `--add-dir` 读取工作区，并以隔离环境变量禁用 `CLAUDE.md` 自动加载；纯联网或无文件步骤仍用空 cwd。配置目录不可被原生工具读取，工作区根不安全时降级为 MCP 文件工具。Codex 的合并 web 工具只在成员同时具备两项联网授权且范围允许发现时启用，并向 scoped provider 声明 Responses web 能力；上游不支持时按实际错误显示，结果按线索保存；Gemini 的 stream-json 工具结果不暴露实际返回正文，因此保持 MCP 联网并记录能力缺口。不能可靠限制工具的 CLI 版本必须标记不支持并阻止启动，不能为兼容放宽权限。现有独立终端 CLI 行为保持兼容，其默认权限不代表网页权限。

在线搜索优先使用 Brave Search（`BRAVE_SEARCH_API_KEY`）。未配置 Brave 时使用无密钥公共搜索回退（Bing RSS，失败后 DuckDuckGo HTML），可用 `COCOGEM_SEARCH_PROVIDER=auto|brave|bing|duckduckgo|public|off` 控制。需要代理访问公共网页时，用 `COCOGEM_WEB_PROXY` 指定 http/https/socks5 地址，或设为 `env` 复用 `HTTPS_PROXY`/`HTTP_PROXY`，或设为 `system` 复用 macOS 已配置的 HTTP/HTTPS/SOCKS 代理（只读取代理主机和端口，不读取 PAC、订阅或凭据）；`make dev` 未设置时使用 `system`，显式空值保持直连。同一解析结果仅在启用原生联网的步骤传给 CLI 子进程，并合并既有 `NO_PROXY`、保留 loopback MCP 直连；它也可能影响该子进程的模型连接路径，这一点在文档中明示。原生联网的实际域名安全检查和网络策略由 CLI/供应商负责，不是 Go `ValidateURL`/DNS/重定向/SSRF 保证；宿主 `fetch_url` 仍是受控路径。探测请求不带代理解析结果。Web 会话默认按任务自主研究（`research_scope=auto`）：用户可在消息中直接贴公共 URL，也可不提供链接；成员按需要主动搜索、读取原文和独立复核，不要求用户预先整理资料。搜索不可用时仍可读取公开 URL 和本地资料，并明确说明搜索限制，不静默改成已有知识回答。API 显式请求 `web_discovery` 时缺少搜索仍报不可用，旧 `given_sources` 及历史 Run 的范围保持兼容。搜索查询会发送给对应搜索服务。

### 2026-10-24 协作扩展约定

本节覆盖下文中“成员属于单一工作空间”“只执行静态计划”“无自主交接”的旧版边界，其余资料、鉴权和工具权限边界继续适用。

- 成员是本机全局档案；工作空间引用成员并设置启用状态和工具授权。有效权限取全局档案与工作空间授权交集。迁移保留所有成员 ID、历史和配置，不按名称自动合并。全局称呼可以重名，加入同一工作空间时检查路由冲突。
- 会话选择最多四名成员及协调者。自由协作允许这些成员在原始用户任务范围内通过受控 `handoff_task` 提出任务；显式用户分工和禁止事项优先。内置讨论、Research、代码分析继续使用明确步骤计划。
- 平台向每次调用提供本轮成员配置快照、任务状态、原始目标和必要上下文。每次派发仍检查当前成员启用状态、工作空间关系和权限撤销。凭证不进入名册、技能、事件或浏览器。
- `handoff_task(request_id,target_agent_id,task,role,context_refs)` 在调用者步骤内幂等，返回任务 ID、结果回传步骤 ID 和接收状态；回执不等于执行完成。目标限本轮会话成员，不接受跨工作空间或虚构目标，复核者不得是被复核内容作者。普通回复中的 `@` 不触发派发。
- 异步任务和后续调用仍持久化为当前 Run 的 Step。成员提交交接后结束当前调用；平台执行任务，待依赖结果成功或失败后新调用原成员继续处理。CLI 进程不阻塞等待，不承诺运行中消息推送。支持独立任务并行；每轮最多十二次交接、三十二个步骤、四层委派，并受可配置的 Run/Step 执行时限约束。
- 提交、结果及回传都使用事务与持久事件。失败不得伪装成功，回传可报告或处理队友失败；取消整轮停止所有后续调用并保留已有结果。重启时先核实旧执行归属和已提交记录，从未完成步骤继续；无法核实的外部结果保留 interrupted，不自动重放。
- 共享技能参考 Clowder：单一 `internal/skills/library/<skill-id>/SKILL.md` 源目录，名称/描述索引、正文和参考文件逐级读取，程序嵌入同源资源发布。隔离 CLI 通过 `read_skill` 读取启用的技能，无需开放原生文件/脚本权限。工作空间可以选择启用项；null 使用默认全部，空列表全部停用；Run 保存版本摘要，读取记录可追踪。
- 技能只写通用角色、能力和协作方法，不绑定具体成员名、handle、成员 UUID、CLI 品牌或模型。选人来自本轮动态名册，身份、CLI 和临时角色独立。
- 验收包含全局成员跨空间复用与权限隔离、旧数据迁移、名册/技能读取、幂等交接、并行/嵌套回传、失败/取消/重启，以及真实本机不同 CLI 的研究—独立复核—汇总流程。模拟协议测试与真实供应商证据分别记录。

首版支持用户直接输入问题、添加公共 URL、绑定本地文本资料。图片、音视频和文件上传不在本版范围。

### 2.3 运行边界

- 一个 Go 服务、一个 SQLite 数据库、一套同源 Web 前端；先支持 macOS 和 Linux。
- 默认仅监听 `127.0.0.1`，首次初始化设置工作空间密码，后续用密码建立本地会话；v0.1 不提供公网部署模式。
- 默认同时运行一个 Run；其内部可以有多个并行 Agent 步骤。其余 Run 持久排队，队列最多 20 项。
- 每个会话选择 1–4 个成员；内置流程至少需要两个不同成员。缺少所需角色时在发送前提示。
- 模型认证由对应 CLI 管理；宿主只白名单转交连接配置，不把凭证写入应用数据、事件或网页。搜索凭证由服务端环境变量提供。网页仅显示 CLI 安装、版本、适配支持和显式验证结果。
- 发布物包含 Go 可执行文件和构建好的前端资源；用户运行发布物无需 Node.js。

## 3. 核心对象与用户语言

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| Workspace / 工作空间 | 一组会话、成员及可使用的资料范围 | “Agent 学习与选型” |
| Agent / 成员 | 有稳定身份、职责、模型和工具权限的参与者 | “研究员”“质疑者”“协调者” |
| Thread / 会话 | 围绕一个主题持续协作的现场 | “比较三种 Agent 开发方式” |
| Message / 消息 | 用户输入或一个成员的可见回复 | 一个问题、一段阶段性分析 |
| Run / 本次协作 | 一次用户发送触发的有限执行过程 | 本轮 Research 及复核、汇总 |
| Step / 步骤 | 一个成员承担的一次 Agent 调用 | 研究、复核、汇总 |
| Source / 来源 | 实际读取并保存出处的资料 | 网页片段、文件行区间 |
| Artifact / 产物 | 可独立查看、继续修订和导出的结果 | 研究报告、讨论笔记 |

一个会话可以产生多次 Run；每次成功 Run 在同一事务中记录最终消息 ID 与确切产物版本的交付引用，会话产物列表只展示该交付。用户补充问题会创建新 Run，保留前序记录；旧历史没有交付记录时不回填、不推断。

### 3.1 成员身份、名称与职责

| 字段 | 用途与规则 | 示例 |
| --- | --- | --- |
| `agent_id` | 服务端 UUID，稳定身份；消息、权限、会话、步骤均使用它关联 | 页面通常不直接显示 |
| `display_name` | 用户可编辑的展示名，支持中文；同名时显示 handle 区分 | 布偶猫 |
| `handle` | 工作空间内唯一的明确路由标识；小写字母开头，后接字母/数字/连字符，总长 2–32 | ragdoll |
| `aliases` | 自然语言可用的称呼；去除两端空白后精确解析，不做模糊昵称猜测 | 布布、布偶 |
| `role_description` | 常用职责；本次流程的具体角色由 assignments 决定 | 擅长资料研究与方案整理 |
| `model` / `tools` | 执行能力与权限，独立于名称 | 已配置模型与允许工具集合 |

用户可以把成员命名为布偶猫、缅因猫、橘猫，也可以使用其他主题。名称、模型和任务角色各自独立：更换模型或名字不创建新成员，布偶猫也可以在不同任务中承担不同职责。

handle 和显式别名在同一工作空间的路由词表中不得指向多个成员；创建/编辑时检查冲突。展示名允许重名，或与另一成员的路由词冲突，此时该称呼被标为歧义，要求选定确切 handle；不能因扫描顺序而选中某个成员。不同工作空间使用各自词表。

改名保留 agent_id。历史消息和 Run 保存当时的展示名与配置 revision，界面可查看当前身份；不得重写历史标签、丢失会话或将历史引用改指其他成员。旧称呼只有被用户明确保留为别名时才继续参与新消息路由。成员配置页实时显示可用称呼、冲突和将使用的模型/工具。网页 `@` 补全显示中文名称，实际选择绑定 agent_id，输入其他语言的名字也不影响身份关联。

## 4. 首次使用与日常流程

### 4.1 首次打开

1. 启动服务，打开本地页面；首次设置密码，之后用密码解锁。
2. 展示真实模型、在线搜索和本地资料目录的可用情况；“已配置”不等于“已连通”。CLI 安装、调用方式/工具隔离和模型连接分别显示；连接验证绑定当时的 CLI 程序身份，CLI 升级或被替换后旧验证不再显示为有效。
3. 用户创建工作空间，填写名称、说明，可点击“浏览目录”逐层选择文件夹、返回上级，或直接输入本机资料目录路径。浏览仅展示可访问的非隐藏文件夹，过滤已知敏感目录与软链接，不读取文件正文；取消不更改原值，选择后保存工作空间才生效。未配置启动目录限制时，从本机主目录开始；配置了允许范围时，从允许目录列表开始，仅能进入其中的目录或子目录。保存路径规范化为真实绝对路径，拒绝不存在、不可读、普通文件及已知敏感目录，空路径表示不绑定。
4. 初始化三个可编辑成员：研究员、质疑者、协调者。三个成员可使用同一个模型，但身份、上下文及职责分别保存。
5. 提供“协作讨论”“Research”“代码分析”入口和示例问题。本机 CLI 不可用时保留历史和设置访问，并提示检查安装、现有连接配置和验证结果。

问题和任务读取的资料片段会通过本机 CLI 发送给配置的模型服务；在线搜索会向搜索服务发送检索词。此说明保留在服务设置和文档中，不设置额外的确认复选框或执行拦截；历史空间无需补确认。

### 4.2 发起协作

1. 新建会话，输入标题或使用首条问题的前 40 个字符作为标题。
2. 选择流程与参与成员；角色分工默认值来自全局设置，显式自然语言或 `@` 指派仍按路由解析。链接可直接写入问题，也可不提供链接，由成员主动查证。代码分析须已绑定本地目录。
3. 输入问题。发送区显示本次流程和实际收件人，权限或凭证缺失时说明具体原因。
4. 按 Enter 或点击发送后完成路由解析；Shift+Enter 换行。中文输入法组合期间的 Enter 仅确认输入，@ 补全的 Enter 先选成员；空白、提交中或执行中不能发送。明确且提交成功时展示持久化的用户消息与排队状态，有歧义时保留草稿并请求澄清。
5. 执行时显示当前步骤、成员回复、工具活动、耗时及来源；不要显示虚构进度百分比。
6. 完成后展示所有成员贡献和最终产物，用户可打开证据、标记产物、复制或导出。

### 4.3 持续协作

- 用户可在同一会话继续追问、切换本次流程，用选中成员、`@成员` 或明确自然语言指令指定回应者。
- 执行期间输入内容保留为草稿；本会话未结束前不能再次发送。用户可以停止后发送补充问题。
- 切换会话、刷新页面和关闭浏览器不终止后台 Run。

## 5. 三类场景与自由协作

### 5.1 自由协作

用于普通问答、资料整理及定向讨论。指定一个成员时调用该成员；指定多个成员时并行回应，首版不额外调用模型汇总。

显式收件人可以通过成员选择器或 `@handle` 指定。解析排除代码块和行内代码；未知或歧义称呼在发送预览中提示，不静默换人。

没有显式收件人时，先判断当前用户消息是否含自然语言指派；没有指派则按所选流程执行，未选择流程则发送给会话协调者。提到某个名字本身不等于指派。

没有显式收件人或流程时，协调者在同一次调用中判断任务是否需要多人方法，并选用：**直接回答**（简单问答，不额外建步骤或强制产物）、**自由分工**（在原始任务范围内把明确子任务交给名册内成员）、**协作讨论**（独立观点、交叉质询与收敛）、**Research**（需要外部证据）或**工程分析**（只读工程分析，兼容旧代码分析）。只有后面三种需要用本轮受控的 `choose_workflow` 工具提交计划；直接回答不调用选择工具，自由分工沿用交接工具。方法选择不能靠关键词或最新消息猜测；简单问题直接回答。选择只接受本轮真实成员 ID 与对应角色，并持久化到 Run 的 `selected_workflow`（方法、参与成员、角色、原因、计划步骤与时间）；成功完成后 `method` 记录实际方法（direct、delegation 或所选流程）。已接受的用户流程、显式分工和已提交交接优先且不可被改写；缺少成员或权限时如实说明并请求澄清，不猜人、不扩容。

界面只展示持久记录的方法和可读原因，不从最新消息推断；全局协作设置只保存内置流程的角色默认值，自由协作不提供按模式的手工“自动分工”控件。过程视图保留原始事件供调试，但默认以可读文本呈现有意义的 `workflow_selected` / `method_recorded`，不刷无意义的协议通知。

### 5.1.1 自然语言指派

| 当前用户消息 | 预期解释 |
| --- | --- |
| “布偶猫帮我调查一下 Go Agent 框架” | 给布偶猫的单成员研究任务；不因“研究”二字擅自追加复核者 |
| “布偶猫和缅因猫分别给个意见” | 两个明确目标并行回答，不自动增加汇总步骤 |
| “布偶猫查资料，缅因猫复核，橘猫汇总” | Research 流程的明确角色分配与顺序 |
| “我觉得布偶猫做 Research 挺好” | 普通讨论，不唤醒布偶猫执行任务 |
| “如果让布偶猫来研究，会有什么问题？” | 假设讨论，不把假设当成执行指令 |
| “不要让布偶猫处理这个” | 保留否定约束，不派给布偶猫；仍缺少正向任务时按普通讨论处理 |
| 代码块或引文中出现“布偶猫帮我……” | 资料中的称呼不直接产生任务 |
| “让小猫研究一下”且存在多个匹配成员 | 请求选择成员；不猜测 ID |

实现分两步：

1. Go 解析显式选择与 `@handle`，从工作空间词表提取自然语言中的候选成员，保留最长名称匹配与准确位置。这里只定位称呼，不用堆积关键词正则决定复杂语义。
2. 对需要解释的自然语言消息进行一次有界模型解析，输出结构化路由建议：`assign / discuss / clarify`、确切成员 ID、对应任务、否定约束，以及可映射的既有流程/角色。解析器只接收当前用户输入、成员词表和必要的路由上下文；不能调用工具或执行任务。

服务端验证模型输出：成员必须真实存在且可用；分配必须有当前用户指令依据；不能覆盖明确选择、添加未要求的成员、扩大权限、把引用/条件/否定当成授权，或生成循环流程。首版只映射已有单步、并行回应和内置流程；超出能力时明确说明并让用户选择现有流程，不自动接纳任意图。

结构化输出还需给出任务所对应的原文位置，服务端核对其确实来自当前消息。格式、身份、范围和流程验证可以确定性完成；复杂语义仍可能被模型误判，需通过可见解释、歧义澄清及否定/引用等负例评测控制风险，不能把 JSON 校验称为意图理解正确性的证明。

显式选择和 `@handle` 的优先级高于模型建议。明确指派与手选流程冲突时展示冲突；语义不清时展示一句具体澄清及成员选项，保留草稿。模型给出的置信度数字不能代替这些验证。

明确点名的工作空间成员可以随本次发送加入会话，受四成员上限约束，并在发送预览中展示；模型不能自行拉入其他成员。引用网页、历史产物或其他 Agent 回复不获得当前用户指令的权限。

### 5.1.2 预览与提交

- 输入框保留工作方式、实际协调者和路由解释；会话内不提供角色分工编辑，默认分工来自全局设置，接受路由后的分工摘要保持可见。不提供“资料”按钮、链接表单或研究范围选择。链接直接写入问题，默认自主研究；不在每次按键时调用模型。
- 点击发送后先解析。结果明确时直接接着提交 Run，不额外要求第二次确认；存在歧义时先显示成员选择或一句澄清，尚不启动执行。
- 解析建议由服务端短期保存，包含 `proposal_id`、原文摘要、词表/配置 revision、确切目标与流程，有效期五分钟；限制解析并发和保存数量。
- 正式提交引用该建议。服务端验证原文、版本、归属和期限，并重新校验成员/权限；建议失效返回 `routing_proposal_stale`，不静默改派。建议不能由客户端自由构造。
- Run 原子保存最终路由、解析来源、输入依据和角色快照。相同幂等 key 的已提交请求先复用原结果，不因预览过期再次派发。
- 路由解析失败不回退到猜测或其他成员；给出诊断和显式选人入口。解析模型调用的耗时、用量和费用与执行调用分开统计，未知用量仍标未知。
- CLI 解析单次期限 90 秒（包含进程启动），只暴露路由决策工具，不执行任务工具；显式收件人与确定性流程路径不必增加一次模型调用。

用户可以一直使用自然语言；`@` 是一种精确指定方式，不是参与协作的前提。

### 5.2 协作讨论

适用于比较方案、探索问题、收集不同视角。

1. 至少两个成员基于同一份输入和历史快照独立回答，彼此不读取本轮未完成回复。
2. 成员依次交叉质询，读取全部独立观点和此前已完成的质询，围绕具体论点挑战或补充。
3. 协调者形成综合草案；原作者分别结合自己的独立观点和质询后修订，简短复查是否被准确表示，以 `confirmed` 或 `disputed` 和纠正意见返回结构化回执。
4. 最终协调者读取草案及全部有效回执，应用修正、保留未收敛分歧，交付一份讨论笔记。无效回执明确失败；一致或确认不等于来源证据。成员数为 2–4，固定一轮质询和一轮复查，共 `3N+2` 步，最多 14 步。
5. 各阶段长度随任务需要；简单问答和轻量游戏可在自由协作直接短答。原始贡献仍可追溯，协调者也可以参与讨论。

### 5.3 Research

适用于资料研究、技术选型、主题梳理与证据比较。

1. **研究员**明确问题和范围，检索/读取资料，提出带来源的结论与不确定性。
2. **质疑者**独立读取相关来源，检查出处、时效、推论跨度和遗漏，指出支持、争议或证据不足。
3. **协调者**整合为 Research 报告：问题、范围、方法、主要发现、分歧、来源、限制和下一步。

研究员和质疑者必须是两个不同的成员 ID；协调者可复用其中一个成员。同模型、同供应商允许使用，界面不得据此声称是跨模型验证。

默认自主研究由成员依据问题和工具权限决定检索与读取：即便用户没有给链接也要主动补充必要证据；用户给了链接也不能把这些链接当成穷尽范围。复核者须独立读取原文，证据不足时可补充查证，不照抄上游结论。简单问候无需搜索；用户明确禁止外部研究时遵守限制。旧 API 的“在线发现资料”需要可用搜索服务；“研究给定资料”保留其范围约束。搜索摘要、搜索引擎结果页与实际抓取的原文分别标记。空正文抓取明确失败；仅有搜索线索的结构化结论须标为证据不足，不能标为 supported。报告不能把摘要检索命中表示为已读原文，也不能把引用存在表示为事实已被证明。

### 5.4 代码分析

适用于仓库理解、指定问题调查和有证据的代码审查。

1. **分析者**使用只读文件工具，记录文件、行号和实际读取版本，提出发现。
2. **复核者**读取相关代码，逐项说明确认、不同意或证据不足；可补充新的发现。
3. 最后一个步骤输出代码分析报告，包含严重度、影响、依据和建议；没有确认问题也要如实说明分析范围。

此流程不修改代码、不执行项目脚本，也不将“静态检查通过”写成“运行已验证”。角色分配不绑定 Claude、Codex 等品牌。

### 5.5 编排共同规则

- 首版流程由代码定义的有限步骤组成：单步骤、并行步骤组、后续汇总步骤；不引入工作流引擎。
- 用户明确 `@成员` 时按自由协作发送，发送预览明确显示覆盖了默认流程；显式同时提交流程和冲突收件人时返回校验错误。
- 选中成员和自然语言明确指派遵循同一目标/角色契约；既定收件人不能被后续模型判断静默替换。
- Agent 输出中的 `@成员` 作为正文展示，首版不自动触发新 Run。真正的交接来自既定步骤计划。
- 每个 Run 开始时冻结角色配置、流程版本、模型、工具权限、上下文选择和输入来源引用。
- 调度前重新校验成员是否停用、资料范围及依赖是否仍可用；不可用时明确失败，不换成员或扩大工具权限。配置编辑对下一次 Run 生效，正在执行的 Run 使用可查看的原快照。
- 前置步骤失败、取消或输出不符合契约时，依赖步骤不启动；独立并行步骤保留已产生的结果。
- 汇总不得把成员异议自动改写成一致同意。人工标记也不得覆盖模型原始结果。

新增工作场景应组合已有角色、步骤和工具，并新增产物 schema/渲染器及契约测试；不得复制一套会话、调度器或消息协议。

### 5.6 成员之间如何交接

首版由服务端执行已接纳的步骤计划。成员通过共享可见消息、来源和产物协作；模型之间不直接建立连接，也不通过一段看似交接的正文自行触发任务。

每条依赖边有一个结构化工作包，保存在已有 Run 计划/Step 输入中，不额外建设一套交接数据库：

- 上游步骤、下游步骤与确切成员 ID。
- 本步职责、用户原始目标及验收条件。
- 已完成的上游消息 ID、确切产物版本和可访问来源 ID。
- 需要检查的结论、分歧、限制和待回答问题。

Research 示例：

```text
用户交付目标
  → 布偶猫检索、读取来源，给出发现与不确定性
  → 服务端保存布偶猫的终态结果，形成交接工作包
  → 缅因猫独立读取依据，给出支持、争议与证据不足
  → 服务端保存复核结果，形成汇总工作包
  → 橘猫读取两方结果和来源，形成保留分歧的报告
  → 页面显示产物与本次协作终态
```

消费者只收到权限内的必要资料，不复制整个上游会话或隐藏推理。前端展示“布偶猫的研究结果 → 缅因猫复核”等交接记录，可展开查看任务说明和输入依据。`handoff_prepared` 表示工作包已准备好；`step_started` 表示执行已开始，两者都不意味着模型已经理解内容。

复核者发现证据不足时可以把问题作为本步结果提交，汇总保留缺口。用户补充问题开启下一 Run；首版没有隐式返工回路。上游真实执行失败则依赖步骤跳过；用户停止时取消整个 Run，并保留已有输出。

模型主动 `ask_agent` / `delegate_task`、临时拉成员或自行增加返工轮次属于后续自主协作层。后续也必须走同一服务端调度、身份、来源和预算机制，不能用解析成员回复中的名字作为调用授权。

## 7. Agent、上下文与工具契约

### 7.1 原生工具循环

```text
冻结本步输入与权限 → 启动独立 CLI 会话 → CLI 请求模型并接收工具调用
    → 原生只读工具按成员现有授权由 CLI 在受限边界内执行
    → 其他工具通过受控 MCP 请求 Go 校验名称、参数、权限与预算并执行
    → 实际结果配对回原调用 → CLI 继续模型循环 → 完成 / 达到限制 / 失败 / 取消
```

- 模型只提出操作请求；原生工具由 CLI 按其权限执行，平台 MCP 工具执行和权限判断属于 Go 代码；CLI 协议解析器只做名称白名单与配对守卫，不冒充文件沙箱。
- 全部工具结果必须关联确切 `tool_call_id`，原生结果标记 `origin=native`，并携带成功/失败、实际内容、截断状态和来源引用。原生工具调用 ID 使用 `cli:` 前缀，不与桥接器宿主 `native-N` 冲突；来源 ID 始终由服务端生成；失败、空结果或未经实际调用/结果配对的内容不能成为证据。
- 工具失败可以返回给模型纠正；鉴权失败、配置/协议错误和超过显式配置的执行期限应结束步骤；不按累计工具调用次数硬停健康任务。
- 模型流必须有协议规定的结束信号；不能把 EOF 或进程退出码单独当成成功。
- 只有被指定为最终交付的步骤可以调用结构化 `publish_artifact`；中间研究、质疑、草案和委派步骤不发布正式产物。自由协作中未被委派的根成员及其最后 continuation 可以发布；根成员一旦委派，先前提交的产物只保留为该 Attempt 的未发布草稿。参数不符合契约时返回错误，不能从普通文本猜测成功。
- 首版不展示或依赖模型内部推理内容；只展示成员的可见回复、动作与结果。

### 7.2 上下文规则

- 身份按 `workspace_id + agent_id` 定义；上下文按 `thread_id + agent_id` 隔离。
- 网页 CLI 每步骤使用新的独立原生会话，由平台重建上下文：系统职责、用户目标、已完成共享消息、明确的上游结果、所选产物与来源指针。
- 并行步骤使用同一个已提交历史快照；不读取其他并行成员的半条回复。
- 历史选择先取最近完成轮次，再满足预算；保留当前问题和本流程的必要上游结果。首版不做后台摘要和长期记忆。
- 长上游正文、被引用产物和工具观察以确切 ID/版本的引用交给模型，按需通过受限 `read_context`/`read_source` 分页取回；每页原文最多 8 KiB、序列化后不超过 64 KiB。不得先把完整 source/body 列表读入内存再截取前几条。
- 消息列表只携带最多 64 KiB 的正文预览；完整正文保存在不可变正文块中，由服务端按 cursor 分页，客户端不自动拼接无限全文。
- Go 对完整输入执行保守字节预算；CLI 负责其实际模型窗口和输出额度。必要输入超限时明确失败，不静默截断关键资料，也不把未知模型窗口标记为已核对。
- 所有网页和文件正文标记为外部资料；其中的指令不能修改系统规则、工具权限或工作空间范围。

### 7.3 工具清单

| 工具 | 输入和输出 | 限制 |
| --- | --- | --- |
| `list_files` | 相对目录 → 文件名、类型、截断标记 | 绑定目录内；过滤忽略目录与敏感路径 |
| `read_file` | 相对路径、可选行区间 → 带行号片段、文件摘要、来源 ID | 文本文件；验证路径和行区间；最多 500 行/32 KiB 输出 |
| `search_content` | 字面量关键词、可选相对子目录 → 文件、行号、片段 | 不接受任意 shell；最多 50 条命中，扫描有时间/字节预算 |
| `web_search` | 查询词 → 标题、URL、摘要、查询时间 | 一种搜索供应商；结果标记为搜索摘要；最多 10 条 |
| `fetch_url` | 公共 HTTP(S) URL → 标题、正文片段、来源 ID、抓取时间 | 无登录、无 JS 浏览器；限制重定向、大小和超时 |
| `list_sources` | 可选 cursor → 本步可见来源的 ID、类型、标题、URL/路径、捕获时间、截断与证据强度；不返回正文 | 只列本步冻结快照和本 Attempt 的原生捕获；20 条/页，cursor 绑定确切来源集合，不跨会话或未提交并行步骤 |
| `read_source` | 可访问的捕获来源 ID、可选 cursor/max_bytes → 原捕获版本的 UTF-8 分页片段与出处；不传 cursor 返回第一页及 `has_more`/`next_cursor` | 只读本步已授权来源，不重新读取当前网页/文件；每页原文最多 8 KiB，编码后最多 64 KiB |
| `read_context` | `kind=message\|artifact`、稳定 ID、artifact 的确切 version、可选 field/cursor/max_bytes → 已提交上游结果或显式引用的分页原文；`field=artifact_json` 包含完整 findings、来源与限制 | 只在当前 Step/Attempt 冻结的授权范围内读取；artifact 多版本时必须显式指定；中断 Attempt 自己的输出标记 `committed=false`；调用时重新校验撤权 |
| `publish_artifact` | 类型、标题、正文、结构化数据、来源 ID → 产物引用 | 只有最终交付步骤可调用；校验类型对应 schema 和来源归属；内容在步骤成功后原子发布并纳入 Run 交付 |

原生只读工具不增加工具词表或授权项：`Read`/`Glob`/`Grep` 对应文件授权，`WebSearch`/`WebFetch` 对应联网授权且仅限发现范围；Codex 的合并 web 工具要求两项联网授权同时存在。原生文件结果保存为 `native_file`，原生网页观察保存为 `native_web`，原生搜索/`Grep`/`Glob` 线索保存为 `native_search`。`native_web` 是 CLI 处理后的观察或摘要，不能表示为原始网页；`native_search` 不能支撑 `supported`/`confirmed`；代码分析接受 `file` 或 `native_file`。原生输出可能只有 metadata 或为空；空输出不构成来源，但工具确实 completed 的事实仍保留。产物引用 `native_web` 时自动补充观察限制说明。

文件工具默认忽略 `.git`、`node_modules`、构建目录、应用数据目录、`.env*`、私钥和已知凭证文件。原生文件读取同样由 CLI 的 deny 规则阻止这些路径。读取失败和无权限必须与“没有结果”区分。

### 7.4 有界执行默认值

| 项目 | v0.1 默认值 |
| --- | --- |
| 每步骤模型轮次 | 原生 CLI 内部模型轮次不由 Go 逐次计数；受显式步骤期限和 CLI 自身限制约束 |
| 累计宿主工具调用 | 不设总次数硬停；调用序号只用于身份关联和统计，重复调用仅作诊断提示 |
| 原生 CLI 步骤期限 | 默认 `0`（无绝对期限），可通过 `COCOGEM_STEP_TIMEOUT` 配置正期限；包含原生循环与工具请求 |
| 等待首个有效响应 | 默认 10 分钟，可通过 `COCOGEM_FIRST_RESPONSE_TIMEOUT` 配置；显式 `0` 关闭；会话初始化不等于模型已响应 |
| 无进展检测 | 默认 15 分钟，可通过 `COCOGEM_STALL_TIMEOUT` 配置；显式 `0` 关闭；真正的新增输出与受控工具活动算进展，协议噪声不算 |
| 停滞动作 | 默认 `warn` 只发出可见告警；`COCOGEM_STALL_ACTION=stop` 时终止该步骤 |
| 单 Run 总期限 | 默认 `0`（无绝对期限），可通过 `COCOGEM_RUN_TIMEOUT` 配置正期限；排队不计时，dispatch 后等待上游成员仍计入 |
| 消息正文 | 预览最多 64 KiB；完整正文按不超过 8 KiB 的不可变块保存，默认每页 8 块、最多 32 块 |
| 单次抓取/搜索期限 | 20 秒 |
| 网页响应读取 | 解压后最多 2 MiB；送给模型的正文最多 32 KiB |
| 文件读取 | 单文件最多 1 MiB；更大文件明确拒绝并说明 |
| 原生工具观察 | 实际返回最多保存 512 KiB；超限标记 `truncated`；持久化事件正文最多 64 KiB，完整观察通过 `read_source` 分页读取 |
| HTTP JSON 请求体 | 最多 64 KiB；用户问题最多 16,000 个 Unicode 字符 |
| 有效取消确认 | 原生请求与工具均已停止后提交；超过 10 秒仍未停止要显示诊断 |

这些值集中在服务端配置中记录，首版网页不提供任意调参。接近 Token 限制时提示剩余能力；供应商未返回用量时展示“未知”，不伪造精确成本。

## 8. 来源与产物

### 8.1 来源记录

每条来源保存 ID、工作空间/会话/Run 归属、类型、标题、URL 或相对文件路径、捕获时间、内容摘要、实际捕获片段和截断状态。宿主文件来源还保存行区间与文件 SHA-256；原生 `native_file` 保存 CLI 实际返回文本并由服务端生成 ID/摘要，不声称拥有文件哈希；网页保存最终 URL、访问结果，以及可获取的发布日期。

- 工具产生的来源 ID 由服务端生成；模型只能引用本次允许访问的确切来源。原生工具没有可直接内嵌的 ID，模型通过 `list_sources` 取得本步实际捕获的 ID，不能编造。
- 来源类型区分宿主 `file`/`web`/`search_snippet`/`search_results` 与原生 `native_file`/`native_web`/`native_search`；搜索摘要、原生观察、实际网页正文和文件片段不得相互冒充。`native_web` 只表示 CLI 处理后的观察或摘要，不是原始网页全文。
- 来源面板首先展示当时捕获的内容。刷新网页或重新读取文件属于一次显式新捕获，不覆盖旧证据。
- 不抓取登录页或绕过付费墙；抓取失败展示原因。缺少发布日期必须显示未知。
- 本地路径只展示工作空间内的相对路径；浏览器不具有任意磁盘读取接口。

### 8.2 产物类型

| 类型 | 必填内容 |
| --- | --- |
| `note` | 标题、正文；适用时附来源和分歧 |
| `research_report` | 问题、范围、方法、发现、争议/证据不足、来源、限制、下一步 |
| `code_analysis` | 分析范围、发现列表、严重度、影响、来源位置、复核结论、建议、未验证项 |

Research 的结构化结论使用 `supported / disputed / insufficient_evidence`；代码发现使用 `confirmed / disputed / insufficient_evidence` 和 `high / medium / low` 严重度。代码报告中每条发现必须有实际文件来源引用（`file` 或 `native_file`）；关键研究结论必须有实际读到的来源或显式标记为推论/待验证。仅有 `search_snippet`、`search_results` 或 `native_search` 线索时只能标为 `insufficient_evidence`；`native_web` 作为 CLI 观察可用于 `supported`，但产物必须保留观察限制。

产物内容采用不可变版本：每次修订生成新版本，保留来源 Run 和成员。人工状态为 `unreviewed / accepted / dismissed`，单独记录操作者和时间，不改变模型原文或执行终态。

每次成功 Run 在同一事务内记录权威交付 `delivery`：最终消息 ID 列表和确切的 `产物ID@版本号` 列表。线程产物列表默认只返回这些交付版本；成功但缺少指定最终结果时整轮原子失败，不按最后时间戳或“最新产物”猜测。未交付草稿仍可通过确切 `id/version` 端点、Attempt 草稿和 Run 事件追溯，但不会展示为正式产物。旧历史没有 `delivery` 记录时不回填、不推断，其已存在产物继续可见。

导出的 Markdown 包含标题、版本、问题、结果、分歧、来源、生成时间、成员与执行方式、人工状态及限制。

## 9. 执行状态与恢复

### 9.1 Run 状态机

```text
queued → running → succeeded
   │        ├────→ failed
   │        ├────→ interrupted  （重启发现旧运行无法继续）
   │        └────→ canceling → canceled
   └────────────────────────→ canceled
```

- `queued` 表示输入已经持久化；`running` 表示调度器已经开始本次执行。
- Step 状态为 `pending / running / succeeded / failed / canceled / skipped / interrupted`。
- `succeeded / failed / canceled` 是唯一不可变终态；`interrupted` 是保留检查点，只能通过显式恢复接口重新打开。成功要求全部必要步骤校验成功，并在同一事务写入最终交付引用（最终消息 ID 与确切产物版本）；缺少指定最终结果时整轮失败。
- 取消与正常完成竞态按持久化 CAS 决定：先提交终态者生效，后续操作返回已存在结果。
- 取消本次 Run 的所有并行步骤与进行中的网络/工具操作；已完成回复保留。仅关闭 SSE 不属于取消。
- 依赖真正失败时，未执行的普通依赖步骤标为 `skipped` 并说明原因；依赖仅为可恢复中断时保持 `pending`。没有完成复核的产物不得展示为正式完成报告。

### 9.2 排队、重试和重启

- FIFO 以持久化入队顺序为准；本版一个调度 worker，不需要 Redis 或外部任务系统。
- 同一会话最多一个非终态 Run；服务端使用事务约束，不能只依赖禁用前端按钮。
- 客户端发送使用 `Idempotency-Key`。相同 key 和相同规范化请求复用原结果；相同 key 不同请求返回 409。
- 每个逻辑 Step 可包含多个 Attempt；新的尝试单独记录 CLI 版本、程序身份、适配方式、请求/实际解析模型、非秘密连接身份、平台拥有的原生会话 ID、进程组归属和最终状态，旧消息、来源与产物不覆盖。
- Run 入队时冻结执行策略快照；Run 与逻辑 Step 在首次真正 dispatch 时各写入一次 `started_at`/`deadline_at`，跨 Attempt、重启和显式恢复不再重置。排队不计时，dispatch 后的依赖等待、恢复和停机计入。策略中的 `0` 表示该项关闭，环境变量修改只影响新 Run；已到期不再启动 CLI，重新执行需新 Run。
- 旧版本没有策略的已启动 Run 在恢复前只采用一次当前配置并记录 adoption 时间；缺少旧期限时从 adoption 起计算，保留历史开始时间，已有明确 deadline 不延长。明确“旧策略未知、首次采用”，不得声称继承了原期限；之后恢复不再重新领时间。
- Attempt 记录可机器判断的 `failure_kind`、输入计划摘要和检查点摘要；已知、未知和缺失用量分开保留，不用 `0` 填充未知。失败 Attempt 不等于失败 Step，可恢复中断保留 `interrupted` 检查点；本版不做自动重试，恢复必须由用户显式发起。
- 启动时先完成恢复，再接受新任务：`queued` 在配置与权限重新校验后继续；`running` 先核实旧 Attempt 的进程归属，仅终止平台记录且身份匹配的进程，然后把未完成步骤转为 `pending` 并继续。已完成步骤不重跑；所有步骤已完成但未提交终态时直接收敛，不重复汇总或发布产物。
- `canceling` 收敛为 `canceled`，不自动复活；用户取消的 Run 永远不进入自动恢复。无法核实进程归属或结果不确定时保留 `interrupted` 检查点并说明人工处理原因；修复后可显式“继续执行”，从已保存目标、结果和上下文创建新尝试。
- 升级迁移只追加策略、Attempt、调度认领和正文块数据，不改写既有成员 ID、历史或任务；旧 inline 消息保持原文，不通过重放事件再制造一份正文。旧版本遗留且没有 Attempt 归属的 `running` 步骤保留为 `interrupted` 检查点，需显式继续。
- 服务正常停止时把执行中的 Attempt 和 Step 记为中断并保留 `running` 检查点；同一 Run 的恢复与调度使用持久化认领，防止并发恢复、重复消费和重复结果回传。恢复与继续前重新检查 CLI 能力、工具隔离探测、连接配置、实际解析模型/上游身份、权限边界和程序身份；模型或供应商变化、能力不足时保留检查点并阻止继续，不静默切换供应商、模型或扩大工具权限。
- 失败/跳过的依赖不再让恢复提前终结存在待执行的 continuation；协调者仍可接收委派失败并处理，普通依赖按既有规则跳过。残留进程按整个记录的进程组核实和清理，组内成员未确认退出时保留不确定检查点。
- 新 Run 使用当前设置的新快照，并记录 `retry_of_run_id` 或跟进来源；旧 Run 不被覆盖。
- SQLite 事务可以防止重复落库，不能据此承诺外部模型执行 exactly-once。取消已发出的请求也不能保证供应商停止计费。

## 10. 技术架构与代码边界

### 10.1 技术基线

| 层 | 选择与理由 |
| --- | --- |
| Go | v0.1 采用 Go 1.26，最低补丁为 1.26.9；CI 覆盖 1.26 与当前 stable |
| HTTP | 标准库 `net/http`；REST + SSE；请求与执行分别管理 context |
| Agent | CLI 管理模型/工具循环；Go 管理有限协作调度与受控 MCP 工具桥 |
| 模型载体 | 复用本机 CLI 认证；成员选择执行器与可选模型；协议成功终止按各 CLI 验证 |
| 数据库 | SQLite，参数化 SQL、显式迁移；一个维护活跃且许可兼容的 Go 驱动，在 M0 固定版本 |
| 前端 | React + TypeScript + Vite，Node.js 22.12+；提交 npm lockfile，CI 使用 `npm ci` |
| 前后端契约 | OpenAPI 3.1；包含普通 API 和 SSE 事件 schema；前端类型从契约生成 |
| 日志 | `log/slog`；使用 workspace/thread/run/step/tool_call ID 关联 |
| 测试 | Go 原生测试、Vitest + Testing Library、Playwright；付费模型测试手动启用 |

本版不引入 Agent 框架、消息中间件、微服务、向量数据库、ORM 或 DI 容器。CLI 协议适配、SQLite 驱动和前端基础依赖均按真实需要选择并固定；不自研已有可靠实现的协议解析或 HTML 提取算法。

### 10.2 目标目录

```text
cmd/cocogem-server/      Web 服务入口与显式依赖组装
internal/agent/          执行器接口与受控工具调用
internal/nativecli/      网页 CLI、受限 MCP、事件、兼容探测与进程生命周期
internal/proc/           进程身份、归属核实与受限终止
internal/model/          内部执行请求/响应类型（执行路径使用 nativecli）
internal/tools/          工具 schema、执行、权限、文件与网页读取
internal/workspace/      工作空间、成员与会话规则
internal/workflow/       内置流程、步骤计划、依赖与取消
internal/store/          SQLite 查询、事务与迁移
internal/testutil/       仅自动化测试使用的模型与网页 fixtures
internal/httpapi/        API、认证、SSE、静态资源服务
web/                    React 应用、组件与浏览器测试
api/openapi.yaml        HTTP 与事件契约
examples/               可公开的人工评测资料
docs/                   产品、架构决策与运行说明
```

目录是职责边界，不要求为每个名词创建抽象。只在实际消费边界定义小接口；先使用具体实现，保持显式构造和依赖注入。关键边界是 `Executor`、`Model`、`Tool` 和事务存储，不建设通用插件框架。

终端入口为 `cmd/cocogem`，实现和测试位于 `internal/cli`；网页使用 `internal/nativecli` 的有界执行路径。`.cocogem/<cli>.json` 不迁作 Web 多会话存储，也不静默改写或删除。

### 10.3 数据模型

| 表 | 最小职责与约束 |
| --- | --- |
| `workspaces` | 名称、说明、允许目录绑定、数据处理确认版本、revision |
| `agent_profiles` | 所属空间、稳定 ID、显示名/唯一 handle/显式别名、职责/提示词、模型、工具集合、停用状态、revision |
| `settings` | 单条设备级协作默认值：默认协调者、按 workflow 的角色分工、revision；不包含成员关系或工具授权 |
| `threads` | 所属空间、标题、参与成员、默认流程、协调者、revision、活动时间 |
| `messages` | 会话/Run/Step、发送者、角色、正文预览（最多 64 KiB）、`content_format`（缺省 `inline` 或 `chunks_v1`）、`content_bytes`、`content_truncated`、稳定创建顺序、草稿/完成状态 |
| `message_chunks` | 追加式正文块：`(message_id, seq)` 唯一、每块不超过 8 KiB 合法 UTF-8；与消息元数据同事务提交，随消息删除；重试同一 `(message_id, seq, content)` 不重复写入 |
| `runs` | 用户输入消息、幂等 key/请求摘要、最终路由与解析依据、流程/配置快照、状态、时间、重跑来源、错误 |
| `steps` | 所属 Run、成员与角色快照、步骤序号/依赖、交接输入引用与验收条件、状态、用量与诊断 |
| `attempts` | 逻辑 Step 的每次执行尝试：序号、CLI/版本/程序身份/适配方式、请求与实际解析模型、非秘密连接身份、原生会话 ID 与模式、进程组归属、开始/进展/结束时间、状态与错误 |
| `run_claims` | 调度与恢复的持久认领：Run、服务实例、服务 PID/启动时间、认领时间；防止并发恢复和重复消费 |
| `events` | Run 内单调序号、事件版本、关联 ID、时间、有限 payload；唯一 `(run_id, seq)` |
| `sources` | 出处、捕获版本/片段、读取类型、时间与访问结果；严格归属空间/会话/Run |
| `artifacts` | 类型、稳定产物 ID/版本、内容与结构化数据、来源、生成步骤、人工状态 |

具体字段类型和索引在 M0 的 schema 设计中冻结。必须具备外键、枚举/空值约束、幂等唯一约束和每会话活动 Run 唯一约束。会话列表状态从最新 Run 派生，避免再维护一份独立执行真相。

SQLite 开启外键、WAL 和有界 busy timeout。必要状态、消息、产物及对应事件通过事务提交；已应用迁移只追加新版本。首次 v0.1 无历史 Web 数据迁移，现有 CLI 记录原样保留。

### 10.4 配置和启动约定

以下为待实现的运行契约，不能当成当前已经可用的命令。

| 配置 | 约定 |
| --- | --- |
| CLI 连接配置 | 复用本机 CLI 已有 API Key、服务地址、供应商和模型配置；无需额外登录或另配模型密钥，凭证不写入应用数据或网页 |

| `COCOGEM_STEP_TIMEOUT` | 单个执行步骤总期限，默认 `0`（无绝对期限）；显式 `0` 关闭 |

| `COCOGEM_SEARCH_PROVIDER` | `auto`（默认：Brave 优先，否则 Bing RSS/DuckDuckGo HTML）、`brave`、`bing`、`duckduckgo`、`public` 或 `off` |

| `--allow-root` | 可选的本地资料目录范围限制，可重复；设置后仅能绑定这些目录或其子目录，不设置时由已登录用户在工作空间设置中指定 |

设置面板按 CLI 展示安装、版本、适配支持以及按 CLI/模型记录的验证结果。连接验证由用户显式触发，说明可能产生用量；CLI 不可用时启动服务仍可查看历史和设置。任务执行仅使用本机 CLI。

开发目标命令为 `make dev`、`make test`、`make build`、`make e2e`。`make dev` 启动 Go 与 Vite，同源 API 经开发代理访问；`make build` 先构建前端再打包 Go 与静态资源。前端资源缺失时启动返回明确错误，不能提供一个页面打不开的“就绪”服务。README 只在命令可用后给出运行说明。

## 11. HTTP 与事件接口

接口以 `/api/v1` 为前缀；ID 使用服务端生成的 UUID；JSON 使用 snake_case；时间使用 RFC 3339 UTC，网页按用户时区显示。以下是接口语义，精确 schema 在 M0 落入 `api/openapi.yaml` 后实现。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /auth/status` | 仅返回是否已设置密码，无需已有会话 |
| `POST /auth/setup` | 首次设置 12–128 字符密码并建立会话；已设置时拒绝覆盖 |
| `POST /auth/login` | 校验工作空间密码，建立 HttpOnly 会话 |
| `POST /api/v1/auth/logout` | 撤销当前浏览器会话并清除 cookie；保留后台协作 |
| `GET /api/v1/system` | 返回执行方式、真实可用状态、模型目录、允许资料目录及限制；不返回密钥 |
| `GET /api/v1/directories?path=…` | 已登录用户浏览本机文件夹名称与路径；空路径返回允许目录列表或主目录内容；遵守目录范围，仅列出子目录，每次最多扫描 1000 条目并提示截断，不更改绑定 |
| `POST /api/v1/system/verify` | 用户显式验证已配置依赖；返回验证时间和结果，不在页面加载时自动调用付费模型 |
| `GET/POST /api/v1/workspaces` | 列表/创建工作空间 |
| `PATCH /api/v1/workspaces/{id}` | 编辑名称、说明和资料绑定；校验 revision |
| `GET/POST /api/v1/workspaces/{id}/agents` | 成员列表/创建 |
| `PATCH /api/v1/agents/{id}` | 编辑或停用成员；不改变进行中的 Run 快照 |
| `GET/PATCH /api/v1/settings` | 读取/更新全局协作默认值（默认协调者、按 workflow 的角色分工）；PATCH 校验 `If-Match` revision 与成员可用性 |
| `GET/POST /api/v1/workspaces/{id}/threads` | 分页会话列表/创建 |
| `GET/PATCH /api/v1/threads/{id}` | 读取或编辑会话配置；只含 `title` 的 PATCH 只校验并更新标题，成员停用后仍可改名；旧客户端完整对象中的 `id`、`workspace_id`、`revision`、`updated_at` 被接受但忽略，身份、版本仍由路径和 `If-Match` 决定；消息按 cursor 分页 |
| `POST /api/v1/threads/{id}/routing-preview` | 解析明确选择、`@` 和自然语言指派；返回服务端建议 ID 或具体澄清，不执行工具 |
| `POST /api/v1/threads/{id}/runs` | 原子保存输入、计划和排队状态，返回 202 与 Run ID |
| `GET /api/v1/runs/{id}` | 状态、步骤、权威交付引用（最终消息 ID 与确切产物版本）和一致的事件 cursor；`delivery` 为 `null` 表示旧历史从未记录交付 |
| `POST /api/v1/runs/{id}/cancel` | 幂等申请取消；返回实际状态 |
| `POST /api/v1/runs/{id}/resume` | 显式恢复 `interrupted` 检查点；重新校验权限、资料范围和 CLI 能力，创建新的执行尝试。已取消或结果待核实的 Run 拒绝恢复 |
| `GET /api/v1/runs/{id}/events` | SSE 历史重放与实时订阅；支持 `after` 和 `Last-Event-ID` |
| `GET /api/v1/runs/{run_id}/messages/{message_id}/content?cursor=&limit=` | 按 cursor 分页读取消息完整正文；默认 8 块、最多 32 块，校验消息归属；旧 inline 消息回退为分页片段，不一次返回无限正文 |
| `GET /api/v1/sources/{id}` | 返回有权限访问的捕获内容与出处 |
| `GET /api/v1/threads/{id}/artifacts` | 会话中已成功 Run 权威交付的产物版本；未交付草稿仅通过确切版本端点、Attempt 与事件追溯，旧历史无交付记录时保留已存在产物 |
| `GET/PATCH /api/v1/artifacts/{id}/versions/{version}` | 读取确切版本/仅修改人工标记，校验 revision |
| `GET /api/v1/artifacts/{id}/versions/{version}/export` | 下载 Markdown，不重新调用模型 |

编辑接口使用 `If-Match` 与资源 revision，冲突返回 412。列表默认 30 项、最多 100 项，使用不透明 cursor。会话与工作空间删除会在同一事务内移除其协作记录、来源和产物，有协作排队或执行中时返回 409；成员只能停用。文件任意读取和任意命令执行接口不在首版提供。

### 11.1 发起协作示例

```http
POST /api/v1/threads/{thread_id}/runs
Content-Type: application/json
Idempotency-Key: 由客户端为一次发送生成的UUID
X-CSRF-Token: 浏览器会话的CSRF值
```

```json
{
  "message": "比较原生工具循环与现成 Agent CLI 的适用场景，列出证据和限制。",
  "workflow": "research",
  "assignments": {
    "researcher": "agent-uuid-1",
    "critic": "agent-uuid-2",
    "coordinator": "agent-uuid-3"
  },
  "source_urls": [],
  "artifact_refs": [],
  "research_scope": "web_discovery"
}
```

上例中的占位成员 ID 在真实调用中必须替换成当前工作空间 UUID。它展示角色分配字段；从自然语言解析而来的提交还须携带服务端 `proposal_id`。自由协作使用独立 schema，提交 `targets`，不混用流程角色分配。前端按同一预览协议验证所有入口，不能凭客户端提供的 ID 绕过成员和权限校验。

错误格式固定为 `error.code / message / request_id / details`。细节字段只包含可公开的字段级错误或状态；不得返回凭证、调用栈或无关本地绝对路径。至少区分 400 参数、401 会话、403 权限/范围、404 不存在、409 状态/幂等冲突、412 revision 冲突、413 大小、429 容量和 503 依赖不可用。

### 11.2 事件契约

事件共同字段：`schema_version: 1`、`run_id`、`seq`、`type`、`occurred_at`、可选 `step_id / agent_id`、类型对应的 `data`。SSE `id` 对应本 Run 的 `seq`。

| 类型 | 用途 |
| --- | --- |
| `run_queued / run_started / run_resumed / run_suspended / run_recovered / run_finished` | Run 生命周期；恢复、停机和终态携带原因 |
| `step_started / step_waiting / step_finished` | 当前成员职责、依赖、等待与结果 |
| `attempt_started / attempt_finished` | 一次执行尝试的 CLI、会话、进程归属与终态 |
| `liveness_warning` | 等待首个响应或长时间无进展；不伪造百分比 |
| `native_notice / cli_changed` | `native_notice` 仅写入诊断记录；用户过程列表只展示影响本步能力的降级通知（如原生文件工具停用），普通系统/未知通知不展示。`cli_changed` 表示 CLI 程序身份变化后的重新检查 |
| `handoff_prepared` | 上游到下游的工作包及输入引用已准备好，不表示接收者已读 |
| `message_started / message_delta / message_finished` | 更新同一消息 ID；delta 明确 append/replace |
| `tool_started / tool_finished` | 关联 tool_call_id、脱敏摘要、结果和来源 |
| `source_captured` | 新来源可查看 |
| `artifact_published` | 新产物版本可查看 |
| `usage_updated` | 供应商实际返回的用量；可标记未知/估算 |

先落库、再通知前端。文本可以按不超过 100ms 的间隔合并落库；已向客户端确认的事件必须可重放。快照与 cursor 同事务读取，订阅与重放不得存在丢事件窗口；重复投递由前端按 `(run_id, seq)` 去重。

心跳不占业务序号。浏览器断线后从最后已处理序号续读；终态后关闭订阅。历史分页、重放和实时流使用同一事件 schema，不维护第二种聊天协议。

人工标记使用 PATCH 返回的当前产物 revision 更新界面；重新打开面板时重新读取。它不追加已经结束的 Run 事件，也不改变 Run 终态。

## 12. 安全与隐私要求

以下要求针对本地文件、外部网页、模型工具和浏览器的真实边界，必须与相应功能一起实现。

- 本地随机引导 token 由 `crypto/rand` 生成，只在启动终端展示；通过 URL fragment 传给前端，再 POST 换取 HttpOnly、SameSite=Strict 会话，随即从地址栏移除。token 一次使用且有期限，不写访问日志。
- 首次初始化设置并确认 12–128 字符工作空间密码。后续直接打开页面用密码解锁，移除一次性启动 token。此密码只保护 Cocogem 页面，本机 CLI 沿用已有连接配置。
- `auth.json` 在数据目录中以 0600 权限保存随机盐及 PBKDF2-HMAC-SHA256（600,000 次迭代）派生值；完整文件原子发布且不覆盖已有密码。文件损坏时拒绝启动，不退回未初始化状态。现有数据目录升级时只补设密码，历史数据保留。
- 密码接口验证 Host、Origin 和 JSON Content-Type；连续 5 次错误暂停尝试 1 分钟。返回 HttpOnly、SameSite=Strict cookie 和 CSRF 值，服务端与 cookie 均限制会话为 24 小时；服务重启需再次解锁。锁定操作撤销当前会话；过期会话在页面回到密码入口。刷新时经已认证的 system 接口取得本会话 CSRF 值。
- 业务 API 和 SSE 都验证本地会话；变更请求验证 CSRF、Origin、Host 和 JSON Content-Type。开发代理也明确配置允许来源，不能使用开放 CORS。
- 修改资料目录绑定前要求该工作空间没有非终态 Run；历史捕获内容仍可查看，新工具调用只能访问新的绑定范围。
- 凭证仅服务端读取；忽略 `.env`、数据库、原始资料、CLI 会话记录和前端构建产物。提供只含占位值的 `.env.example`。
- 文件访问使用 Go `os.Root` 等具备范围保证的能力；拒绝绝对路径、路径穿越和越界访问。首版拒绝符号链接路径，并验证敏感路径过滤；禁止只做字符串前缀判断。
- 网页读取仅允许公共 HTTP(S) URL，拒绝 localhost、私有/保留/链路本地地址和云元数据地址，并在每次重定向时重新校验；不携带用户 Cookie 或跨站 Authorization。直连模式下，Go 在本地解析 DNS、丢弃非公网结果，并只拨已验证的数字 IP，防止解析后换地址。显式代理模式（`COCOGEM_WEB_PROXY` 指定的地址、`env` 或 `system`，以及 `make dev` 默认使用的系统代理）由用户选定的代理解析目标主机并建立远端连接；本地仍执行 URL 与重定向检查，但无法在本地验证代理实际连接的远端地址，这是该信任边界的已知限制。除显式选择 `env`/`system` 外，不继承其他环境代理设置。
- 所有工具有输入、时间、输出及资源预算；禁止任意 shell、网络端口探测和写磁盘工具。模型给出的名称、参数和引用均视为不可信输入。
- Markdown、文件和网页中的 HTML/指令作为资料处理；前端不能执行模型生成的脚本。
- 默认运行日志仅记录元数据与脱敏错误；消息与捕获片段保存在用户数据目录，目录 0700、含数据文件 0600。明确数据位置和停止服务后的备份方式。
- 外部研究会暴露查询词和资料片段；软件无法识别源码中所有硬编码秘密。README 和首次使用说明必须如实表达这个边界。

## 13. 开源工程规范

### 13.1 仓库与协作

- 正式仓库为 `github.com/AcSunday/cocogem`，Go module 使用同一路径；已初始化本地 Git，按功能测试通过后提交独立 commit。
- 项目代码计划采用 MIT；采用自身名称与视觉资产。引用或移植上游代码时核对文件许可、保留要求的版权和许可说明，并记录来源版本；依赖许可另行核对。
- 首次公开前补齐 `LICENSE`、`README.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md`、变更记录和 PR 模板。
- README 区分当前已实现功能与计划，包含本机 CLI 运行、环境变量、数据位置、限制和验证记录；不放未验证的 CI 徽章。
- PR 按可独立验收的范围拆分，说明用户行为、契约变化、验证和迁移；CI 必须通过。风险修改需要独立审阅，AI 自评不能代替测试。
- 开源发布、推送、公开仓库创建和发布凭证配置是单独操作；文档完成不意味着已执行这些动作。

### 13.2 代码与依赖

- Go 使用 `gofmt`、显式错误处理、`context` 传播、资源关闭和有界并发；导出符号有准确注释。
- React 使用语义 HTML、受控表单、明确的状态归属和可测试事件 reducer；避免万能组件与复制运行状态。
- 输入校验放在边界；内部使用明确类型。外部协议在适配层结束，不能把供应商事件名散布到业务和前端。
- 新依赖说明用途、替代方案、维护状态和许可；提交 lockfile。CI 工具固定版本，GitHub Actions 固定已审核的完整 commit SHA。
- API 与事件变更同时修改 OpenAPI、生成类型、服务端、前端、fixtures 和相关测试；CI 验证生成文件无漂移。
- 重要决策以简短 ADR 保存原因和取舍，包括 CLI 优先与连接配置复用、有限流程、SQLite、SSE 和本地安全边界；普通实现细节不写 ADR。

### 13.3 CI 和发布门禁

| 检查 | 必须验证的内容 |
| --- | --- |
| Go | 格式无差异、`go vet ./...`、`go test -race -shuffle=on ./...`、构建 |
| 依赖安全 | 固定版本 `govulncheck`、前端生产依赖审计；可利用的高危问题须修复或有具体验证的例外记录 |
| 前端 | `npm ci`、lint、TypeScript 检查、单元/组件测试、生产构建 |
| 契约 | OpenAPI 校验、生成类型无差异、真实 API 响应与事件符合 schema |
| 浏览器 | Playwright 通过仅供测试的隔离 Go HTTP/SSE 服务和合成 fixtures 跑用户流程，不只 mock 页面请求；fixtures 不进入发布程序 |
| 可复现性 | `go mod tidy` 与生成操作后工作区无意外差异；发布包从干净 checkout 构建 |
| 基本安全 | 密钥扫描、路径/SSRF/鉴权负例、Markdown XSS 和并发取消测试 |

PR CI 不需要模型或搜索密钥，不允许外发真实项目源码。真实模型 smoke test 由维护者手动启用，记录供应商、模型、版本、脱敏结果和用量；不能把 fixture 测试称为模型效果验证。默认 HTTP smoke 只检查正式服务启动、工作空间持久化和备份恢复，不发起模型任务。

发布使用 SemVer 和变更记录。v0.1 构建 macOS arm64、Linux amd64 发布包，附校验和、许可及启动说明；每种宣称支持的平台完成对应 smoke test，未验证平台不标支持。正式发布前验证备份/恢复，不提供一键破坏性清库操作。

## 14. 测试和评测要求

### 14.1 自动化验证

| 层 | 必测场景 |
| --- | --- |
| 模型适配与 Loop | SSE 跨 chunk、工具参数拼接、多工具 ID 关联、未知工具、参数错误、终止标志、断流、预算、取消 |
| 编排 | 角色不同 ID 校验、并行输入快照、依赖失败跳过、异议保留、无自主循环派发 |
| 命名与指派 | 改名保持身份/历史；别名冲突；指派/讨论/否定/假设/引用；显式目标优先；建议过期、词表变更和未知成员 |
| 存储 | 幂等重放/冲突、终态 CAS、唯一活动 Run、事务回滚、migration、重启恢复 |
| 长任务与恢复 | 首响应/无进展/等待工具/依赖等待区分；正常停止与异常退出的检查点；Attempt 历史；重复恢复只调度一次；崩溃窗口不重复步骤/产物/汇总；取消不复活；残留进程身份核实；不确定结果阻止自动重跑 |
| CLI 兼容 | 已知不兼容基线；新版本能力相同；缺少隔离参数；程序被替换后重新检测；可选通知、未知工具动作、会话身份变化、缺失终态；help-only 不得声称隔离；真实 CLI 无凭证隔离探测；升级后恢复的继续/阻塞 |
| 连接变化 | 默认模型、供应商、endpoint 变化时阻止恢复；实际解析模型/连接身份匹配时继续；旧 Attempt 无连接身份时要求新 Run |
| 工具 | 文件越界/符号链接/秘密路径、超大/二进制文件；HTTP 重定向/私网/超时/大小；引用归属 |
| HTTP/SSE | 鉴权、CSRF、revision 冲突、分页、刷新重放、重复与断线重连、快照 cursor 一致性 |
| 前端 | 草稿/展开/阅读位置保留、真实状态、键盘与焦点、失败和取消、产物版本及引用 |
| 端到端 | 三类工作、跟进、切换会话、断线、停止、排队、重启、导出和未配置依赖 |

测试覆盖行为与失败边界，不为 getter 或简单转发凑覆盖率。收集覆盖率用于定位缺口；鉴权、预算、终态、来源隔离和取消必须有负例，不用一个总覆盖率数字替代风险判断。

### 14.2 隔离测试数据

- 确定性模型、网页 transport 和临时文件仅在测试中构造；浏览器测试仍通过正式 HTTP/SSE、工具、状态机和数据库实现。
- 测试服务由 Go 测试二进制启动，fixtures 不进入发布包或用户数据目录，也不作为应用运行模式提供。
- 测试不读取用户任意目录、不发送外部网络请求、不要求付费账号，不捏造真实模型用量、搜索实时性或运行效果。

### 14.3 作品评测

维护一小组可公开任务和人工判据，覆盖讨论分歧保留、研究来源质量、代码发现正确性。记录单成员与多成员的结果质量、误报/漏报、耗时和实际可获取的用量。首版公布方法与有限样例，不声称多 Agent 必然优于单 Agent。

## 15. 分阶段实现与完成条件

每个阶段先跑通一条用户路径，再补齐本阶段失败边界。后端和前端共同推进；不能把可交互页面推迟到全部后端结束以后。

| 阶段 | 具体交付 | 完成条件 |
| --- | --- | --- |
| M0 工程与契约 | Git/module、许可证与贡献规范、Go/前端基线、OpenAPI、schema/迁移、测试 fixtures、基础 CI | 新 checkout 可按说明启动前端与 Go 服务；测试不用密钥；既有 CLI 行为不回归 |
| M1 首条垂直流程 | 工作空间/成员/会话、网页发送、持久 Run、CLI 原生 Loop、受控资料工具、SSE | 页面能完成一次真实 CLI 单成员资料问答；失败/取消/刷新可验证 |
| M2 多成员协作 | 名称/别名、自由 `@`/自然语言指派、并行讨论、角色分配、结构化交接、有限上下文 | 明确指派准确送达，歧义不执行；独立回答再汇总；交接/来源可看；并发/取消测试通过 |
| M3 Research 与代码场景 | 搜索/网页读取、来源捕获、研究-质疑-汇总、代码分析-复核、产物版本 | 三种流程真实可用；报告引用可打开；依赖缺失不伪装成功；静态/运行证据边界清楚 |
| M4 恢复与体验 | 排队/幂等、启动恢复、断线续读、人工标记、导出、响应式与可访问性 | 完整浏览器流程、恢复/竞态/安全负例通过；重启后历史和证据仍可读 |
| M5 开源发布准备 | 干净构建、支持平台 smoke、文档/截图/录屏、公开评测样例、依赖许可清单 | 本文验收项全部有证据；发布包无凭证/私有数据；具备可审阅发布候选 |

M0 的基础契约按版本演进，M1 起开始落地安全边界和取消，不集中拖到 M4。M4 验证全流程和重启场景。不得为了赶阶段将 CI 失败、不可复现错误或权限问题记作“已完成”。
