# Cocogem v0.1 产品与实现规格

版本：0.1 / 2026-10-16。状态：CLI 执行路径已修正并有实际页面协作样例，发布验收仍有门禁；证据见 [实现进度](development-progress.md)。面向本地单用户的开源应用。

本文是第一版的范围、交互、接口与验收依据。勾选完成项必须附实现和验证证据；修改范围时先更新本文，再调整代码与测试。新增依赖和跨模块契约变更需在 PR 中说明理由。

## 1. 产品定位

**Cocogem 是一个由 Go 驱动、带交互式 Web 前端的多 Agent 协作工作空间。** 用户围绕一个主题组织多个 Agent，开展讨论、Research、资料整理和代码分析，保留协作过程、来源与产物，并继续追问。

工作空间和会话是产品的核心。代码分析是工作场景之一；系统的会话、角色、编排、工具、事件、资料和产物不绑定软件开发领域。

第一版要回答三个问题：

1. 多个 Agent 如何围绕同一个问题分工、交流并交付结果？
2. 用户如何看清过程、补充问题、控制执行，并核对结果依据？
3. 新贡献者能否在没有模型凭证的情况下运行、测试和理解项目？

### 1.1 目标用户与成果

| 用户 | 核心需求 | v0.1 交付 |
| --- | --- | --- |
| 个人知识工作者 | 组织资料研究、比较观点、生成报告 | Research 会话、来源查看、报告导出 |
| 开发者 | 理解仓库、定位问题、独立复核结论 | 本地代码读取、分析与复核、文件证据 |
| Agent 学习者与贡献者 | 理解并扩展 Agent 的运行机制 | CLI 原生循环、Go 协作与工具边界、离线演示和测试 |

首版成功标准：用户能在网页完成创建工作空间、选择成员、发起三类协作、观察真实执行、查看来源与产物、取消、继续追问和重新打开历史的完整流程。

## 2. 范围与明确取舍

### 2.1 v0.1 必交付

| 编号 | 能力 | 交付边界 |
| --- | --- | --- |
| F01 | 工作空间 | 创建、编辑名称和说明、确认后永久删除；可选绑定经服务端允许的本地资料目录 |
| F02 | Agent 成员 | 内置角色；创建、编辑、停用成员；设置显示名、handle、别名、职责、模型和允许工具 |
| F03 | 共享会话 | 新建、历史列表、按协作分段的消息时间线、连续追问、确认后永久删除；支持选中成员、`@成员` 与自然语言指派 |
| F04 | 协作编排 | 自由协作、协作讨论、Research、代码分析；有限串行与并行步骤 |
| F05 | 原生 Agent | 本机 CLI 执行、复用登录、CLI 工具循环、流式输出和受控宿主工具 |
| F06 | 工具与来源 | 本地读取/搜索、公共网页检索/读取、来源记录及证据查看 |
| F07 | 交互前端 | 实时过程、工具详情、来源面板、产物面板、取消与重试 |
| F08 | 产物 | 笔记、Research 报告、代码分析报告；历史版本、人工标记、Markdown 导出 |
| F09 | 可靠性 | 持久记录、有限排队、幂等提交、断线续读、取消与启动恢复 |
| F10 | 开源工程 | 文档、许可证、贡献说明、CI、契约测试、浏览器端到端测试、离线演示 |

网页执行以本机已安装的 Claude/Codex/Gemini CLI 为载体，复用 CLI 自己的登录与模型配置，不要求额外配置模型 API Key。成员显式选择 CLI，模型默认沿用该 CLI 的默认值，也可指定。已有 API Key/服务地址/供应商设置按连接字段白名单复用，不强制改为 OAuth，也不要求重新登录。安装与版本探测不等于登录或模型已验证。

CLI 负责模型调用和工具循环，Go 负责成员身份、路由、上下文工作包、流程调度、权限、来源和产物。为保持本版只读范围，网页运行关闭原生通用工具、扩展和外部 MCP，只允许本步受控 MCP 工具桥。不能可靠限制工具的 CLI 版本必须标记不支持并阻止启动，不能为兼容放宽权限。现有独立终端 CLI 行为保持兼容，其默认权限不代表网页权限。

在线搜索先接一种服务，基线为 Brave Search。缺少搜索凭证时仍可研究用户给定的公共 URL 和本地资料；选择“在线发现资料”时必须明确报不可用，不静默改成已有知识回答。

### 2.2 后续版本

通用外部 MCP 服务端/客户端、外部 A2A/ACP、模型自主委派、任意 DAG 编辑器、长期记忆与向量检索、定时任务、多人账户与云端部署、写文件/执行 shell/Git 推送、浏览器自动化、登录网页、PDF/Office 导入、桌面应用和第三方插件市场留到后续版本。

首版支持用户直接输入问题、添加公共 URL、绑定本地文本资料。图片、音视频和文件上传不在本版范围。

### 2.3 运行边界

- 一个 Go 服务、一个 SQLite 数据库、一套同源 Web 前端；先支持 macOS 和 Linux。
- 默认仅监听 `127.0.0.1`，使用本地会话认证；v0.1 不提供公网部署模式。
- 默认同时运行一个 Run；其内部可以有多个并行 Agent 步骤。其余 Run 持久排队，队列最多 20 项。
- 每个会话选择 1–4 个成员；内置流程至少需要两个不同成员。缺少所需角色时在发送前提示。
- 模型认证由对应 CLI 管理；宿主只白名单转交连接配置，不把凭证写入应用数据、事件或网页。搜索凭证由服务端环境变量提供。网页仅显示 CLI 安装、版本、适配支持和显式验证结果。
- 发布物包含 Go 可执行文件和构建好的前端资源；用户运行发布物无需 Node.js。

## 3. 核心对象与用户语言

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| Workspace / 工作空间 | 一组会话、成员及可使用的资料范围 | “Agent 学习与选型” |
| Agent / 成员 | 有稳定身份、职责、模型和工具权限的参与者 | “研究员”“质疑者”“协调者” |
| Thread / 会话 | 围绕一个主题持续协作的现场 | “比较三种 Agent 开发方式” |
| Message / 消息 | 用户输入或一个成员的可见回复 | 一个问题、一段阶段性分析 |
| Run / 本次协作 | 一次用户发送触发的有限执行过程 | 本轮 Research 及复核、汇总 |
| Step / 步骤 | 一个成员承担的一次 Agent 调用 | 研究、复核、汇总 |
| Source / 来源 | 实际读取并保存出处的资料 | 网页片段、文件行区间 |
| Artifact / 产物 | 可独立查看、继续修订和导出的结果 | 研究报告、讨论笔记 |

一个会话可以产生多次 Run；每次 Run 可以产生多个成员回复和产物。用户补充问题会创建新 Run，保留前序记录。

### 3.1 成员身份、名称与职责

| 字段 | 用途与规则 | 示例 |
| --- | --- | --- |
| `agent_id` | 服务端 UUID，稳定身份；消息、权限、会话、步骤均使用它关联 | 页面通常不直接显示 |
| `display_name` | 用户可编辑的展示名，支持中文；同名时显示 handle 区分 | 布偶猫 |
| `handle` | 工作空间内唯一的明确路由标识；小写字母开头，后接字母/数字/连字符，总长 2–32 | ragdoll |
| `aliases` | 自然语言可用的称呼；去除两端空白后精确解析，不做模糊昵称猜测 | 布布、布偶 |
| `role_description` | 常用职责；本次流程的具体角色由 assignments 决定 | 擅长资料研究与方案整理 |
| `model` / `tools` | 执行能力与权限，独立于名称 | 已配置模型与允许工具集合 |

用户可以把成员命名为布偶猫、缅因猫、橘猫，也可以使用其他主题。名称、模型和任务角色各自独立：更换模型或名字不创建新成员，布偶猫也可以在不同任务中承担不同职责。

handle 和显式别名在同一工作空间的路由词表中不得指向多个成员；创建/编辑时检查冲突。展示名允许重名，或与另一成员的路由词冲突，此时该称呼被标为歧义，要求选定确切 handle；不能因扫描顺序而选中某个成员。不同工作空间使用各自词表。

改名保留 agent_id。历史消息和 Run 保存当时的展示名与配置 revision，界面可查看当前身份；不得重写历史标签、丢失会话或将历史引用改指其他成员。旧称呼只有被用户明确保留为别名时才继续参与新消息路由。成员配置页实时显示可用称呼、冲突和将使用的模型/工具。网页 `@` 补全显示中文名称，实际选择绑定 agent_id，输入其他语言的名字也不影响身份关联。

## 4. 首次使用与日常流程

### 4.1 首次打开

1. 启动服务，打开终端给出的本地引导链接，建立浏览器会话。
2. 展示真实模型、在线搜索和本地资料目录的可用情况；“已配置”不等于“已连通”。
3. 用户创建工作空间，填写名称、说明，可从服务端允许目录中绑定一个资料目录。
4. 初始化三个可编辑成员：研究员、质疑者、协调者。三个成员可使用同一个模型，但身份、上下文及职责分别保存。
5. 提供“协作讨论”“Research”“代码分析”入口和示例问题。没有模型凭证时提供显式离线演示入口。

首次发起真实模型任务前，说明问题和读取的资料片段会发送给配置的模型服务；在线搜索还会向搜索服务发送检索词。用户确认工作空间的数据处理范围后保存确认版本。演示模式不外发资料。

### 4.2 发起协作

1. 新建会话，输入标题或使用首条问题的前 40 个字符作为标题。
2. 选择流程、成员及角色分工，添加资料链接；代码分析须已绑定本地目录。
3. 输入问题。发送区显示本次流程和实际收件人，权限或凭证缺失时说明具体原因。
4. 点击发送后完成路由解析；明确且提交成功时展示持久化的用户消息与排队状态，有歧义时保留草稿并请求澄清。
5. 执行时显示当前步骤、成员回复、工具活动、耗时及来源；不要显示虚构进度百分比。
6. 完成后展示所有成员贡献和最终产物，用户可打开证据、标记产物、复制或导出。

### 4.3 持续协作

- 用户可在同一会话继续追问、切换本次流程，用选中成员、`@成员` 或明确自然语言指令指定回应者。
- 执行期间输入内容保留为草稿；本会话未结束前不能再次发送。用户可以停止后发送补充问题。
- 切换会话、刷新页面和关闭浏览器不终止后台 Run。
- “重新运行”明确创建新 Run，保留旧记录，并提示可能再次消耗模型额度。
- 选择历史产物后继续提问，发送预览显示引用的确切产物版本。

## 5. 三类场景与自由协作

### 5.1 自由协作

用于普通问答、资料整理及定向讨论。指定一个成员时调用该成员；指定多个成员时并行回应，首版不额外调用模型汇总。

显式收件人可以通过成员选择器或 `@handle` 指定。解析排除代码块和行内代码；未知或歧义称呼在发送预览中提示，不静默换人。

没有显式收件人时，先判断当前用户消息是否含自然语言指派；没有指派则按所选流程执行，未选择流程则发送给会话协调者。提到某个名字本身不等于指派。

### 5.1.1 自然语言指派

| 当前用户消息 | 预期解释 |
| --- | --- |
| “布偶猫帮我调查一下 Go Agent 框架” | 给布偶猫的单成员研究任务；不因“研究”二字擅自追加复核者 |
| “布偶猫和缅因猫分别给个意见” | 两个明确目标并行回答，不自动增加汇总步骤 |
| “布偶猫查资料，缅因猫复核，橘猫汇总” | Research 流程的明确角色分配与顺序 |
| “我觉得布偶猫做 Research 挺好” | 普通讨论，不唤醒布偶猫执行任务 |
| “如果让布偶猫来研究，会有什么问题？” | 假设讨论，不把假设当成执行指令 |
| “不要让布偶猫处理这个” | 保留否定约束，不派给布偶猫；仍缺少正向任务时按普通讨论处理 |
| 代码块或引文中出现“布偶猫帮我……” | 资料中的称呼不直接产生任务 |
| “让小猫研究一下”且存在多个匹配成员 | 请求选择成员；不猜测 ID |

实现分两步：

1. Go 解析显式选择与 `@handle`，从工作空间词表提取自然语言中的候选成员，保留最长名称匹配与准确位置。这里只定位称呼，不用堆积关键词正则决定复杂语义。
2. 对需要解释的自然语言消息进行一次有界模型解析，输出结构化路由建议：`assign / discuss / clarify`、确切成员 ID、对应任务、否定约束，以及可映射的既有流程/角色。解析器只接收当前用户输入、成员词表和必要的路由上下文；不能调用工具或执行任务。

服务端验证模型输出：成员必须真实存在且可用；分配必须有当前用户指令依据；不能覆盖明确选择、添加未要求的成员、扩大权限、把引用/条件/否定当成授权，或生成循环流程。首版只映射已有单步、并行回应和内置流程；超出能力时明确说明并让用户选择现有流程，不自动接纳任意图。

结构化输出还需给出任务所对应的原文位置，服务端核对其确实来自当前消息。格式、身份、范围和流程验证可以确定性完成；复杂语义仍可能被模型误判，需通过可见解释、歧义澄清及否定/引用等负例评测控制风险，不能把 JSON 校验称为意图理解正确性的证明。

显式选择和 `@handle` 的优先级高于模型建议。明确指派与手选流程冲突时展示冲突；语义不清时展示一句具体澄清及成员选项，保留草稿。模型给出的置信度数字不能代替这些验证。

明确点名的工作空间成员可以随本次发送加入会话，受四成员上限约束，并在发送预览中展示；模型不能自行拉入其他成员。引用网页、历史产物或其他 Agent 回复不获得当前用户指令的权限。

### 5.1.2 预览与提交

- 输入框提供收件人标签、任务/流程摘要和解释依据；不在每次按键时调用模型。
- 点击发送后先解析。结果明确时直接接着提交 Run，不额外要求第二次确认；存在歧义时先显示成员选择或一句澄清，尚不启动执行。
- 解析建议由服务端短期保存，包含 `proposal_id`、原文摘要、词表/配置 revision、确切目标与流程，有效期五分钟；限制解析并发和保存数量。
- 正式提交引用该建议。服务端验证原文、版本、归属和期限，并重新校验成员/权限；建议失效返回 `routing_proposal_stale`，不静默改派。建议不能由客户端自由构造。
- Run 原子保存最终路由、解析来源、输入依据和角色快照。相同幂等 key 的已提交请求先复用原结果，不因预览过期再次派发。
- 路由解析失败不回退到猜测或其他成员；给出诊断和显式选人入口。解析模型调用的耗时、用量和费用与执行调用分开统计，未知用量仍标未知。
- 模型解析遵守工作空间的数据外发确认，CLI 解析单次期限 90 秒（包含进程启动），只暴露路由决策工具，不执行任务工具；显式收件人与确定性流程路径不必增加一次模型调用。

用户可以一直使用自然语言；`@` 是一种精确指定方式，不是参与协作的前提。

### 5.2 协作讨论

适用于比较方案、探索问题、收集不同视角。

1. 至少两个成员基于同一份输入和历史快照独立回答，彼此不读取本轮未完成回复。
2. 所有讨论步骤成功后，协调者读取这些回复，整理共识、分歧、待验证事项和建议下一步。
3. 产出讨论笔记；保留各成员原始贡献。协调者可以是前面参与讨论的成员。

### 5.3 Research

适用于资料研究、技术选型、主题梳理与证据比较。

1. **研究员**明确问题和范围，检索/读取资料，提出带来源的结论与不确定性。
2. **质疑者**独立读取相关来源，检查出处、时效、推论跨度和遗漏，指出支持、争议或证据不足。
3. **协调者**整合为 Research 报告：问题、范围、方法、主要发现、分歧、来源、限制和下一步。

研究员和质疑者必须是两个不同的成员 ID；协调者可复用其中一个成员。同模型、同供应商允许使用，界面不得据此声称是跨模型验证。

“在线发现资料”需要可用搜索服务；“研究给定资料”可使用用户提供的 URL 和本地文件。搜索摘要与实际抓取的原文分别标记。报告不能把摘要检索命中表示为已读原文，也不能把引用存在表示为事实已被证明。

### 5.4 代码分析

适用于仓库理解、指定问题调查和有证据的代码审查。

1. **分析者**使用只读文件工具，记录文件、行号和实际读取版本，提出发现。
2. **复核者**读取相关代码，逐项说明确认、不同意或证据不足；可补充新的发现。
3. 最后一个步骤输出代码分析报告，包含严重度、影响、依据和建议；没有确认问题也要如实说明分析范围。

此流程不修改代码、不执行项目脚本，也不将“静态检查通过”写成“运行已验证”。角色分配不绑定 Claude、Codex 等品牌。

### 5.5 编排共同规则

- 首版流程由代码定义的有限步骤组成：单步骤、并行步骤组、后续汇总步骤；不引入工作流引擎。
- 用户明确 `@成员` 时按自由协作发送，发送预览明确显示覆盖了默认流程；显式同时提交流程和冲突收件人时返回校验错误。
- 选中成员和自然语言明确指派遵循同一目标/角色契约；既定收件人不能被后续模型判断静默替换。
- Agent 输出中的 `@成员` 作为正文展示，首版不自动触发新 Run。真正的交接来自既定步骤计划。
- 每个 Run 开始时冻结角色配置、流程版本、模型、工具权限、上下文选择和输入来源引用。
- 调度前重新校验成员是否停用、资料范围及依赖是否仍可用；不可用时明确失败，不换成员或扩大工具权限。配置编辑对下一次 Run 生效，正在执行的 Run 使用可查看的原快照。
- 前置步骤失败、取消或输出不符合契约时，依赖步骤不启动；独立并行步骤保留已产生的结果。
- 汇总不得把成员异议自动改写成一致同意。人工标记也不得覆盖模型原始结果。

新增工作场景应组合已有角色、步骤和工具，并新增产物 schema/渲染器及契约测试；不得复制一套会话、调度器或消息协议。

### 5.6 成员之间如何交接

首版由服务端执行已接纳的步骤计划。成员通过共享可见消息、来源和产物协作；模型之间不直接建立连接，也不通过一段看似交接的正文自行触发任务。

每条依赖边有一个结构化工作包，保存在已有 Run 计划/Step 输入中，不额外建设一套交接数据库：

- 上游步骤、下游步骤与确切成员 ID。
- 本步职责、用户原始目标及验收条件。
- 已完成的上游消息 ID、确切产物版本和可访问来源 ID。
- 需要检查的结论、分歧、限制和待回答问题。

Research 示例：

```text
用户交付目标
  → 布偶猫检索、读取来源，给出发现与不确定性
  → 服务端保存布偶猫的终态结果，形成交接工作包
  → 缅因猫独立读取依据，给出支持、争议与证据不足
  → 服务端保存复核结果，形成汇总工作包
  → 橘猫读取两方结果和来源，形成保留分歧的报告
  → 页面显示产物与本次协作终态
```

消费者只收到权限内的必要资料，不复制整个上游会话或隐藏推理。前端展示“布偶猫的研究结果 → 缅因猫复核”等交接记录，可展开查看任务说明和输入依据。`handoff_prepared` 表示工作包已准备好；`step_started` 表示执行已开始，两者都不意味着模型已经理解内容。

复核者发现证据不足时可以把问题作为本步结果提交，汇总保留缺口。用户补充问题开启下一 Run；首版没有隐式返工回路。上游真实执行失败则依赖步骤跳过；用户停止时取消整个 Run，并保留已有输出。

模型主动 `ask_agent` / `delegate_task`、临时拉成员或自行增加返工轮次属于后续自主协作层。后续也必须走同一服务端调度、身份、来源和预算机制，不能用解析成员回复中的名字作为调用授权。

## 7. Agent、上下文与工具契约

### 7.1 原生工具循环

```text
冻结本步输入与权限 → 启动独立 CLI 会话 → CLI 请求模型并接收工具调用
    → CLI 通过受控 MCP 请求 Go 校验名称、参数、权限与预算并执行
    → Go 返回关联工具结果 → CLI 继续模型循环 → 完成 / 达到限制 / 失败 / 取消
```

- 模型只提出操作请求；工具执行和权限判断属于 Go 代码。
- 工具结果必须关联确切 `tool_call_id`，携带成功/失败、内容、截断状态和来源引用。
- 工具失败可以返回给模型纠正；达到硬预算、鉴权失败和流中断应结束步骤。
- 模型流必须有协议规定的结束信号；不能把 EOF 或进程退出码单独当成成功。
- 产生报告的步骤通过结构化 `publish_artifact` 工具提交产物；中间研究/质疑步骤只能发布 note，正式报告只由指定汇总/复核步骤提交。参数不符合契约时返回错误，不能从普通文本猜测成功。
- 首版不展示或依赖模型内部推理内容；只展示成员的可见回复、动作与结果。

### 7.2 上下文规则

- 身份按 `workspace_id + agent_id` 定义；上下文按 `thread_id + agent_id` 隔离。
- 网页 CLI 每步骤使用新的独立原生会话，由平台重建上下文：系统职责、用户目标、已完成共享消息、明确的上游结果、所选产物与来源指针。
- 并行步骤使用同一个已提交历史快照；不读取其他并行成员的半条回复。
- 历史选择先取最近完成轮次，再满足预算；保留当前问题和本流程的必要上游结果。首版不做后台摘要和长期记忆。
- Go 对完整输入执行保守字节预算；CLI 负责其实际模型窗口和输出额度。必要输入超限时明确失败，不静默截断关键资料，也不把未知模型窗口标记为已核对。
- 所有网页和文件正文标记为外部资料；其中的指令不能修改系统规则、工具权限或工作空间范围。

### 7.3 工具清单

| 工具 | 输入和输出 | 限制 |
| --- | --- | --- |
| `list_files` | 相对目录 → 文件名、类型、截断标记 | 绑定目录内；过滤忽略目录与敏感路径 |
| `read_file` | 相对路径、可选行区间 → 带行号片段、文件摘要、来源 ID | 文本文件；验证路径和行区间；最多 500 行/32 KiB 输出 |
| `search_content` | 字面量关键词、可选相对子目录 → 文件、行号、片段 | 不接受任意 shell；最多 50 条命中，扫描有时间/字节预算 |
| `web_search` | 查询词 → 标题、URL、摘要、查询时间 | 一种搜索供应商；结果标记为搜索摘要；最多 10 条 |
| `fetch_url` | 公共 HTTP(S) URL → 标题、正文片段、来源 ID、抓取时间 | 无登录、无 JS 浏览器；限制重定向、大小和超时 |
| `read_source` | 可访问的捕获来源 ID → 原捕获片段与出处 | 只读本步已授权来源，不重新读取当前网页/文件 |
| `publish_artifact` | 类型、标题、正文、结构化数据、来源 ID → 产物引用 | 校验类型对应 schema 和来源归属；最终版本在步骤成功后发布 |

文件工具默认忽略 `.git`、`node_modules`、构建目录、应用数据目录、`.env*`、私钥和已知凭证文件。读取失败和无权限必须与“没有结果”区分。

### 7.4 有界执行默认值

| 项目 | v0.1 默认值 |
| --- | --- |
| 每步骤模型轮次 | demo 循环最多 12 次；原生 CLI 内部模型轮次不声称由 Go 逐次计数，受步骤时间与工具预算约束 |
| 每步骤工具调用 | 最多 30 次 |
| 原生 CLI 步骤期限 | 5 分钟；包含原生循环与工具请求 |
| 单步骤总期限 | 5 分钟 |
| 单 Run 总期限 | 15 分钟 |
| 单次抓取/搜索期限 | 20 秒 |
| 网页响应读取 | 解压后最多 2 MiB；送给模型的正文最多 32 KiB |
| 文件读取 | 单文件最多 1 MiB；更大文件明确拒绝并说明 |
| HTTP JSON 请求体 | 最多 64 KiB；用户问题最多 16,000 个 Unicode 字符 |
| 有效取消确认 | 原生请求与工具均已停止后提交；超过 10 秒仍未停止要显示诊断 |

这些值集中在服务端配置中记录，首版网页不提供任意调参。接近 Token 限制时提示剩余能力；供应商未返回用量时展示“未知”，不伪造精确成本。

## 8. 来源与产物

### 8.1 来源记录

每条来源保存 ID、工作空间/会话/Run 归属、类型、标题、URL 或相对文件路径、捕获时间、内容摘要、实际捕获片段和截断状态。文件来源还保存行区间与文件 SHA-256；网页保存最终 URL、访问结果，以及可获取的发布日期。

- 工具产生的来源 ID 由服务端生成；模型只能引用本次允许访问的确切来源。
- 搜索摘要、实际网页正文和文件片段分别标记；不得相互冒充。
- 来源面板首先展示当时捕获的内容。刷新网页或重新读取文件属于一次显式新捕获，不覆盖旧证据。
- 不抓取登录页或绕过付费墙；抓取失败展示原因。缺少发布日期必须显示未知。
- 本地路径只展示工作空间内的相对路径；浏览器不具有任意磁盘读取接口。

### 8.2 产物类型

| 类型 | 必填内容 |
| --- | --- |
| `note` | 标题、正文；适用时附来源和分歧 |
| `research_report` | 问题、范围、方法、发现、争议/证据不足、来源、限制、下一步 |
| `code_analysis` | 分析范围、发现列表、严重度、影响、来源位置、复核结论、建议、未验证项 |

Research 的结构化结论使用 `supported / disputed / insufficient_evidence`；代码发现使用 `confirmed / disputed / insufficient_evidence` 和 `high / medium / low` 严重度。代码报告中每条发现必须有实际文件来源引用；关键研究结论必须有来源或显式标记为推论/待验证。

产物内容采用不可变版本：每次修订生成新版本，保留来源 Run 和成员。人工状态为 `unreviewed / accepted / dismissed`，单独记录操作者和时间，不改变模型原文或执行终态。

导出的 Markdown 包含标题、版本、问题、结果、分歧、来源、生成时间、成员与执行方式、人工状态及限制。演示产物在页面和导出中均标记“离线演示”。

## 9. 执行状态与恢复

### 9.1 Run 状态机

```text
queued → running → succeeded
   │        ├────→ failed
   │        ├────→ interrupted  （重启发现旧运行无法继续）
   │        └────→ canceling → canceled
   └────────────────────────→ canceled
```

- `queued` 表示输入已经持久化；`running` 表示调度器已经开始本次执行。
- Step 状态为 `pending / running / succeeded / failed / canceled / skipped / interrupted`。
- 一次 Run 只有一个不可变终态；成功要求全部必要步骤和产物校验成功。
- 取消与正常完成竞态按持久化 CAS 决定：先提交终态者生效，后续操作返回已存在结果。
- 取消本次 Run 的所有并行步骤与进行中的网络/工具操作；已完成回复保留。仅关闭 SSE 不属于取消。
- 未执行的依赖步骤标为 `skipped` 并说明原因；没有完成复核的产物不得展示为正式完成报告。

### 9.2 排队、重试和重启

- FIFO 以持久化入队顺序为准；本版一个调度 worker，不需要 Redis 或外部任务系统。
- 同一会话最多一个非终态 Run；服务端使用事务约束，不能只依赖禁用前端按钮。
- 客户端发送使用 `Idempotency-Key`。相同 key 和相同规范化请求复用原结果；相同 key 不同请求返回 409。
- 首版不自动重新运行已经发出的模型请求。限流、超时和断流保存诊断，用户可显式重新运行。
- 启动时先完成恢复，再接受新任务：`running/canceling` 收敛为 `interrupted`，保留部分记录；`queued` 在配置与权限重新校验后继续。
- 新 Run 使用当前设置的新快照，并记录 `retry_of_run_id` 或跟进来源；旧 Run 不被覆盖。
- SQLite 事务可以防止重复落库，不能据此承诺外部模型执行 exactly-once。取消已发出的请求也不能保证供应商停止计费。

## 10. 技术架构与代码边界

### 10.1 技术基线

| 层 | 选择与理由 |
| --- | --- |
| Go | v0.1 采用 Go 1.26，最低补丁为 1.26.9；CI 覆盖 1.26 与当前 stable |

| 模型载体 | 复用本机 CLI 认证；成员选择执行器与可选模型；协议成功终止按各 CLI 验证 |
| 数据库 | SQLite，参数化 SQL、显式迁移；一个维护活跃且许可兼容的 Go 驱动，在 M0 固定版本 |
| 前端 | React + TypeScript + Vite，Node.js 22.12+；提交 npm lockfile，CI 使用 `npm ci` |
| 前后端契约 | OpenAPI 3.1；包含普通 API 和 SSE 事件 schema；前端类型从契约生成 |
| 日志 | `log/slog`；使用 workspace/thread/run/step/tool_call ID 关联 |
| 测试 | Go 原生测试、Vitest + Testing Library、Playwright；付费模型测试手动启用 |

本版不引入 Agent 框架、消息中间件、微服务、向量数据库、ORM 或 DI 容器。CLI 协议适配、SQLite 驱动和前端基础依赖均按真实需要选择并固定；不自研已有可靠实现的协议解析或 HTML 提取算法。

### 10.2 目标目录

```text
cmd/cocogem-server/      Web 服务入口与显式依赖组装
internal/agent/          执行器接口与离线演示工具循环
internal/nativecli/      网页 CLI、受限 MCP、事件与进程生命周期
internal/model/          执行请求/响应类型及离线 fake（真实路径使用 nativecli）
internal/tools/          工具 schema、执行、权限、文件与网页读取
internal/workspace/      工作空间、成员与会话规则
internal/workflow/       内置流程、步骤计划、依赖与取消
internal/store/          SQLite 查询、事务与迁移
internal/httpapi/        API、认证、SSE、静态资源服务
web/                    React 应用、组件与浏览器测试
api/openapi.yaml        HTTP 与事件契约
examples/demo/          可公开的本地资料与确定性演示数据
docs/                   产品、架构决策与运行说明
```

目录是职责边界，不要求为每个名词创建抽象。只在实际消费边界定义小接口；先使用具体实现，保持显式构造和依赖注入。关键边界是 `Executor`、`Model`、`Tool` 和事务存储，不建设通用插件框架。

终端入口为 `cmd/cocogem`，实现和测试位于 `internal/cli`；网页使用 `internal/nativecli` 的有界执行路径。`.cocogem/<cli>.json` 不迁作 Web 多会话存储，也不静默改写或删除。

### 10.3 数据模型

| 表 | 最小职责与约束 |
| --- | --- |
| `workspaces` | 名称、说明、允许目录绑定、数据处理确认版本、revision |
| `agent_profiles` | 所属空间、稳定 ID、显示名/唯一 handle/显式别名、职责/提示词、模型、工具集合、停用状态、revision |
| `threads` | 所属空间、标题、参与成员、默认流程、协调者、revision、活动时间 |
| `messages` | 会话/Run/Step、发送者、角色、内容块、稳定创建顺序、草稿/完成状态 |
| `runs` | 用户输入消息、幂等 key/请求摘要、最终路由与解析依据、流程/配置快照、状态、时间、重跑来源、错误 |
| `steps` | 所属 Run、成员与角色快照、步骤序号/依赖、交接输入引用与验收条件、状态、用量与诊断 |
| `events` | Run 内单调序号、事件版本、关联 ID、时间、有限 payload；唯一 `(run_id, seq)` |
| `sources` | 出处、捕获版本/片段、读取类型、时间与访问结果；严格归属空间/会话/Run |
| `artifacts` | 类型、稳定产物 ID/版本、内容与结构化数据、来源、生成步骤、人工状态 |

具体字段类型和索引在 M0 的 schema 设计中冻结。必须具备外键、枚举/空值约束、幂等唯一约束和每会话活动 Run 唯一约束。会话列表状态从最新 Run 派生，避免再维护一份独立执行真相。

SQLite 开启外键、WAL 和有界 busy timeout。必要状态、消息、产物及对应事件通过事务提交；已应用迁移只追加新版本。首次 v0.1 无历史 Web 数据迁移，现有 CLI 记录原样保留。

### 10.4 配置和启动约定

以下为待实现的运行契约，不能当成当前已经可用的命令。

| 配置 | 约定 |
| --- | --- |
| CLI 登录 | 在对应 CLI 中登录；Cocogem 不读取、复制或替换登录凭证 |
| 成员执行器/模型 | 网页选择本机 CLI；模型为 `default` 或明确的模型 ID |
| `BRAVE_SEARCH_API_KEY` | 在线发现资料所需凭证；缺失时禁用该研究范围 |
| `COCOGEM_DATA_DIR` | 默认 `os.UserConfigDir()/cocogem`；SQLite、捕获来源与运行记录位于此目录 |
| `--listen` | 默认 `127.0.0.1:8741`；首版拒绝非 loopback 监听 |
| `--allow-root` | 显式允许的本地资料根目录；可重复；不设置时只有网页资料能力 |
| `--web-dir` | 前端构建目录；开发默认为 `web/dist`，发布包启动按可执行文件位置解析 |

开发目标命令为 `make dev`、`make test`、`make build`、`make demo`。`make dev` 启动 Go 与 Vite，同源 API 经开发代理访问；`make build` 先构建前端再打包 Go 与静态资源。前端资源缺失时启动返回明确错误，不能提供一个页面打不开的“就绪”服务。M0 创建这些入口并由 CI 校验，README 只在命令可用后给出运行说明。

## 11. HTTP 与事件接口

接口以 `/api/v1` 为前缀；ID 使用服务端生成的 UUID；JSON 使用 snake_case；时间使用 RFC 3339 UTC，网页按用户时区显示。以下是接口语义，精确 schema 在 M0 落入 `api/openapi.yaml` 后实现。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /bootstrap` | 消耗一次性本地引导 token，建立 HttpOnly 会话；该路由在 `/api/v1` 外 |
| `GET /api/v1/system` | 返回执行方式、真实可用状态、模型目录、允许资料目录及限制；不返回密钥 |
| `POST /api/v1/system/verify` | 用户显式验证已配置依赖；返回验证时间和结果，不在页面加载时自动调用付费模型 |
| `GET/POST /api/v1/workspaces` | 列表/创建工作空间 |
| `PATCH /api/v1/workspaces/{id}` | 编辑名称、说明和资料绑定；校验 revision |
| `GET/POST /api/v1/workspaces/{id}/agents` | 成员列表/创建 |
| `PATCH /api/v1/agents/{id}` | 编辑或停用成员；不改变进行中的 Run 快照 |
| `GET/POST /api/v1/workspaces/{id}/threads` | 分页会话列表/创建 |
| `GET/PATCH /api/v1/threads/{id}` | 读取或编辑会话配置；消息按 cursor 分页 |
| `POST /api/v1/threads/{id}/routing-preview` | 解析明确选择、`@` 和自然语言指派；返回服务端建议 ID 或具体澄清，不执行工具 |
| `POST /api/v1/threads/{id}/runs` | 原子保存输入、计划和排队状态，返回 202 与 Run ID |
| `GET /api/v1/runs/{id}` | 状态、步骤、消息/产物引用和一致的事件 cursor |
| `POST /api/v1/runs/{id}/cancel` | 幂等申请取消；返回实际状态 |
| `GET /api/v1/runs/{id}/events` | SSE 历史重放与实时订阅；支持 `after` 和 `Last-Event-ID` |
| `GET /api/v1/sources/{id}` | 返回有权限访问的捕获内容与出处 |
| `GET /api/v1/threads/{id}/artifacts` | 会话产物及版本列表 |
| `GET/PATCH /api/v1/artifacts/{id}/versions/{version}` | 读取确切版本/仅修改人工标记，校验 revision |
| `GET /api/v1/artifacts/{id}/versions/{version}/export` | 下载 Markdown，不重新调用模型 |

编辑接口使用 `If-Match` 与资源 revision，冲突返回 412。列表默认 30 项、最多 100 项，使用不透明 cursor。会话与工作空间删除会在同一事务内移除其协作记录、来源和产物，有协作排队或执行中时返回 409；成员只能停用。文件任意读取和任意命令执行接口不在首版提供。

### 11.1 发起协作示例

```http
POST /api/v1/threads/{thread_id}/runs
Content-Type: application/json
Idempotency-Key: 由客户端为一次发送生成的UUID
X-CSRF-Token: 浏览器会话的CSRF值
```

```json
{
  "message": "比较原生工具循环与现成 Agent CLI 的适用场景，列出证据和限制。",
  "workflow": "research",
  "assignments": {
    "researcher": "agent-uuid-1",
    "critic": "agent-uuid-2",
    "coordinator": "agent-uuid-3"
  },
  "source_urls": [],
  "artifact_refs": [],
  "research_scope": "web_discovery"
}
```

上例中的占位成员 ID 在真实调用中必须替换成当前工作空间 UUID。它展示角色分配字段；从自然语言解析而来的提交还须携带服务端 `proposal_id`。自由协作使用独立 schema，提交 `targets`，不混用流程角色分配。前端按同一预览协议验证所有入口，不能凭客户端提供的 ID 绕过成员和权限校验。

错误格式固定为 `error.code / message / request_id / details`。细节字段只包含可公开的字段级错误或状态；不得返回凭证、调用栈或无关本地绝对路径。至少区分 400 参数、401 会话、403 权限/范围、404 不存在、409 状态/幂等冲突、412 revision 冲突、413 大小、429 容量和 503 依赖不可用。

### 11.2 事件契约

事件共同字段：`schema_version: 1`、`run_id`、`seq`、`type`、`occurred_at`、可选 `step_id / agent_id`、类型对应的 `data`。SSE `id` 对应本 Run 的 `seq`。

| 类型 | 用途 |
| --- | --- |
| `run_queued / run_started / run_finished` | Run 生命周期；finished 携带唯一终态与原因 |
| `step_started / step_finished` | 当前成员职责、依赖与结果 |
| `handoff_prepared` | 上游到下游的工作包及输入引用已准备好，不表示接收者已读 |
| `message_started / message_delta / message_finished` | 更新同一消息 ID；delta 明确 append/replace |
| `tool_started / tool_finished` | 关联 tool_call_id、脱敏摘要、结果和来源 |
| `source_captured` | 新来源可查看 |
| `artifact_published` | 新产物版本可查看 |
| `usage_updated` | 供应商实际返回的用量；可标记未知/估算 |

先落库、再通知前端。文本可以按不超过 100ms 的间隔合并落库；已向客户端确认的事件必须可重放。快照与 cursor 同事务读取，订阅与重放不得存在丢事件窗口；重复投递由前端按 `(run_id, seq)` 去重。

心跳不占业务序号。浏览器断线后从最后已处理序号续读；终态后关闭订阅。历史分页、重放和实时流使用同一事件 schema，不维护第二种聊天协议。

人工标记使用 PATCH 返回的当前产物 revision 更新界面；重新打开面板时重新读取。它不追加已经结束的 Run 事件，也不改变 Run 终态。

## 12. 安全与隐私要求

以下要求针对本地文件、外部网页、模型工具和浏览器的真实边界，必须与相应功能一起实现。

- 本地随机引导 token 由 `crypto/rand` 生成，只在启动终端展示；通过 URL fragment 传给前端，再 POST 换取 HttpOnly、SameSite=Strict 会话，随即从地址栏移除。token 一次使用且有期限，不写访问日志。
- 引导端点验证一次性 token、Origin 和 Host，不要求已有登录状态；返回会话 cookie 和 CSRF 值。刷新时经已认证的 system 接口取得本会话 CSRF 值。
- 其他 API 和 SSE 都验证本地会话；变更请求验证 CSRF、Origin、Host 和 JSON Content-Type。开发代理也明确配置允许来源，不能使用开放 CORS。
- 修改资料目录绑定前要求该工作空间没有非终态 Run；历史捕获内容仍可查看，新工具调用只能访问新的绑定范围。
- 凭证仅服务端读取；忽略 `.env`、数据库、原始资料、CLI 会话记录和前端构建产物。提供只含占位值的 `.env.example`。
- 文件访问使用 Go `os.Root` 等具备范围保证的能力；拒绝绝对路径、路径穿越和越界访问。首版拒绝符号链接路径，并验证敏感路径过滤；禁止只做字符串前缀判断。
- 网页读取仅允许公共 HTTP(S)，拒绝 localhost、私有/保留/链路本地地址和云元数据地址；DNS 解析、实际连接及每次重定向均执行相同检查，防止解析后换地址。首版不继承任意环境代理，不携带用户 Cookie 或跨站 Authorization。
- 所有工具有输入、时间、输出及资源预算；禁止任意 shell、网络端口探测和写磁盘工具。模型给出的名称、参数和引用均视为不可信输入。
- Markdown、文件和网页中的 HTML/指令作为资料处理；前端不能执行模型生成的脚本。
- 默认运行日志仅记录元数据与脱敏错误；消息与捕获片段保存在用户数据目录，目录 0700、含数据文件 0600。明确数据位置和停止服务后的备份方式。
- 外部研究会暴露查询词和资料片段；软件无法识别源码中所有硬编码秘密。README 和首次使用说明必须如实表达这个边界。

## 13. 开源工程规范

### 13.1 仓库与协作

- 正式仓库为 `github.com/AcSunday/cocogem`，Go module 使用同一路径；已初始化本地 Git，按功能测试通过后提交独立 commit。
- 项目代码计划采用 MIT；采用自身名称与视觉资产。引用或移植上游代码时核对文件许可、保留要求的版权和许可说明，并记录来源版本；依赖许可另行核对。
- 首次公开前补齐 `LICENSE`、`README.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md`、变更记录和 PR 模板。
- README 区分当前已实现功能与计划，包含离线演示、真实运行、环境变量、数据位置、限制和截图；不放未验证的 CI 徽章。
- PR 按可独立验收的范围拆分，说明用户行为、契约变化、验证和迁移；CI 必须通过。风险修改需要独立审阅，AI 自评不能代替测试。
- 开源发布、推送、公开仓库创建和发布凭证配置是单独操作；文档完成不意味着已执行这些动作。

### 13.2 代码与依赖

- Go 使用 `gofmt`、显式错误处理、`context` 传播、资源关闭和有界并发；导出符号有准确注释。
- React 使用语义 HTML、受控表单、明确的状态归属和可测试事件 reducer；避免万能组件与复制运行状态。
- 输入校验放在边界；内部使用明确类型。外部协议在适配层结束，不能把供应商事件名散布到业务和前端。
- 新依赖说明用途、替代方案、维护状态和许可；提交 lockfile。CI 工具固定版本，GitHub Actions 固定已审核的完整 commit SHA。
- API 与事件变更同时修改 OpenAPI、生成类型、服务端、前端、fixtures 和相关测试；CI 验证生成文件无漂移。
- 重要决策以简短 ADR 保存原因和取舍，包括 CLI 优先与连接配置复用、有限流程、SQLite、SSE 和本地安全边界；普通实现细节不写 ADR。

### 13.3 CI 和发布门禁

| 检查 | 必须验证的内容 |
| --- | --- |
| Go | 格式无差异、`go vet ./...`、`go test -race -shuffle=on ./...`、构建 |
| 依赖安全 | 固定版本 `govulncheck`、前端生产依赖审计；可利用的高危问题须修复或有具体验证的例外记录 |
| 前端 | `npm ci`、lint、TypeScript 检查、单元/组件测试、生产构建 |
| 契约 | OpenAPI 校验、生成类型无差异、真实 API 响应与事件符合 schema |
| 浏览器 | Playwright 通过真实 Go HTTP/SSE 和 fake 模型跑用户流程，不只 mock 页面请求 |
| 可复现性 | `go mod tidy` 与生成操作后工作区无意外差异；发布包从干净 checkout 构建 |
| 基本安全 | 密钥扫描、路径/SSRF/鉴权负例、Markdown XSS 和并发取消测试 |

PR CI 不需要模型或搜索密钥，不允许外发真实项目源码。真实模型 smoke test 由维护者手动启用，记录供应商、模型、版本、脱敏结果和用量；不能把离线测试称为模型效果验证。

发布使用 SemVer 和变更记录。v0.1 构建 macOS arm64、Linux amd64 发布包，附校验和、许可及启动说明；每种宣称支持的平台完成对应 smoke test，未验证平台不标支持。正式发布前验证备份/恢复，不提供一键破坏性清库操作。

维护一小组可公开任务和人工判据，覆盖讨论分歧保留、研究来源质量、代码发现正确性。记录单成员与多成员的结果质量、误报/漏报、耗时和实际可获取的用量。首版公布方法与有限样例，不声称多 Agent 必然优于单 Agent。

## 15. 分阶段实现与完成条件

每个阶段先跑通一条用户路径，再补齐本阶段失败边界。后端和前端共同推进；不能把可交互页面推迟到全部后端结束以后。

| 阶段 | 具体交付 | 完成条件 |
| --- | --- | --- |
| M0 工程与契约 | Git/module、许可证与贡献规范、Go/前端基线、OpenAPI、schema/迁移、fake、基础 CI | 新 checkout 可按说明启动前端与 Go 服务；测试不用密钥；既有 CLI 行为不回归 |
| M1 首条垂直流程 | 工作空间/成员/会话、网页发送、持久 Run、CLI 原生 Loop、受控资料工具、SSE | 页面能完成一次真实 CLI 单成员资料问答；demo 同路径；失败/取消/刷新可验证 |
| M2 多成员协作 | 名称/别名、自由 `@`/自然语言指派、并行讨论、角色分配、结构化交接、有限上下文 | 明确指派准确送达，歧义不执行；独立回答再汇总；交接/来源可看；并发/取消测试通过 |
| M3 Research 与代码场景 | 搜索/网页读取、来源捕获、研究-质疑-汇总、代码分析-复核、产物版本 | 三种流程真实可用；报告引用可打开；依赖缺失不伪装成功；静态/运行证据边界清楚 |
| M4 恢复与体验 | 排队/幂等、启动恢复、断线续读、人工标记、导出、响应式与可访问性 | 完整浏览器流程、恢复/竞态/安全负例通过；重启后历史和证据仍可读 |
| M5 开源发布准备 | 干净构建、支持平台 smoke、文档/截图/录屏、公开评测样例、依赖许可清单 | 本文验收项全部有证据；发布包无凭证/私有数据；具备可审阅发布候选 |

M0 的基础契约按版本演进，M1 起开始落地安全边界和取消，不集中拖到 M4。M4 验证全流程和重启场景。不得为了赶阶段将 CI 失败、不可复现错误或权限问题记作“已完成”。

## 17. 实现依据与原型来源
