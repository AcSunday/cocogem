# 成员与共享技能协作

成员、模型连接和任务角色分别配置。全局成员可以加入多个工作空间，同一个成员在不同任务中可以承担不同角色。模型连接沿用本机 CLI 的现有配置。

## 配置与数据

- `global_agents` 保存稳定成员 ID、显示名、handle、职责、能力、内置头像、CLI、模型、全局工具允许集和配置版本。头像只接受内置值，不使用远程 URL、SVG 或上传内容，也不进入模型提示。
- `workspace_members` 保存空间与成员的关联、启用状态、工具授权和版本。有效工具为全局允许集与空间授权交集；删除空间或移除成员不删除全局档案。
- `settings` 保存单条全局默认协调者与按 workflow 的角色分工，带 revision。新建会话和解析分工时只使用当前空间已启用且具备所需工具的成员；显式选择优先，默认值不会新增空间关系、权限或会话成员，互斥角色会获得不同成员，两名成员都可行时唯一发布者优先承担复核角色，缺失角色按会话名单补足；显式指定但不可用的角色返回校验错误而非静默改派。预览先验证完整计划，新会话输入区显示实际协调者及默认不可用时的简短回退说明；会话输入区不编辑角色分工，接受路由后的分工摘要仍可见，已有会话协调者与 Run 快照不随设置改写。写入校验 `If-Match`，未知 workflow/角色/成员与重复的互斥角色会被拒绝，空值表示重置。
- Thread 保存参与者和协调者，最多四名成员。Run 保存本轮有效成员与技能版本快照；临时角色、任务说明、依赖和结果归入 Step。
- 旧数据库打开时在事务中迁移，每个旧成员保留原 ID，名称相同也不合并；历史消息和 Run 内容不重写。数据库备份与恢复继续按 README 操作。

全局修改成员会影响以后使用它的空间；空间授权只影响当前空间。运行中的配置快照保持可追溯，但派发和工具调用仍检查当前停用、空间关系和权限撤销；配置变化导致不可继续时如实失败，不静默换人或扩大权限。

## 如何发起

1. 在“设置 → 成员”创建全局档案，配置能力、CLI 与内置头像；把现有档案加入需要的空间。成员编辑不依赖当前是否存在工作空间，新建档案不会自动加入空间。
2. 在“设置 → 协作”选择默认协调者和各模式角色默认值；显式会话选择与每轮分工仍然优先。
3. 会话选择参与者和协调者。普通定向问答继续用 `@`；需要动态协作时，在自由协作中说明目标、分工或所需的研究/复核。
4. 空间设置选择共享技能。默认启用全部，显式取消全部后不会提供技能读取工具。
5. 发送任务；时间线显示任务交接、接收者、状态、输入依据和结果回传。停止按钮取消整轮，刷新后可继续查看持久记录。

用户显式选择优先。协调成员仅在原始任务需要时从名册选人，平台不从名称或 CLI 品牌推定能力。固定的讨论、Research、代码分析继续按选定步骤执行，不额外创建动态流程。

## 共享技能

唯一源目录为 `internal/skills/library/`，每项包含 `SKILL.md` 和实际需要的 `references/*.md`；通过 `go:embed` 随程序发布。修改后重新构建程序。该目录参考 Clowder 的单一源与按需加载思路，不复制其具体成员安排和平台工具名。

每次调用注入 bootstrap 与已启用的技能元数据。模型按需调用 `read_skill(skill_id, resource)` 读取正文和参考文件，参考文件默认入口为 `SKILL.md`。隔离 CLI 的本地工具限制不改变，不向本机 CLI 配置目录写入或安装技能。

技能正文只描述临时角色、能力和协作方法。具体名字、handle、模型和真实成员 ID 来自本轮名册。版本摘要覆盖入口与参考资源，Run 还保存整体快照摘要；`skill_read` 事件表示内容已返回，不证明模型严格执行了所有说明。

内置：`task-orchestration`、`task-handoff`、`independent-review`、`synthesize-results`。

## MCP 交接与异步结果

`handoff_task` 只提交当前 Run 内的工作，不允许跨空间、虚构或自身目标。字段：

- `request_id`：当前发送步骤内稳定的幂等标识。同一标识修改内容会被拒绝。
- `target_agent_id`：名册中的真实成员 ID。
- `task`：具体问题、范围、预期输出与完成条件。
- `role`：本次临时角色。复核或质疑必须引用另一成员已提交的工作。
- `context_refs`：最多十二个当前会话已提交的消息 ID、来源 ID 或 `产物ID@版本号`。

工具返回 `task_id`、`continuation_id` 和 `accepted`。这只是平台接收回执。成员结束当前 CLI 调用后，平台执行已保存的子任务，在依赖收敛后重新调用发送者，提供成功或失败结果。独立提交可并行，嵌套交接会延后原消费者，直到嵌套结果准备好。

`get_task(task_id)` 查询当前 Run 的持久状态。`task` 保留原调用，顶层 `status` 与 `final_step` 追踪该任务自己的后续处理，避免把“已发出委派”当成整个任务成功。过大的查询返回截断标志和精确产物引用，不挤爆工具结果。

每轮限制：最多十二次交接、三十二步、四层委派；Run/Step 执行时限与停滞告警单独配置。队友失败仍可回传说明缺口；整轮保留失败状态。取消后不启动回传且不会自动复活；重启先核实旧执行归属和已提交记录，未完成步骤从检查点继续；已委派任务失败时仍把失败结果回传给协调者处理。无法核实的外部结果保留中断并要求人工确认，不自动重放。已提交的交接会阻止重试尝试创建重复任务。MCP 不提供运行中推送或 CLI 共享模型记忆，普通正文 `@` 不触发任务。

## 交付引用

只有被指定为最终交付的步骤可以发布正式产物；中间研究、质疑、草案和委派步骤不发布正式产物，根成员委派后先前提交的内容只保留为该 Attempt 的未发布草稿。Run 成功时在同一事务记录最终消息 ID 与确切的 `产物ID@版本号` 列表；线程产物列表只展示这些版本。成功但缺少指定最终结果时整轮失败，不按最后时间戳或最新产物猜测。未交付草稿仍可通过确切版本端点、Attempt 和事件追溯。旧历史没有交付记录时不回填、不推断，其已存在产物继续可见。

## 验证入口

- `make test`：行为、迁移、权限、幂等、并行、嵌套回传、失败、取消、技能读取和原生 CLI 兼容测试。
- `make build`、`go run ./cmd/smoke`：正式构建、HTTP、持久化及备份恢复。
- `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e --prefix web`：隔离测试服务中的浏览器流程。测试 fixture 不作为产品运行模式。
- `COCOGEM_CHECK_LIVE_COLLABORATION=1 go test ./internal/httpapi -run '^TestLiveMixedCLICollaboration$' -count=1 -timeout=15m -v`：调用现有本机模型配置的真实混合 CLI 流程，内容仅为公开合成资料。默认优先三个不同 CLI，显式 `COCOGEM_LIVE_REVIEWER_CLI=claude` 可以选择已支持的复核 CLI；实际使用者与限制必须记录。

实机结果和未通过项见 `development-progress.md`，不能用模拟测试代替真实模型验收。
