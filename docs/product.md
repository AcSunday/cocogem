## 定位与范围

Cocogem 是面向本地单用户的多 Agent 协作项目空间。它调用本机已可用的 Claude Code、Codex、Gemini、Pi 或 OpenCode，让成员围绕持久目标讨论、研究、分析数据或执行受控开发，并保存任务版本、消息、来源、协作回执、验收记录和交付物。

产品以项目、任务和成果为中心：默认展示问题、成员回复及最终成果，执行过程按需展开。用户选择成员与任务目标；平台负责身份、权限交集、有限计划、来源引用、根任务预算及状态恢复，不按 CLI 品牌推定成员能力。

当前不提供多人账户、公网托管、任意扩展或跨项目自动共享。网页是唯一产品界面，但不接管用户已有的原生 CLI 交互会话。内置资料提取不提供登录网页抓取、OCR 或音视频解析：支持 UTF-8 与带 BOM 的 UTF-16 文本/源码、CSV/TSV、HTML、受限单页文本 PDF，以及 DOCX/XLSX/PPTX 原生解析；旧版 `.doc`、RTF、ODT 在本机存在 `textutil` 或 `pandoc` 时转换，否则明确拒绝，旧版 `.xls/.ppt` 明确报告未支持。已获授权的成员可尝试调用本机程序处理其他格式，实际能力取决于安装、权限和任务，不能将其当作内置解析或已验证能力。加密文档、图片文字和复杂版式不会因提取失败而被假装成已读。跨 adapter×OS 的通用原生 shell 隔离、自动集成/部署和定时 Schedule 尚未形成已验证执行闭环；显式 `full_access` 的本机原生命令不等同于已隔离或可完整审计，不按已有持久唤醒能力宣称自动 Schedule 已交付。

## 核心对象

| 对象 | 含义 |
| --- | --- |
| 工作空间 Workspace | 项目边界，包含会话、成员关联、共享技能及可选本地资料/工程目录；权限与协作预算默认值由全局统一配置 |
| 任务 Task / 任务版本 TaskRevision | 跨 Run 的工作身份，以及不可变的目标、范围、验收和允许动作版本；可先保存，首次执行时绑定主会话 |
| 项目记录 ProjectRecord / 记忆 MemoryRecord | 有来源、可见性和不可变版本的有效约束、决定或派生经验 |
| 成员 Agent | 可复用的全局档案，含稳定 ID、名称、handle、职责、能力、CLI、模型和执行选项；旧工具数组仅作历史兼容 |
| 空间成员 WorkspaceMember | 将全局成员加入空间，管理启用状态；不提供独立工具权限 |
| 会话 Thread | 保存参与者、协调者和有序历史，名册最多 10 人；单次显式 `@` 初始收件人最多 4 人；内部任务线程默认不进侧栏 |
| 协作 Run | 一次用户提交或自动续办，冻结成员配置、技能版本、授权和执行策略；关联任务时另冻结目标版本 |
| 步骤 Step / 尝试 Attempt | 步骤保存职责与依赖；每次执行尝试保存 CLI、连接、进程、会话、上下文及恢复信息 |
| 执行 WorkspaceExecution / 会话 ExecutionSession | 候选目录、基线和租约，以及一次性执行会话的指纹、披露范围和撤销版本 |
| 操作审批 / 会话授权 / 预算 BudgetAccount | 执行前的单次或同会话共享授权及撤销版本；每个根任务与其 owned descendants 共用各自的累计预算账本 |
| 验收 CompletionRecord / 副作用 EffectRecord | 绑定任务版本和证据的逐项验收，以及受管理效果的实际/不确定结果 |
| A2A 消息 / 投递回执 | 不可变任务间消息及逐目标 queued/presented/handled 等观察，不等同于验收完成 |
| 等待 Wakeup / 补充 Inbox / 问题 Question | 持久等待条件与代际、执行边界补充和绑定具体任务版本的问题 |
| 消息 Message | 用户输入与成员输出；长正文独立持久化，页面按需分页 |
| 来源 Source / 数据 DatasetManifest | 已捕获的原件、网页、文件、原生观察、diff、测试或分析证据及其数据集版本 |
| 产物 Artifact / 交付 Delivery | 不可覆盖的产物版本，以及成功 Run 明确交付的消息和版本引用；包含研究图表等类型 |

全局成员可用于多个空间，移除空间关系或删除空间不删除全局档案。成员使用稳定 ID，不因同名合并；历史消息、产物、任务版本和 Run 快照不随配置编辑重写。成员管理为每个档案提供图标删除入口并在删除前确认；删除会移除全局档案及所有空间关系，清理默认协调者和相关会话名单，但历史消息、Run 快照与已完成任务记录保持可读。Run 执行成功只说明交付成立；Task 仍需当前必需验收全部满足才能完成，报告反馈不自动等同于任务验收。

## 首次使用与日常操作

1. 启动服务，首次打开网页时设置并确认本地访问密码；之后使用该密码解锁。
2. 直接输入目标。首次输入会在同一事务中创建默认「未命名项目」、会话和可编辑的默认成员档案；不要求先完成成员或项目向导。已有全局成员会复用，不从旧 Run 回填任务或验收。选择附件只把文件保留在输入区草稿中，不创建会话或上传原件；首次发送时才创建会话、上传所选资料并提交执行。
3. 一个可用 CLI 时沿用该 CLI 的 provider、endpoint、模型与凭据并建立默认成员；检测到多个 CLI 时仍给出可直接使用的默认协调者和其他默认档案，成员配置保持可选。没有可用 CLI 时保留输入草稿并显示安装/连接诊断。
4. 研究目标不需要工程目录；第一次工程任务就地选择目录。首次初始化默认 `workspace_autonomous`；之后新空间沿用当前全局权限。Composer 与「设置 → 权限」同步切换两档模式，目录绑定不覆盖任务本身的只读要求。Composer 另有单轮「仅规划」开关：本轮只读证据、不改代码、不改变全局权限或授权版本。
5. 简单问答与普通未升级单成员对话保留为普通会话并直接作用于绑定目录；需要交付、开发验证或持续推进的目标可在原会话升级为持久 Task（并派生隔离的候选 worktree）。也可先在任务清单保存目标，再开始执行并生成主会话。项目首页保留欢迎页和少量摘要，任务页支持清单、看板、搜索及项目/负责人/状态筛选；清单默认按需要你、进行中、待推进和待验收组织，常态行保持紧凑两行（标题与来源/负责人/子任务），只有需要你或失败的行以 3px 语义边框单行直出真实阻塞原因；已验收与已取消默认收进底部「已归档 N 项 ›」抽屉。任务板、项目摘要、工作空间任务列表与单任务详情统一输出待批授权、未决问题、活跃/待处理子任务数与未应用候选摘要，其中列表与摘要均由一次读事务批量组装、不按任务逐条查询；进行中的子任务使父任务保持进行中，不抢跑进入待验收。阅读流式回复、来源、执行过程及最终交付物；可停止协作、补充问题或记录人工验收。

成员创建与编辑不依赖当前是否存在空间，新档案不会自动加入空间。「设置 → 协作」只保存默认协调者和未来根任务预算；单一动态协作内核不再有预设流程的角色槽位。默认协调者只从当前空间已启用成员中生效，不扩大成员名单和授权。已有会话和运行中的快照不被全局默认值改写。

成员模型为空或 `default` 时沿用本机 CLI 配置。`context_size` 是宿主输入的估算 token 预算，0 表示沿用 CLI 默认，显式值至少 1024 tokens；它只用于宿主限制，不改变 CLI 自身的上下文窗口。已有配置数值保留，但单位按估算 token 重新解释。`thinking_level` 为空沿用 CLI 配置，显式值按适配器校验：

| CLI | 可显式选择的 thinking 级别 |
| --- | --- |
| Claude | low、medium、high、xhigh、max |
| Codex | low、medium、high、xhigh、ultra、max |
| Gemini | low、high；显式设置思考级别时必须同时指定具体模型，不能使用 `default` |
| Pi | low、medium、high、xhigh、max |
| OpenCode | 从当前模型的原生 variants 动态读取；留空沿用本机或 `provider/model#variant` 配置 |

头像支持本地 PNG/JPEG 上传：最多 512 KiB、单边不超过 2048 像素，检查 MIME、尺寸和完整解码。拒绝远程 URL、SVG 和非法图像；旧内置图案可继续显示与清空，新档案只使用上传图像或默认头像。头像不进入模型提示。

目录可通过浏览器逐层选择，也可输入绝对路径或 `~/` 路径；保存前校验并记录真实绝对路径。取消选择不改原绑定。`--allow-root` 可重复指定，限制可浏览和绑定的范围；未指定时由已解锁的本机用户选择目录。敏感目录、符号链接逃逸和不可读路径被拒绝；活跃协作期间不能更改绑定。

### 项目首页与会话界面

项目首页保留欢迎页（场景卡片与成员提示）和桌面项目摘要，700px 及以下隐藏摘要及占位。最左侧第一个首页图标管理首页与会话，第二个图标管理全局任务清单和任务详情；打开任何执行会话都会点亮首页图标，包括从任务详情进入的会话。任务清单与任务详情隐藏工作空间会话导航，以及顶部的工作空间成员和协作入口；打开会话后恢复。高亮由当前页面确定，直接访问链接、刷新和浏览器前进后退采用相同规则。

任务清单默认使用焦点清单：先显示需要你，再按进行中、待推进、待验收排列；常态行紧凑展示标题与来源/负责人/子任务，只有需要你或失败的行以 3px 语义左边框单行直出真实阻塞原因，回答、待批授权、失败、中断和运行停止进入需要你，未开始、暂停与真实等待条件进入待推进。可切换为看板；看板列为待办、进行中、等待处理、待验收、已验收，已取消任务存在时显示取消列。提供标题/目标搜索、项目、负责人和状态筛选，本地会话内保留筛选与视图选择；已验收与已取消任务默认从清单收进底部「已归档 N 项 ›」抽屉，可通过状态筛选或清单底部入口查看。支持多选后永久删除，删除前必须确认；删除会一并移除选中任务及其子任务、关联会话、执行记录、协作消息和成果。仍处于活动状态、存在未核实副作用、与其他任务共享会话，或被删除范围外任务有效依赖时拒绝删除并给出原因。运行成功仅进入待验收，不能通过拖动、手动勾选或最后消息时间伪造完成。

清单/看板切换位于任务页顶栏右上角；宽屏看板居中并限制最大宽度和列高，各列采用状态同色系淡底并在列内滚动。卡片只显示标题、状态、负责人和按钮，正文与操作区共享整卡 hover/focus。移动端看板可横向浏览，头部操作可换行，状态点与边线保持间距。执行停止在任务清单与任务详情头部统一显示「执行已停止」，运行记录显示「已停止」；任务被取消仍显示「已取消」。

「新建任务」可保存尚无会话的待办，也可创建并开始；标题与目标独立保存。首次开始在同一事务创建主会话、绑定任务、冻结权限与上下文并提交 Run。重复创建使用稳定 request_id 去重；重复开始返回该任务既有执行，失败或结果不确定时也不会通过再次开始自动重放。成员步骤重试保留已完成工作并核对旧进程状态；服务重启后的自动恢复另有下述限制。任务详情以未回答的问题卡、只读任务说明、上次执行、交付成果和验收为主；未回答问题不折叠。状态、负责人和关联会话位于属性区。「去验收」打开独立人工验收弹窗，任务页没有内嵌「验收交付」、任务设置、手动暂停/取消/目标/预算编辑，参考来源展示及其专用请求、派生与证据选项也已移除。执行过程和来源在关联会话查看，成果文件仍提供实际版本下载。永久删除会移除任务树及其关联会话，无法恢复。可拆分子任务，各自拥有内部会话并共享根任务预算；内部会话默认不进入普通会话列表。

普通问答不再无条件建立 Task。首轮沿用当前模型调用，由协调者或该轮实际收件成员通过受控 `promote_to_task` 提交标题、目标和当前用户输入的确切未引用指令。模型判断语义，代码核对消息来源、活动会话、成员与权限，并在事务中去重、绑定 Task/TaskRevision、预算和上下文：若本轮需要其他成员协作，协调者可在同一次调用中紧接着调用 `handoff_task` 直接派发后续步骤（自动吸收未启动的立项续接步，不再额外重复拉起协调者 CLI）；若由单成员自行执行，则在原会话的新执行步骤继续。简单解释、一次检索、假设和否定请求保持问答；消息长度、工具调用次数和成员提及本身都不触发任务。意图不明时继续讨论；无活跃执行的普通会话提供「转为任务」入口。任务建立前使用只读问答工具，不提前开放原生命令，也不因全局项目内自主误触发额外审批。升级不扩张任务目标和语义只读范围，旧成员工具数组不再作为新执行的隐藏权限。

升级保留原会话身份和所有历史，之前的普通问答 Run 不回填任务身份。围绕既有任务继续执行时沿用当前目标版本；已接受的会话目标补充形成新修订，单纯追问不覆盖目标。已验收任务的关联会话收到新的推进消息时自动推进目标修订并重新激活，而不是返回冲突；同一任务有未决问题或待批授权时，列表、会话顶栏胶囊和详情页一致显示「需要你」。人工验收可选择确切交付产物版本或属于当前任务成功 Run 的最终 Delivery 回复；未交付草稿、失败/中断回复、其他任务和升级前普通问答不能作为候选。弹窗冻结目标修订、评估版本、条件和候选；目标变更后要求重新核对，保存中不能关闭重投。宿主校验 Task 归属和确切 Delivery 并计算正文摘要，人工判断明确标为 human_confirmed。旧 Task、成员 ID、不可变目标/完成记录、正文与累计预算保持原样，旧来源证据仍可读。

权限由全局统一保存，输入框底部模式选择与「设置 → 权限」同步，切换空间不改变选择；编辑工作空间和空间成员模态框不再提供权限或预算。权限页可查看、撤销当前会话持续授权。「设置 → 协作」管理全局预算默认值。设置采用字段合并和版本校验，保存预算不会覆盖权限；权限收紧阻止新准入并核实受影响执行，无法确认停止时报告未核实状态，历史快照和预算不重置。

侧栏提供空间切换、新建会话、标题搜索和会话菜单；菜单支持重命名及工作空间操作。删除会话无需二次确认，会立即移入回收站。各成员的工具执行活动位于其回复旁，默认折叠，按需查看真实工具、目标、耗时、退出码和有界输出；同一调用的授权等待与最终结果不会重复计数。待授权操作始终位于折叠区外。右侧协作面板保留来源与产物，移除「过程」页签。

输入区 Enter 发送、Shift+Enter 换行；输入法确认不会误发送，`@` 支持键盘补全成员，不再提供 `/` 协作模式菜单或预设流程选择器。常态桌面 placeholder 为「一起构建什么？（Enter 发送 · Shift + Enter 换行）」，900px 及以下只显示「一起构建什么？」。右上角透明提示图标在悬停、聚焦或触屏点击时说明 `@` 指定成员与协调者默认分工方式，浮层避免视口裁切；补全和弹窗关闭不覆盖后到的编辑或光标位置。自由协作不提供自动指派开关或数据共享确认门禁；助手正文中的 `@` 不会触发派发。

会话操作报错、路由澄清和权限模式切换失败显示在输入框上方的浮层中，右上角提供圆形关闭按钮。关闭提示保留草稿并将焦点返回输入框，不发送消息、不更改权限，也不重试执行；新的请求仍可显示新的提示。任务清单和任务详情没有输入框，操作错误仍在页面中显示。

最左侧窄栏固定提供齿轮设置入口；外观在「设置 → 外观」中切换浅色、深色、暖色或跟随系统，保存为本机偏好。页面支持移动端、键盘操作、焦点反馈及减少动态效果。消息可查看原文和模型信息，长内容分页，报告可打开阅读并导出。

### 回收站与清理

会话先软删除，保留身份及完整历史，可在保留期内恢复。侧栏删除会话直接移入回收站，不再二次确认；回收站顶部可调整保留周期，支持多选、全选后批量恢复或永久删除，永久删除前仍需确认。默认保留 7 天，可在全局设置中调整为 1–3650 天；到期由维护任务清理，也可显式永久删除。永久删除不可恢复。

正在运行或仍有待核实归属进程的会话不能删除；删除空间也受活跃协作及进程检查约束。移入回收站会撤销持续授权、取消挂起审批，但冻结保留未应用的候选 worktree 与 IO 目录，恢复后代码改动完好。永久删除、到期清理和删除空间会回收对应候选 worktree、IO 目录并 `git worktree prune`，主仓不留孤儿元数据。永久删除会清理对应运行、消息、来源、产物、事件和正文，保留独立的全局成员档案。

## 协作方式

### 单一动态协作内核

用户可显式 `@` 一个或多个成员，或在 Composer 选择收件成员；显式收件人优先于会话协调者。正文没有明确收件人时，消息直接进入会话协调者的流式首步。发送前没有串行的模型预路由，也没有 `/` 协作模式菜单：`@` 与自然语言中的成员称呼都只由后端确定性解析，未点名即交给协调者。

一次 `@A` 产生一个可写步骤；`@A @B` 产生两个互不可见的并行步骤，该轮并行盲答自动带上 `Step.ReadOnly`，项目目录被锁为只读。正文中的否定与条件式提及仍会触发澄清，不会误派给被排除的成员；无效成员报告错误并保留草稿。

成员在步骤内通过受控 `handoff_task` 自行组织后续工作：`mode="relay"` 把控制权直接交给下一位成员（执行 → 独立复核），`delegate` 则让平台在该成员完成后回到它继续。没有固定 DAG、固定角色槽位或必填报告模板；成功交付就是成员已提交的回复或它自愿发布的 `note`/`research_report`。

### 复核收敛与防乒乓

独立复核（`reviewer` / `critic`）不能是作者本人，且必须引用已提交的确切上游引用。复核步骤可调用 `submit_review_verdict`：`approved` 表示问题已核实、无需返工；`changes_requested` 表示还需一轮有界修复。同一复核者对同一作者的点对点返工硬上限为 2 轮；达到上限后，宿主拒绝第三轮 `relay` 返工，要求复核者按现状交付并明确保留未解决分歧。

### 设置

全局设置只保留默认协调者、保留周期和未来根任务预算；不再有预设流程的角色默认值或会话级分工编辑器。成员工具数组是历史审计数据，不再是新执行的权限来源。

### 成员交接与共享技能

自由协作使用现有的 scoped MCP bridge，不解析助手正文派发任务：

| 工具 | 契约 |
| --- | --- |
| handoff_task | 提交当前 Run 内的任务，支持 `delegate`（默认，子任务结束后回到发送者汇总）和 `relay`（点对点接力 A2A，直接将控制权与当前步骤成果移交目标成员，如执行者完成后直接唤起复核者）两种模式，角色含 `engineer`、`researcher`、`analyst`、`reviewer`、`critic`、`coordinator`、`member` |
| submit_review_verdict | 独立复核步骤提交结构化结论（`approved` 提前收敛，`changes_requested` 进入有界返工；同问题最多 2 轮） |
| get_task | 查询当前 Run 中任务自己的持久状态及后续回传结果 |
| read_skill | 按需读取当前 Run 启用的共享技能和允许的参考文件 |
| read_context / read_source | 分页读取当前步骤已获授权的确切消息、产物版本和捕获来源 |

`handoff_task` 使用发送步骤内稳定的 `request_id` 幂等去重，同一 ID 修改内容会被拒绝。不允许虚构成员、自我委派或跨空间派发。`context_refs` 最多 12 个，必须是完整消息 ID、来源 ID 或 `产物ID@版本号`；短 ID、步骤 ID 和越权引用被拒绝，独立复核也不能引用目标成员自己的作品作为待审对象。`mode="relay"` 下由当前作者把本步成果直接接力给复核者时，平台自动传递已提交回复与捕获的 diff/test 来源，复核无异议可直接结束整轮而不强制绕回发送者。

平台接收任务不等于任务完成。`delegate` 模式下当前 CLI 调用结束后运行子任务并在收敛后回传发送者；`relay` 模式下直接调度下一位接力成员。独立步骤可并行，嵌套委派会延后消费者；每轮最多 12 次交接、32 步、4 层嵌套委派。运行期间立项/编排步与已完成的中间上游步骤收纳在协作过程抽屉展示。

共享技能唯一源为 `internal/skills/library/`，随程序嵌入。固定 10 个内置工程技能：`task-orchestration`、`task-handoff`、`independent-review`、`synthesize-results`、`file-delivery`、`writing-plans`、`debugging`、`tdd`、`quality-gate`、`receive-review`。每条 `description` 必须包含 `Use when` / `Not for` / `Output` 且 ≤240 字符，单篇正文 ≤90 行，`library_test.go` 静态强校验，保证 bootstrap 索引稳定。跨技能方法位于 `library/_shared/references/*.md`，通过 `read_skill(skill_id="_shared")` 读取；任一技能或 `_shared` 内容变化都会改变 `SnapshotHash`。项目可在 `.agents/skills/<id>/SKILL.md` 只读提供最多 8 个项目技能：符号链接越界、敏感路径、同名内置技能均被拒绝，项目技能只读、只接受 `SKILL.md`，并纳入同一快照。

启动时提供 bootstrap 与索引，正文和参考文件按需读取，不安装到用户 CLI 配置目录。技能只描述运行时角色、能力及方法，不绑定具体成员、handle、CLI 或模型。

工作空间技能列表为 null 时默认全部启用，空列表表示全部停用。Run 记录启用项、内容版本与快照摘要；`skill_read` 表示返回了内容，不证明模型遵守了全部说明。

## 工具与执行边界

成员统一使用标准工具目录，有效操作由全局模式、当前任务与步骤角色、会话操作授权及适配器实际能力共同决定。全局成员和空间成员表单不再配置工具数组，旧数组和空间 Grant 保留为历史兼容，不参与新执行的隐藏交集。停用、移出成员、任务修订、只读和独立审核约束继续在派发及执行前验证。权限变化推进授权版本并使旧请求/持续授权失效；旧 Attempt 不能就地扩权，预算与不可变历史保持原样。

全局保存两档权限：`workspace_autonomous`（默认）与 `full_access`。

- `workspace_autonomous`：项目目录/候选 worktree、会话 `TaskDirectory` 与本机只读语言工具链目录内自动读写、测试与命令；OS 沙箱内允许私有 `$TMPDIR` 与 `/tmp` 临时读写（屏蔽 `/tmp/ssh-*`），并允许 `run_command` / `preview_page` / 原生命令绑定并访问 `localhost:*` 本地回环（`run_test` 保持无网络隔离）；公共检索与依赖经受控代理；高敏凭据路径内核默认拒绝，显式访问时标记 `Risk="sensitive_path"` 发起只能「仅本次允许」的高危审批。显式指定项目外路径（含 `/tmp/...`）、系统安装、`git push` 和外部发布/写入在执行前按确切范围申请；批准目录后该子树内新文件可复用（三档动作层级 `read < write < execute`，批准写不放开执行），`/`、`$HOME`、`/Users`、顶层 `/tmp` 不能存为宽泛授权，但允许对 `/tmp/<子目录>` 建立目录授权。
- `full_access`：保留原生 CLI 的本机信任执行，可按任务读写本机文件、执行命令并联网。这不是沙箱隔离；单轮「仅规划」与独立审核的只读限制仍然有效。

CLI 连接配置与正常运行依赖由适配器复用，不要求用户额外登录。没有绑定目录的文件任务使用自己的持久任务目录。

审批提供「仅本次允许」「本会话持续允许」「拒绝」，对非敏感外部文件另提供显式「允许目录 `<parent>/`」选项；关闭只隐藏提示，保留请求与输入草稿。单次决定绑定完整调用身份、参数摘要和资源并持久消费，批准后只继续该次尚未执行的操作。持续授权按三档动作层级（`read < write < execute`）与物理目录子树匹配：批准某目录后，同 Thread 内合格成员对该子树中新文件的覆盖动作复用同一授权，读授权不放开写或命令，写授权不放开执行；`/`、`$HOME`、`/Users`、顶层 `/tmp` 不能存为宽泛授权（`/tmp/<子目录>` 允许）。高敏凭据路径禁建持续授权。持续授权跨刷新/重启有效；其他 Thread 不继承。撤销、切模式和会话删除会使授权失效，恢复回收站会话不复活授权。等待决定不持有数据库写事务，也不算 CLI 无响应或自动重试理由。

macOS 上的适配器按各自协议验证，具体版本与覆盖范围见验收记录；真实供应商任务单独验证。Claude 使用双向 stream-json，OpenCode 使用私有执行前插件，Gemini/Pi 使用私有原生工具 gate 与双向调用。Codex 项目内自主使用 app-server 与显式拒绝根目录的窄权限配置；当前原生审批不能表达按次外部范围，项目外操作由范围受限的宿主工具承接，不能为一次批准放开整轮权限或自动重放已发生部分效果的命令。原生及宿主命令采用实际执行约束，额外范围仅用于已批准操作；未验证的平台/协议失败关闭并报告能力缺口。Linux 构建兼容不代表命令隔离已实测。原生效果审计仍为 partial，保留无法强制的约束，不把工作目录、提示词或某条正例冒充所有操作的完整隔离。

| 工具 | 行为 |
| --- | --- |
| list_files / read_file / search_content / git_inspect | 在项目/任务范围内读取，或在批准后读取该次确切外部范围；搜索命中只作导航线索；git_inspect 只读仓库状态/差异/历史，禁用外部 diff 与 hook |
| preview_page | 从项目内入口渲染页面；CDP 只放行宿主唯一 origin，截图注册为 image 来源，不写项目或候选树 |
| web_search / fetch_url | 发现公共资料、读取原文并捕获来源；搜索摘要不算已读原文 |
| read_source / read_context / read_task | 读取已授权快照和同一协作域的任务，支持有界分页，不扩大范围 |
| publish_file | 发布真实文件快照并返回成果下载入口，不接受仅路径文字冒充交付 |
| view_image | 通过已授权原件或任务路径返回实际图片像素；宿主解码支持 PNG、JPEG、GIF，并受大小与像素预算限制 |
| run_command | 沙箱自主在项目/任务目录与 OS 沙箱约束内执行，越界或高危操作先申请确切授权；完全访问沿用信任执行；保存退出码与有界日志 |
| publish_artifact / save_claim / save_memory / save_dataset | 校验来源、生成执行披露范围和持久对象契约；accepted/supported 不自动降低资料可见性 |
| analyze_csv | 只分析已授权的不可变 CSV 原件，执行有界进程内统计并生成安全 SVG 图表与数据集版本，不启动 shell、网络或原文件读写 |
| handoff_task / send_task_message / delegate_task / yield_run | 分别处理 Run 内有界交接、持久 A2A、owned 子任务及有等待条件的执行段让出 |
| write_file / patch_file | 按任务/角色与全局模式执行，研究文件交付不要求切工程模式；检查确切路径、文件哈希、内容限制和操作授权 |
| run_test | 按任务/角色和操作范围通过支持的 OS 沙箱按校验枚举（`auto/go/npm/pnpm/yarn/pytest/cargo` × `test/typecheck/lint/build`，支持有界 `filter` 与相对 `target`）执行，仅 `kind=test` 记为行为验证；独立复核在一次性 `verify_dir` 验证副本内执行，不改写作者候选或原项目目录 |

### 原生 CLI

Web 复用本机 CLI 现有 API Key、endpoint、provider、默认模型和允许的执行配置，五家 CLI 的托管会话文件保存在各自原生目录（`~/.claude`、`~/.codex`、`~/.gemini`、`~/.pi` 与 OpenCode 原生存储）。平台不继承无关 hooks、插件或外部 MCP；权限 gate 是宿主生成的私有适配组件。当适配器证明确切 resume ACK 且模型、连接、角色、工作根、上下文及全局授权版本等指纹一致时，自动跨轮增量续接托管 session（一次性 reviewer `verify_dir` 固定使用 `fresh_only` 无痕会话）。模型错误按实际原因报告，不能用要求 CLI 登录代替配置转发诊断。

单轮「仅规划」或只读并行步骤（`Step.ReadOnly`）仅启用只读检索工具（如 Read、Glob、Grep、WebSearch、WebFetch）与宿主只读工具（如 `git_inspect`、`preview_page` 静态模式），禁用原生写与命令工具。沙箱自主与完全访问按真实适配能力启用原生文件、命令及图片工具；Cocogem 的 handoff、资料引用和成品发布继续经 scoped MCP。明确只读步骤和独立 reviewer/critic 对作者候选/源树的写隔离不会被会话持续授权绕过。

文件任务在持久任务工作目录处理输入副本和输出，无需切换其他模式。附件按原件接收，文本提取成功时直接可读；受支持的图片可通过 `view_image` 返回真正的 MCP image 内容；无法直接解析的文件可由已授权原生/宿主命令使用可用程序和库处理。每次最多 5 份附件、原件各不超过 8 MiB；交付文件各不超过 32 MiB。格式不决定能否上传或发布，解析失败不冒充已读。`publish_file` 捕获真实输出字节、文件名、类型和 SHA-256，并在成果中提供绑定确切版本的下载链接。沙箱自主或完全访问的可写最终步骤成功时，若允许发布、未委派且尚未显式交付文件，还会尝试收集 `outputs/` 直属的本轮新增或改变的文件（只读步骤不自动收集，显式交付优先调用 `publish_file`）。旧轮未改变的输出不会冒充本轮成果，失败/取消不自动发布。下载不依赖临时目录继续存在。调用内的瞬态重试不会自动重放已记录的原生命令效果；重启恢复的限制见下文，外部副作用保持部分可观察。

OpenCode 复用用户配置目录（支持 JSON/JSONC、`OPENCODE_CONFIG`、`OPENCODE_CONFIG_CONTENT` 及连接字段的环境/文件变量）、有效凭据与 `provider/model` 默认选择。Web 每步只复制连接配置和有效凭据到临时目录，不复制用户数据库、会话历史、成员提示、插件或外部 MCP。连接检查冻结实际模型、供应商与端点；`provider/model#variant` 可指定供应商支持的变体，成员思考级别按当前模型声明的 variants 动态显示，可通过 thinking_level 显式选择；选择优先于模型标识中的 #variant，不支持的值在执行前拒绝。未知模型、认证失败、截断与缺失完成结果均按失败处理。

Codex 内置的 MCP 资源助手不等于宿主工具授权。平台不提供资源读取：仅将空资源发现结果或 scoped bridge 明确返回的“不支持该资源方法”视为可继续的反馈，并记录诊断通知，让模型继续使用本步已授权工具。非空资源结果、陌生服务器、未知工具及缺少完成结果的调用仍终止执行。

CLI 原生工具库存由 CLI 强制限制，解析器再核对调用和结果配对，只有匹配的结果可捕获为来源。原生网页结果是 CLI 处理后的观察，不等同于宿主抓取的原始网页；原生网络由 CLI/供应商策略约束，不承诺宿主的 URL/DNS/SSRF 校验覆盖该路径。

「设置 → 服务」区分安装、版本、调用适配、隔离状态及 CLI/模型连接验证时间。版本只作诊断和已知不兼容拦截，关键协议与工具隔离须实际探测。每次尝试及重启恢复前重新检查程序路径、大小、修改时间和 inode；程序变化不能复用旧结论。无法确认隔离时阻止执行并保留检查点。

### 候选执行目录与会话

普通未升级的单成员对话（`thread.TaskID == ""`）直接在绑定的 `Workspace.Root` 内受沙箱约束读写，避免轻量问答与小修小补的额外 Apply 摩擦。当对话升级为持久 `Task`（含 `promote_to_task`）或派发并行 `delegate_task` 子任务时，服务通过 SQLite 租约创建独立候选目录：Git 来源使用 `git worktree add --detach`（共享源仓对象池，毫秒级）并记录基线快照提交 `base_snapshot_oid`，非 Git 来源或未提交仓库回退到有大小、文件数和敏感路径限制的副本；同步记录基线提交、树摘要、owner、lease epoch 和实际差异。派生时同步原工作区未提交的已跟踪改动与未被忽略、非敏感的未跟踪文件。同一作用域在同一源根只允许一个活跃候选；并行子任务各自持有独立候选。过期租约或原 owner 未核实停止时拒绝接管，不以 TTL 到期证明进程已退出。目录互斥不是 OS 沙箱；候选结果不会自动合并或部署。

任务/子任务候选目录在未应用前持续复用：同一任务在 Apply 或 Discard 前，后续可写轮次继续在同一 worktree 上演进。会话与任务详情的候选交付条列出未应用候选及其 `CandidateVerification`（`verified` / `unverified_mutation` / `unchanged`）和变更文件，支持展开实时统一 Diff（`GET .../candidates/{id}/diff`）；「应用到项目目录」基于 `base_snapshot_oid` 仅逐一核对受影响文件自基线起未发生外部修改或删除后原子写回（兼容 Agent 在候选目录内的 `git commit` 与互不重叠的并行子任务顺序应用），发生冲突时返回 409 并保留候选，用户可点击「导出本地分支」（`POST .../export-branch`）将其导出为 `cocogem/cand-<shortID>` 本地分支手动合并；「丢弃变更」只销毁候选，源目录字节不变。两者都需二次确认，协作运行期间禁用；应用或丢弃后下一轮写操作从最新源目录派生新候选。没有可覆盖的 diff/test 证据时一律显示为未验证变更。实际外部副作用不能仅凭目录或树摘要认定已核实。

附件与交付件位于 `$COCOGEM_DATA_DIR/io/<thread|task>/{inputs,outputs}`，与代码候选正交：上传素材和收集的成品不进入代码树，也不进入候选 diff。命令步骤以当前步骤根（作者候选或复核沙箱）为工作目录，IO 目录只作为显式交换区。

独立复核/质疑步骤在派发前从作者的确切候选树派生一次性 `verify_dir` worktree，销毁后断言作者候选摘要未变；复核成员的原生会话为 fresh-only，写入不会回流作者候选。

会话移入回收站时撤销持续授权、取消挂起审批并冻结保留未应用候选与 IO 目录，恢复后代码改动完好。永久删除、到期 Purge 和删除工作空间会回收候选 worktree、IO 目录并 `git worktree prune` 主仓元数据。存在未应用候选时修改 `Workspace.Root` 返回 409；换根提交后该空间下绑定旧根的原生会话被标记为 sealed，下一轮在新项目路径开启新会话。

宿主模型与原生 CLI 的 Task Attempt 都持久化独立 ExecutionSession，保存成员/角色/连接/执行目录/授权/上下文指纹、已暴露引用和 visibility epoch。适配器报告 `session_resume_ack=supported` 且 Run 指纹与 visibility epoch 未变化、runner 返回匹配的原生 session 身份时，才复用同一会话/任务、成员、角色、执行分支和 `work_root` 的 session：续接时通过 `session_delta/v1` 仅增量发送未确认的消息、变更的工作项与必要上游交接，不重复注入已确认的历史；引用已确认但被替换的约束明确列为 superseded。原生会话不可恢复、`RetryStep`、`Stop` 后残损、上下文溢出换新桌或 `promote_to_task` 切换工作根时，注入统一的有界 Continuity Capsule（≤1.5K tokens / ~4.5KB 交接卡，含目标、工作根、变更文件、最近工具调用、未完草稿尾段与分页读取提示；该上限只约束交接卡本身，不限制整体对话上下文）让成员接着半程工作继续而不是从头重来；续聊前若检测到会话溢出或残损，自动把旧 `ExecutionSession` 标记为 `sealed` 并以交接卡无感换新桌重试。五家 CLI 的真实会话文件保存在各自原生目录（`~/.claude`、`~/.codex`、`~/.gemini`、`~/.pi` 与 OpenCode 原生存储），宿主只传该次 MCP/规则参数，不覆盖 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 或加常规 `--ephemeral`；沙箱仅放行当前成员所属那一家 CLI 的状态目录。只有一次性 Reviewer `verify_dir` 使用无痕会话，避免已销毁目录污染原生历史列表。没有可核对的 ACK 时仍从工作记录新建，跨线程、成员或 CLI 从工作记录继续。撤销关联资料权限后旧 session 不能继续派生发布：宿主只把数据库中的会话标记为 `revoked` 并清空原生 session ID，不删除也不修改用户自己 CLI 目录中的会话文件。

### 受控工程写入与测试

`write_file` 创建或替换最多 32 KiB 的 UTF-8 文件。已有文件必须提供完整文件 `expected_sha256`；新建要求目标不存在。`patch_file` 对最多 1 MiB 的已有 UTF-8 文件执行一次精确替换：旧片段非空且恰好匹配一次，新旧片段合计最多 32 KiB，也须匹配完整文件哈希。两者按当前权限模式、任务与角色准入；项目内操作不一定逐次审批，项目外目标需获得相应的确切授权。

写入限定于执行根或已批准的确切范围；未绑定项目的文件任务以任务目录为根。工具拒绝符号链接、硬链接、敏感路径、非普通文件、非 UTF-8、过大内容和过期哈希。重复提交相同修改只在能证明已应用时幂等返回。成功写入生成实际 unified diff 来源；进程内写入与证据读取共享锁，但不提供针对外部编辑器并发写入的完整 compare-and-swap 保证。

可写步骤使用成员可用的 write_file、patch_file 和 run_test；标为 `ReadOnly` 的步骤（例如多人并行盲答或单轮「仅规划」）不提供写入与副作用命令工具。独立复核（`reviewer` / `critic`）步骤在派发前物化的一次性 `verify_dir` 验证副本中可运行测试、命令、预览页面及编写临时反例脚本，但审结销毁 `verify_dir` 后作者候选或源项目目录的 `TreeDigest` 必须保持逐字节不变。

`run_test` 不启动 shell，宿主从校验过的枚举组合固定 argv：`toolchain` 支持 `auto | go | npm | pnpm | yarn | pytest | cargo`，`kind` 为 `test | typecheck | lint | build`，`filter` 只接受 `^[A-Za-z0-9_./:-]+$`（用于 `go -run`、`pytest -k` 或包管理器脚本参数），`target` 是项目内相对目录。默认 120 秒，上限 600 秒。只有 `kind=test` 能验证行为；typecheck/lint/build 只是支持性证据并在输出里明确说明。macOS 使用 deny-default sandbox-exec，限制网络、系统路径、凭据、进程和 AppleEvents；Linux 先运行最小无害 `bwrap` 实测探针，受限 AppArmor/userns 主机报告 `linux_bwrap_userns_unavailable` 并失败关闭，不以 `LookPath` 假装沙箱已生效；其他不支持的平台同样失败关闭。

新增确定性只读 `git_inspect`：`status | diff | log | show`，宿主硬编码 `--no-ext-diff --no-textconv -c core.hooksPath=/dev/null` 并禁用外部 diff 与 hook，不联网、不写仓库；`path` 限定仓库内相对路径，`revision` 限定分支/标签/提交，日志有上限。供只读步骤与「仅规划」核对实际变更与历史。

新增 `preview_page`：不接受 URL 或端口，只接受项目内相对入口（`mode=static` 由宿主在 `127.0.0.1:0` 起只读静态服务，仅暴露入口所在子树）或精确预览 argv（`mode=command` 在宿主分配的随机回环端口以独立进程组启动，退出时整组回收）。无头 Chromium 的 CDP 请求拦截器只放行本次唯一 origin 与 `data:/blob:`，其他本机端口、管理端口和公网请求一律中止；截图以 `Source{Kind:"image"}` 注册并返回 `console_errors` 与 AXTree 摘要，项目与候选 worktree 不新增文件、不改 `TreeDigest`。没有可用浏览器内核时返回 `browser_engine_unavailable`，不声称已渲染。只读轮次只能使用 `static` 模式。

候选 diff 增加非阻塞静态提示：单文件净增 ≥3 层兜底控制流分支（连续 `else if`、空值回退或吞错分支）时，在写入观测与候选 verdict 中附加提示，引导检查根因与状态契约；它不改变 `verified` 判定。

测试本身仍能改写允许的工程路径。复核结论引用来源时，文件、diff 与测试记录必须匹配本次 Run 的实际捕获；证据缺失或已过期时只能标记 insufficient_evidence，不能声称变更已验证。

## 来源、上下文与交付

来源保存捕获内容、类型、标识、时间、完整性及截断信息。文件行号、网页正文、原生工具观察、diff 与测试记录各自保留来源性质。搜索结果和未读取的 URL 仅为线索，不能提升成已核实结论；没有公开搜索或原文时明确说明限制。

每个步骤只读取派发时冻结的可见范围，包括必要的共享历史和确切上游产物。未提交内容、失败消息正文、其他会话和未授权兄弟步骤的正文不能进入证据；最近失败轮次中已成功提交的回复仍可作为共享历史上下文，但不自动升级为交付或已验证结论。长消息、来源和产物支持基于确切引用的分页，模型输入预算不截断已保存的原始正文。最近失败、取消或中断的状态可作为诊断上下文，但不是研究依据。

ContextManifest 保存任务版本、scope digest、渲染 digest、真实宿主输入字节数及 inline/reference 条目数，并对相同政策、范围和渲染内容生成稳定复用键；这些值描述可复用条件和实际测量，不代表供应商缓存命中或模型已理解。当前没有基于真实对照任务集的后台摘要质量/成本结论，不默认宣称压缩节省费用。

### 资料、研究与披露

CSV 以内容寻址原件保存，解析最多 5000 行和 32 KiB/单元格，支持行列定位；本地 CSV 读取和附件上传各有 8 MiB 的入口限制。`analyze_csv` 对已捕获原件另设 32 MiB 的分析上限，统计有限数值的计数、缺失、非法、最小/最大/求和/均值，图表最多绘制前 100 个数值；统计覆盖所有数据行，图表不是全量散点。数据集 manifest 记录来源、schema、处理步骤和 digest，新版本不覆盖旧结果。SVG 由前端白名单重建，不直接注入原始 SVG/HTML。

文本 PDF 当前只支持恰好一页、非加密、无对象流且能提取文字的文件，保留原件和 `page:1` 定位。其他 PDF、扫描件/OCR 和复杂版式明确报告未支持，不能把空解析当作已读。

DOCX/XLSX/PPTX 通过统一的 OOXML 容器解析正文、表格单元格、幻灯片文本和共享字符串，保留原件并记录 `paragraph`/`sheet`/`slide` 定位；图片、图表、批注、修订痕迹和嵌入对象不进入正文。旧版 `.doc`、RTF、ODT 由本机 `textutil` 或 `pandoc` 转换，转换器不可用或转换失败时返回具体原因；旧版 `.xls/.ppt` 不支持。所有提取都有解压和文本预算，解析失败的原件仍可下载；仅尚未进入任务证据链的上传资料可以单独删除。不能把空解析或二进制原文当作已读证据。

Claim、MemoryRecord、ProjectRecord、DatasetManifest、Artifact 与 A2A 正文继承显式证据和生成 Attempt 的全部可证明暴露范围。没有 refs 的改写不是“干净房间”证明；私密派生资料跨 Task、跨协作域或跨角色发布会被拒绝。`handled` 回执只表示有关联回答或处置，不是 Task completed；跨独立根任务的答疑创建请求方预算下的内部 consultation，不重开原任务。

成功 Run 在同一事务中记录最终消息 ID 和确切 `产物ID@版本号`。会话的正式产物列表以该交付记录为准，不按最后时间戳或最新版本猜测。中间草稿保留为可追溯历史；旧记录没有 Delivery 时不推断、不回填，保留原有终态产物可见性。

产物类型包括 note、research_report、data_chart。发现需要相应来源、状态和限制；人工反馈独立保存，不改模型原始正文。界面可下载所选确切版本的 Markdown 报告，以及该版本实际交付的文件；版本数据也可通过接口查询。

## 状态、长任务与恢复

Run 可处于 queued、running、canceling、succeeded、failed、canceled、interrupted，以及新 Task 执行段使用的 yielded。yielded 保存 continuation、等待谓词和已知 effect 状态后释放执行约束，不是成功交付；唤醒创建关联 `continued_from_run_id` 的新 Run（例如问题回答或 `delegate_task` 子任务结算触发的 `delegation` 唤醒事件）。等待登记与当前事实原子核对，事件先到可补配，重复事件、旧 wait generation 和旧 lease 不能推进新任务，重启会扫描未决条件。桌面服务关闭时不执行唤醒，定时 Schedule 尚未提供。

当前使用有界并发调度处理独立任务的 Run，默认服务最多同时执行 4 个，可用 `COCOGEM_MAX_PARALLEL_RUNS` 调整为 1–16；同一 Task、同一 Thread 各最多一个活跃 Run，独立任务和 Run 内独立步骤可并行。默认不设 Run 或步骤累计时长上限，不保证供应商 token、费用和存储有硬上限；可以通过环境变量启用期限。原生 CLI 默认等待首个有效响应 10 分钟：到一半先提示，到期限仍无响应则中断该步骤。取得首响应后，默认无有效进展 15 分钟时按 `COCOGEM_STALL_ACTION` 处理：`warn` 只报告，`stop` 才停止停滞步骤。0 关闭对应检测，非法或负数配置拒绝启动。

「设置 → 协作」统一配置未来根任务的默认预算：自动续办 20 次、并行分支 4、写分支 2、同问题修复 3 轮、连续无进展失败 2 次；工作空间不再覆盖，任务页没有预算编辑。每个根任务分别累计，其 owned descendants、修订、续办、重试和 consultation 共享所属账户。已有根账户的 policy、用量和预留不因全局修改或模式切换清零，也不因提高未来默认值自动解锁。持久 reservation、并发准入和有限修复继续生效。当前账本覆盖 Run、Run 内 Step 和 owned 子 Task；独立后台作业及逃逸后代没有可靠持久计数，不宣称完整并发、副作用审计或硬 token/美元上限。

网络、限流和供应商暂态错误最多自动重试 3 次，即最多 4 次尝试，使用有上限的退避；认证、未知错误、用户取消、期限、结果不确定或已提交交接不能盲目重放。失败尝试和重试原因独立持久化。

服务停止或异常退出后，先核对旧执行租约和进程归属，只处理本平台记录且身份匹配的进程。已完成步骤不重跑；进程归属或停止状态无法核实时保留中断并要求人工处理。若进程已退出或已确认终止，但结果尚未提交，当前恢复逻辑仍可能将未完成步骤重新排队，不能保证已发生而未记录的原生副作用不会再次发生。用户取消的协作不会自动复活。

显式「继续执行」会重新验证 CLI 程序、模型/连接、目录绑定和权限。模型、供应商或服务地址变化时保留检查点并要求新 Run；恢复是新的执行尝试，不等于恢复用户原生交互 session。失败的子任务仍可将缺口回传协调者，整轮保留真实失败状态。

成员回复失败或执行停止后，失败回复旁直接显示「重试 成员名」；输入框上方同时显示本轮失败成员的同一入口，每个用户轮次只提示一次，不持久记录弹出状态。界面不再提供「重试此轮」。手动重试只补跑选中的失败步骤，以及原计划中因它阻塞、尚未执行且依赖已满足的后续步骤。已成功成员不重跑，上游消息与产物用确切版本引用复用；其他独立失败成员仍可分别重试，后续流程可使用这些已成功补跑的结果。独立观点重试不会把同轮兄弟回复当作共享历史注入。

每次成员重试创建新的 queued Run，以 `retry_of_run_id` 和 `retry_of_step_id` 关联原记录；原 Run、步骤和尝试保持不变，不重复用户消息。受理重试时丢弃该步骤尚未完成的旧回复，按原步骤位置展示补跑产生的新回复，不追加重复消息；已完成同伴回复保持不变。新的执行沿用原任务版本与根预算，并核对当前成员、权限、目录、CLI 连接及旧进程状态。同一任务已建立未应用候选目录时，重试继续在同一 worktree 上演进，保留作者半程成果而不是另复制一份；候选目录已变化、来源越界或进程未核实时拒绝重放。部分成员补跑成功只表示其结果已交付，不等于原流程或 Task 已验收。

成员重试使用稳定 `Idempotency-Key`，重复请求或旧按钮再次触发返回该失败步骤已接受的重试，即使它已经完成也不重复执行；再次失败时重试新的失败步骤。关闭浮层保留草稿，失败回复旁的成员重试入口仍可用。旧版不带 `step_id` 的 retry API 保留整轮重建兼容，界面不再调用它。

Gemini 的顶层和嵌套错误均按实际协议读取，非终止警告会继续等待最终结果；终止失败保留已报告的用量，不因已有流式文字就视为成功。模型 SSE 流中的心跳注释会被跳过，流内明确的上游服务、额度或认证错误按安全类别报告，不展示上游原始内容；兼容处理不更改用户现有的 CLI 模型、服务地址或凭据。空、截断或无效响应显示对应说明；CLI 未提供底层详情时明确说明无法确定具体原因，不把它猜成认证失败。只读受限与沙箱自主路径的已安装 Gemini CLI 使用本地协议夹具验证，真实上游汇总也在隔离的数据副本上验证；这不代表所有上游或平台均已验证。

后续追问会带上会话内最近一轮已提交消息；即使该轮最终失败或中断，成员先前已完成并提交的回复仍作为共享历史进入上下文，失败、未完成或其他会话的正文不会进入。完整轮次优先于零散片段，四人讨论在常规长度内可整轮保留；更早的完整成功轮次在有界预算内继续保留，超长内容通过确切 ID 分页读取。

共享历史默认上限为 128 条消息 / 64,000 估算 tokens；成员显式设置 `context_size` 时，其历史预算按该输入 token 预算的 60% 缩放，其余留给当前任务、角色指令、上游交接、来源指针和工具定义。成员未设置 `context_size` 时使用服务默认值，可通过 `COCOGEM_HISTORY_MESSAGES` 和 `COCOGEM_HISTORY_TOKENS` 调整。token 数使用保守估算（ASCII 约 4 字节/token，非 ASCII 字符按 1 token/字符），不保证与供应商 tokenizer 完全一致；单条消息预览默认约 4K tokens，大上下文成员最高约 32K tokens，超出部分仍可通过 `read_context` 读取完整正文。

## 配置与启动

开发需要 Go 1.26 系列且至少 1.26.10、Node.js 22.12+ 和 npm，建议 Node.js 24 LTS。构建后的 Web 服务无需 Node.js；CLI 执行仍依赖本机可执行程序。

```sh
make setup
make dev                 # 前端 127.0.0.1:5173，代理本地服务
make build
./dist/cocogem-server     # 默认 127.0.0.1:8741
```

服务参数：

| 参数 | 默认与用途 |
| --- | --- |
| --listen | 127.0.0.1:8741，只接受回环 IP |
| --web-dir | 优先可执行文件同目录的 web/，否则使用 web/dist |
| --allow-root | 可重复；限制可绑定目录及其子目录 |

环境变量必须在启动时传入，程序不自动加载 `.env`；示例见 [`.env.example`](../.env.example)。

| 变量 | 默认与用途 |
| --- | --- |
| COCOGEM_DATA_DIR | os.UserConfigDir()/cocogem，保存 SQLite 与本地访问密码派生值 |
| COCOGEM_SEARCH_PROVIDER | auto；可选 brave、bing、duckduckgo、public、off |
| BRAVE_SEARCH_API_KEY | 可选，仅用于 Brave 在线搜索，无关模型连接 |
| COCOGEM_EXTERNAL_EGRESS_HOSTS | 默认未配置；逗号分隔的精确 host 或 host:port，启用宿主外部 HTTP 写入入口；权限与重定向限制见下文 |
| COCOGEM_WEB_PROXY | 默认直连；env 使用代理环境变量，system 读取 macOS 系统代理，也可指定 HTTP/HTTPS/SOCKS5 地址 |
| COCOGEM_RUN_TIMEOUT / COCOGEM_STEP_TIMEOUT | 0，关闭累计期限；支持 Go duration，如 2h |
| COCOGEM_MAX_PARALLEL_RUNS | 4；同时执行的独立 Run 数，范围 1–16；同一 Task 和 Thread 仍各自串行 |
| COCOGEM_HISTORY_MESSAGES | 128；默认共享历史消息条数，范围 1–1000 |
| COCOGEM_HISTORY_TOKENS | 64000；默认共享历史估算 token 预算，范围 1024–2000000 |
| COCOGEM_FIRST_RESPONSE_TIMEOUT | 10m；0 关闭首响应检测 |
| COCOGEM_STALL_TIMEOUT | 15m；0 关闭无进展检测 |
| COCOGEM_STALL_ACTION | warn；stop 才停止停滞执行 |

auto 优先使用已配置的 Brave，否则回退公共搜索（Bing RSS，再到 DuckDuckGo HTML）；搜索失败明确报告。`make dev` 在未设置代理变量时选择 system，显式空值表示直连。系统代理只读取 host/port，不处理 PAC、订阅或代理凭据；启用原生联网的 CLI 子进程可接收已解析代理，loopback MCP 保持直连并保留原 NO_PROXY。

配置 `COCOGEM_EXTERNAL_EGRESS_HOSTS` 后，宿主可提供外部发布、部署、发布版本或安装的 HTTP 写操作；沙箱自主模式仍按操作申请授权，完全访问在任务允许时可直接准入。当前实现只在首次请求前检查 HTTPS 和目标名单，默认 HTTP 客户端可能跟随重定向，后续目标未重新检查名单；不要将其视为对整个重定向链的范围保证。完全访问下的原生联网不受此宿主入口约束。真实公开发布与部署尚未验证。

### 本地访问与数据管理

网页使用首次初始化的密码，长度 12–128 字符。随机盐与 PBKDF2-HMAC-SHA256（600,000 次迭代）的派生值写入私有 auth.json，不保存明文。会话使用 HttpOnly、SameSite=Strict cookie，24 小时或服务重启后失效；变更请求检查 CSRF、Host 与 Origin，连续 5 次密码错误暂停 1 分钟。「锁定工作空间」撤销当前浏览器会话，后台协作继续。

数据目录权限为 0700，auth.json 为 0600。停止服务后整体备份数据目录，恢复前也先停止服务；不要遗漏 SQLite WAL 或密码文件。忘记密码时，停止服务并将 auth.json 移到安全备份位置，再启动重新初始化；数据库保留，网页不提供免密码重置。

本地存储的消息、捕获来源和工程内容可能敏感。模型服务会收到执行所需问题与片段，搜索服务会收到查询；只处理允许分享的数据。完整威胁边界与漏洞报告方式见 [SECURITY.md](../SECURITY.md)。

### HTTP 与生成契约

完整接口以 [`api/openapi.yaml`](../api/openapi.yaml) 为准，前端类型为 [`web/src/api/schema.ts`](../web/src/api/schema.ts)，由 `make contract` 生成，不手改。认证入口为 `/auth/status`、`/auth/setup`、`/auth/login`；其余接口位于 `/api/v1`：

| 分组 | 主要接口 |
| --- | --- |
| 服务与配置 | system、system/verify、system/model-options、directories、settings、auth/logout |
| 空间与成员 | workspaces、agents、workspaces/{id}/members/{agentID} |
| 会话与清理 | threads/{id}、trash、threads/{id}/restore、threads/{id}/permanent |
| 项目与任务 | tasks（全局任务清单）、workspaces/{id}/overview、workspaces/{id}/tasks、tasks/{id}、tasks/{id}/start、deliveries（无来源的确切交付投影）、revisions、dependencies、completions、actions、records |
| 补充与问题 | tasks/{id}/inbox、tasks/{id}/questions、questions/{questionID}/answers |
| 预算与授权 | settings（全局执行权限与未来根预算）、tasks/{id}/budget（内部账本）、threads/{id}/permission-requests、permission-requests/{id}/decisions、threads/{id}/permission-grants、permission-grants/{id}/revoke；旧空间授权/预算写接口退役 |
| A2A 与唤醒 | tasks/{id}/messages、collaboration-messages/{id}、delegations、handoffs、wakeups、wake-events |
| 资料与记忆 | tasks/{id}/claims、datasets、workspaces/{id}/memories、executions/{id}、effects/{id} |
| 路由与运行 | threads/{id}/runs、runs/{id}、context、cancel、resume、retry |
| 候选目录 | threads/{id}/candidates、candidates/{executionID}/diff、apply、discard、export-branch |
| 输出与历史 | runs/{id}/events（SSE）、event-history、messages/{messageID}/content |
| 来源与产物 | sources/{id}、threads/{id}/artifacts、artifacts/{id}/versions/{version} 及 export |

配置修改使用 revision/If-Match 防止过期覆盖，提交与交接有稳定幂等标识。提交结果因断网而未确认时，页面保留原请求与重试入口；重试复用原幂等键，不新建重复 Run。SSE 使用持久事件序号重放，刷新、断线和较晚快照不得丢失较新消息或把终态回退为执行中。API、OpenAPI、生成类型、fixtures 和行为测试必须同步。

| make check-contract | 重新生成 OpenAPI 和前端类型，并检查两文件相对 Git HEAD 是否有差异；未提交的预期改动也会导致失败 |
| make build | 前端生产包及 Web 服务可执行文件 |
| make e2e | 构建、正式服务 HTTP smoke、持久化/备份恢复及隔离浏览器流程 |

首次浏览器测试在 web/ 下执行 `npx playwright install chromium`，或用 `PLAYWRIGHT_CHANNEL=chrome make e2e`。浏览器 fixture 服务仅测试启动，不作为产品运行模式。

验收应覆盖以下行为：

- Web 密码与 CLI 凭据独立，既有模型连接配置正确转发，安装与真实连接状态明确区分。
- 全局成员跨空间复用、授权取交集、稳定 ID、运行快照和历史不被编辑改写。
- 路由歧义不误派发；明确收件人直接执行，未指定时交给会话协调者；跨成员协作用只经受控 MCP 的 `handoff_task` 派发，`@` 文本本身不派发工作。
- 研究和工程复核读取确切上游成果，分歧与证据缺口进入最终产物，草稿不冒充交付。
- 工程协作按成员授权写入与测试，路径/哈希/内容限制、独立复测和工程树证据成立；未获写权限时绝不升级。
- 停止、暂态重试、失败重跑、并行会话、重启、显式恢复、权限撤销和不确定进程应保留真实状态；重点验证不重复交接、不复活已取消任务，以及上述重启时未知副作用的缺口。
- 成员重试只执行选中的失败步骤与可继续的后续工作，在原用户轮次内原位替换未完成回复，保留成功同伴、上游引用和候选目录；多个失败成员、请求去重、独立输入隔离及根预算不重置通过行为测试。
- 长正文完整保存并有界读取，SSE 重放与快照合并正确，回收站恢复/过期清理及数据备份有效。
- Enter/换行、IME、`@` 成员补全、移动端、主题、键盘焦点和可访问性保持兼容；会话提示位于输入框上方，右上角圆形关闭按钮保留草稿且不触发执行。
- 简单问答无任务、原会话升级、任务派生会话、开始请求去重、历史迁移和确切会话交付验收通过行为测试；任务/会话导航、高亮、筛选恢复、文件交付和移动端布局通过浏览器合成旅程。
