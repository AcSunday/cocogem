## 定位与范围

Cocogem 是面向本地单用户的多 Agent 协作项目空间。它调用本机已可用的 Claude Code、Codex、Gemini、Pi 或 OpenCode，让成员围绕持久目标讨论、研究、分析数据或执行受控开发，并保存任务版本、消息、来源、协作回执、验收记录和交付物。

产品以项目、任务和成果为中心：默认展示问题、成员回复及最终成果，执行过程按需展开。用户选择成员与任务目标；平台负责身份、权限交集、有限计划、来源引用、根任务预算及状态恢复，不按 CLI 品牌推定成员能力。

当前不提供多人账户、公网托管、任意扩展或跨项目自动共享。网页是唯一产品界面，但不接管用户已有的原生 CLI 交互会话。内置资料提取不提供登录网页抓取、OCR 或音视频解析：支持 UTF-8 与带 BOM 的 UTF-16 文本/源码、CSV/TSV、HTML、受限单页文本 PDF，以及 DOCX/XLSX/PPTX 原生解析；旧版 `.doc`、RTF、ODT 在本机存在 `textutil` 或 `pandoc` 时转换，否则明确拒绝，旧版 `.xls/.ppt` 明确报告未支持。已获授权的成员可尝试调用本机程序处理其他格式，实际能力取决于安装、权限和任务，不能将其当作内置解析或已验证能力。加密文档、图片文字和复杂版式不会因提取失败而被假装成已读。跨 adapter×OS 的通用原生 shell 隔离、自动集成/部署和定时 Schedule 尚未形成已验证执行闭环；显式 `full_access` 的本机原生命令不等同于已隔离或可完整审计，不按已有持久唤醒能力宣称自动 Schedule 已交付。

## 核心对象

| 对象 | 含义 |
| --- | --- |
| 工作空间 Workspace | 项目边界，包含会话、成员关联、共享技能及可选本地资料/工程目录；权限与协作预算默认值由全局统一配置 |
| 任务 Task / 任务版本 TaskRevision | 跨 Run 的工作身份，以及不可变的目标、范围、验收和允许动作版本；可先保存，首次执行时绑定主会话 |
| 项目记录 ProjectRecord / 记忆 MemoryRecord | 有来源、可见性和不可变版本的有效约束、决定或派生经验 |
| 成员 Agent | 可复用的全局档案，含稳定 ID、名称、handle、职责、能力、CLI、模型和执行选项；旧工具数组仅作历史兼容 |
| 空间成员 WorkspaceMember | 将全局成员加入空间，管理启用状态；不提供独立工具权限 |
| 会话 Thread | 保存参与者、协调者和有序历史，名册最多 10 人；自由协作初始收件人最多 4 人，讨论为 2–4 人；内部任务线程默认不进侧栏 |
| 协作 Run | 一次用户提交或自动续办，冻结成员配置、技能版本、授权和执行策略；关联任务时另冻结目标版本 |
| 步骤 Step / 尝试 Attempt | 步骤保存职责与依赖；每次执行尝试保存 CLI、连接、进程、会话、上下文及恢复信息 |
| 执行 WorkspaceExecution / 会话 ExecutionSession | 候选目录、基线和租约，以及一次性执行会话的指纹、披露范围和撤销版本 |
| 操作审批 / 会话授权 / 预算 BudgetAccount | 执行前的单次或同会话共享授权及撤销版本；每个根任务与其 owned descendants 共用各自的累计预算账本 |
| 验收 CompletionRecord / 副作用 EffectRecord | 绑定任务版本和证据的逐项验收，以及受管理效果的实际/不确定结果 |
| A2A 消息 / 投递回执 | 不可变任务间消息及逐目标 queued/presented/handled 等观察，不等同于验收完成 |
| 等待 Wakeup / 补充 Inbox / 问题 Question | 持久等待条件与代际、执行边界补充和绑定具体任务版本的问题 |
| 消息 Message | 用户输入与成员输出；长正文独立持久化，页面按需分页 |
| 来源 Source / 数据 DatasetManifest | 已捕获的原件、网页、文件、原生观察、diff、测试或分析证据及其数据集版本 |
| 产物 Artifact / 交付 Delivery | 不可覆盖的产物版本，以及成功 Run 明确交付的消息和版本引用；包含研究图表等类型 |

全局成员可用于多个空间，移除空间关系或删除空间不删除全局档案。成员使用稳定 ID，不因同名合并；历史消息、产物、任务版本和 Run 快照不随配置编辑重写。成员管理为每个档案提供图标删除入口并在删除前确认；删除会移除全局档案及所有空间关系，清理默认协调者、流程指派和相关会话名单，但历史消息、Run 快照与已完成任务记录保持可读。Run 执行成功只说明交付成立；Task 仍需当前必需验收全部满足才能完成，报告反馈不自动等同于任务验收。

## 首次使用与日常操作

1. 启动服务，首次打开网页时设置并确认本地访问密码；之后使用该密码解锁。
2. 直接输入目标。首次输入会在同一事务中创建默认「未命名项目」、会话和可编辑的默认成员档案；不要求先完成成员或项目向导。已有全局成员会复用，不从旧 Run 回填任务或验收。选择附件只把文件保留在输入区草稿中，不创建会话或上传原件；首次发送时才创建会话、上传所选资料并提交执行。
3. 一个可用 CLI 时沿用该 CLI 的 provider、endpoint、模型与凭据并建立默认成员；检测到多个 CLI 时仍给出可直接使用的默认协调者和其他默认档案，成员配置保持可选。没有可用 CLI 时保留输入草稿并显示安装/连接诊断。
4. 研究目标不需要工程目录；第一次工程任务就地选择目录。首次初始化及旧模型的一次性迁移默认 `project_autonomous`；之后新空间沿用当前全局权限。Composer 与「设置 → 权限」同步切换三档模式，目录绑定不覆盖任务本身的只读要求。
5. 简单问答保留为普通会话；需要交付、开发验证或持续推进的目标可在原会话升级为持久 Task。也可先在任务清单保存目标，再开始执行并生成主会话。项目首页保留欢迎页和少量摘要，任务页支持清单、看板、搜索及项目/负责人/状态筛选；清单默认按需要你、进行中、待推进和待验收组织，每行显示当前动作、下一步与验收进度。阅读流式回复、来源、执行过程及最终交付物；可停止协作、补充问题或记录人工验收。

成员创建与编辑不依赖当前是否存在空间，新档案不会自动加入空间。「设置 → 协作」保存默认协调者和各内置流程的角色分工；显式选择优先，默认值只从当前空间已启用且有必要权限的成员中生效，不扩大成员名单和授权。互斥角色必须由不同成员承担。未显式配置的角色由协调者根据本轮名册的职责、能力和实际工具权限选择；宿主校验角色、工具和互斥关系，选择失败时才按会话顺序补齐。会话协调者只有在没有其他可用成员时才补研究或执行角色。已有会话和运行中的快照不被全局默认值改写。

成员模型为空或 `default` 时沿用本机 CLI 配置。`context_size` 是宿主输入的估算 token 预算，0 表示沿用 CLI 默认，显式值至少 1024 tokens；它只用于宿主限制，不改变 CLI 自身的上下文窗口。已有配置数值保留，但单位按估算 token 重新解释。`thinking_level` 为空沿用 CLI 配置，显式值按适配器校验：

| CLI | 可显式选择的 thinking 级别 |
| --- | --- |
| Claude | low、medium、high、xhigh、max |
| Codex | low、medium、high、xhigh、ultra、max |
| Gemini | low、high；显式设置思考级别时必须同时指定具体模型，不能使用 `default` |
| Pi | low、medium、high、xhigh、max |
| OpenCode | 从当前模型的原生 variants 动态读取；留空沿用本机或 `provider/model#variant` 配置 |

头像支持本地 PNG/JPEG 上传：最多 512 KiB、单边不超过 2048 像素，检查 MIME、尺寸和完整解码。拒绝远程 URL、SVG 和非法图像；旧内置图案可继续显示与清空，新档案只使用上传图像或默认头像。头像不进入模型提示。

目录可通过浏览器逐层选择，也可输入绝对路径或 `~/` 路径；保存前校验并记录真实绝对路径。取消选择不改原绑定。`--allow-root` 可重复指定，限制可浏览和绑定的范围；未指定时由已解锁的本机用户选择目录。敏感目录、符号链接逃逸和不可读路径被拒绝；活跃协作期间不能更改绑定。

### 项目首页与会话界面

项目首页保留欢迎页（场景卡片与成员提示）和桌面项目摘要，700px 及以下隐藏摘要及占位。最左侧第一个首页图标管理首页与会话，第二个图标管理全局任务清单和任务详情；打开任何执行会话都会点亮首页图标，包括从任务详情进入的会话。任务清单与任务详情隐藏工作空间会话导航，以及顶部的工作空间成员和协作入口；打开会话后恢复。高亮由当前页面确定，直接访问链接、刷新和浏览器前进后退采用相同规则。

任务清单默认使用焦点清单：先显示需要你，再按进行中、待推进、待验收排列；每行显示标题、项目、负责人、当前动作、下一步和验收进度，回答、失败、中断和运行停止进入需要你，未开始、暂停与真实等待条件进入待推进并标明下一步。可切换为看板；看板列为待办、进行中、等待处理、待验收、已验收，已取消任务存在时显示取消列。提供标题/目标搜索、项目、负责人和状态筛选，本地会话内保留筛选与视图选择；已验收任务默认从清单归档，可通过状态筛选或清单底部入口查看。支持多选后永久删除，删除前必须确认；删除会一并移除选中任务及其子任务、关联会话、执行记录、协作消息和成果。仍处于活动状态、存在未核实副作用、与其他任务共享会话，或被删除范围外任务有效依赖时拒绝删除并给出原因。运行成功仅进入待验收，不能通过拖动、手动勾选或最后消息时间伪造完成。

清单/看板切换位于任务页右上角；看板填充可用页面，各列采用状态同色系淡底并在列内滚动。卡片只显示标题、状态、负责人和按钮，正文与操作区共享整卡 hover/focus。移动端头部可换行，状态点与边线保持间距。执行停止在详情头部、属性及运行记录统一显示「已停止」；任务被取消仍显示「已取消」。

「新建任务」可保存尚无会话的待办，也可创建并开始；标题与目标独立保存。首次开始在同一事务创建主会话、绑定任务、冻结权限与上下文并提交 Run。重复创建使用稳定 request_id 去重；重复开始返回该任务既有执行，失败或结果不确定时也不会通过再次开始自动重放。成员步骤重试保留已完成工作并核对旧进程状态；服务重启后的自动恢复另有下述限制。任务详情以未回答的问题卡、只读任务说明、上次执行、交付成果和验收为主；未回答问题不折叠。状态、负责人和关联会话位于属性区。「去验收」打开独立人工验收弹窗，任务页没有内嵌「验收交付」、任务设置、手动暂停/取消/目标/预算编辑，参考来源展示及其专用请求、派生与证据选项也已移除。执行过程和来源在关联会话查看，成果文件仍提供实际版本下载。永久删除会移除任务树及其关联会话，无法恢复。可拆分子任务，各自拥有内部会话并共享根任务预算；内部会话默认不进入普通会话列表。

普通问答不再无条件建立 Task。首轮沿用当前模型调用，由协调者或该轮实际收件成员通过受控 `promote_to_task` 提交标题、目标和当前用户输入的确切未引用指令。模型判断语义，代码核对消息来源、活动会话、成员与权限，并在事务中去重、绑定 Task/TaskRevision、预算和上下文，再在同一会话的新执行步骤继续。简单解释、一次检索、假设和否定请求保持问答；消息长度、工具调用次数、成员提及和工作流选择本身都不触发任务。意图不明时继续讨论；无活跃执行的普通会话提供「转为任务」入口。任务建立前使用只读问答工具，不提前开放原生命令，也不因全局项目内自主误触发额外审批。升级不扩张任务目标和语义只读范围，旧成员工具数组不再作为新执行的隐藏权限。

升级保留原会话身份和所有历史，之前的普通问答 Run 不回填任务身份。围绕既有任务继续执行时沿用当前目标版本；已接受的会话目标补充形成新修订，单纯追问不覆盖目标。人工验收可选择确切交付产物版本或属于当前任务成功 Run 的最终 Delivery 回复；未交付草稿、失败/中断回复、其他任务和升级前普通问答不能作为候选。弹窗冻结目标修订、评估版本、条件和候选；目标变更后要求重新核对，保存中不能关闭重投。宿主校验 Task 归属和确切 Delivery 并计算正文摘要，人工判断明确标为 human_confirmed。旧 Task、成员 ID、不可变目标/完成记录、正文与累计预算保持原样，旧来源证据仍可读。

权限由全局统一保存，输入框底部模式选择与「设置 → 权限」同步，切换空间不改变选择；编辑工作空间和空间成员模态框不再提供权限或预算。权限页可查看、撤销当前会话持续授权。「设置 → 协作」管理全局预算默认值。设置采用字段合并和版本校验，保存预算不会覆盖权限；权限收紧阻止新准入并核实受影响执行，无法确认停止时报告未核实状态，历史快照和预算不重置。

侧栏提供空间切换、新建会话、标题搜索和会话菜单；菜单支持重命名及工作空间操作。删除会话无需二次确认，会立即移入回收站。各成员的工具执行活动位于其回复旁，默认折叠，按需查看真实工具、目标、耗时、退出码和有界输出；同一调用的授权等待与最终结果不会重复计数。待授权操作始终位于折叠区外。右侧协作面板保留来源与产物，移除「过程」页签。

输入区 Enter 发送、Shift+Enter 换行；输入法确认不会误发送，`@` 支持键盘补全成员，`/` 支持键盘补全协作模式。常态桌面 placeholder 为「一起构建什么？（Enter 发送 · Shift + Enter 换行）」，900px 及以下只显示「一起构建什么？」。右上角透明提示图标在悬停、聚焦或触屏点击时说明两种触发方式，浮层避免视口裁切；补全和弹窗关闭不覆盖后到的编辑或光标位置。不选模式时由协调者判断；显式选择显示紧凑、可关闭的标签，清除后交回协调者。自由协作不提供自动指派开关或数据共享确认门禁；助手正文中的 `@` 不会触发派发。

会话操作报错、路由澄清和权限模式切换失败显示在输入框上方的浮层中，右上角提供圆形关闭按钮。关闭提示保留草稿并将焦点返回输入框，不发送消息、不更改权限，也不重试执行；新的请求仍可显示新的提示。任务清单和任务详情没有输入框，操作错误仍在页面中显示。

最左侧窄栏固定提供齿轮设置入口；外观在「设置 → 外观」中切换浅色、深色、暖色或跟随系统，保存为本机偏好。页面支持移动端、键盘操作、焦点反馈及减少动态效果。消息可查看原文和模型信息，长内容分页，报告可打开阅读并导出。

### 回收站与清理

会话先软删除，保留身份及完整历史，可在保留期内恢复。侧栏删除会话直接移入回收站，不再二次确认；回收站顶部可调整保留周期，支持多选、全选后批量恢复或永久删除，永久删除前仍需确认。默认保留 7 天，可在全局设置中调整为 1–3650 天；到期由维护任务清理，也可显式永久删除。永久删除不可恢复。

正在运行或仍有待核实归属进程的会话不能删除；删除空间也受活跃协作及进程检查约束。永久删除会清理对应运行、消息、来源、产物、事件和正文，保留独立的全局成员档案。

## 协作方式

### 自由协作

用户可显式 `@` 一个或多个成员，或用 `/` 选择协作模式，或通过自然语言描述任务与分工。当前正文中的明确收件人与分工优先于 `/` 已选流程及默认角色：单纯点名时，本轮按自由协作交给点名成员；自然语言明确指定方法与角色时，按该指派执行，不要求先切换流程或移除成员。正文没有新指派时沿用所选 workflow 和默认分工。一次覆盖不改写会话默认流程或历史已接受计划，也不扩大授权；否定、条件和无效成员仍需澄清或报告错误。路由预览和提交绑定同一任务及配置，配置过期时重新确认实际计划。

未指定流程和收件人时，协调者在任务计划步骤内决定方法，无需额外分类调用：可以直接回答，通过受控交接自由分工，或调用一次 `choose_workflow` 选择协作讨论、Research 或只读工程协作。选择只能使用本轮名册中的成员，并校验角色和工具；不能改写用户显式流程、已接受计划或已提交交接，不能自行取得写入权限。

实际方法、选人原因和计划保存在 Run，界面读取持久记录，不按最新回复猜测。全局设置仅提供内置流程的角色默认值，不为自由协作增加手动自动分工控件。

### 内置流程

| 方式 | 执行顺序与交付 |
| --- | --- |
| 协作讨论 | 2–4 人独立观点 → 逐人交叉质疑 → 汇总草稿 → 每位成员检查是否准确表达其修正后的观点 → 协调者交付唯一 note |
| Research | 研究 → 独立质疑 → 研究员逐项回应 → 质疑者复查并保留未决项 → 协调者交付唯一 research_report |
| 工程协作 | 执行 → 独立复核 → 执行回应 → 最终复核者交付唯一 engineering_report；成员按已获授权的能力读取、修改或测试，未获写权限时保持只读 |

输入区只保留一个协作模式入口：`/` 命令。工程协作不再区分分析或开发。用户在输入区显式选择工程协作时，成员可按任务、角色和实际授权使用写入/测试工具；协调者自行选择的工程方法强制只读，不开放写入或测试。自由协作中的文件任务仍可按其自身授权执行，不要求切换工程模式。独立复核和最终工程报告始终保留。旧 `code_analysis` 工作方式保持只读兼容；历史计划继续可恢复。

内置流程的角色先采用用户显式指派和全局默认分工；仍有空缺时，协调者根据本轮名册中的职责、能力、实际工具权限和当前任务选择成员。宿主校验成员是否在本轮名册、角色是否互斥、是否具备该角色所需工具；选择失败或模型不可用时才按会话顺序补齐。协调者只有在没有其他可用成员时才补研究或执行角色，不能优先占用执行身份。

研究员和质疑者、分析员/开发者和复核者不能是同一成员。汇总必须保留真实分歧，不把投票、确认或成员一致当成外部证据。中间草稿和步骤回复不发布正式报告；只有指定的最终步骤承担发布义务。

### 成员交接与共享技能

自由协作使用现有的 scoped MCP bridge，不解析助手正文派发任务：

| 工具 | 契约 |
| --- | --- |
| handoff_task | 提交当前 Run 内的任务，使用真实目标成员 ID、职责、目标与确切上下文引用 |
| get_task | 查询当前 Run 中任务自己的持久状态及后续回传结果 |
| read_skill | 按需读取当前 Run 启用的共享技能和允许的参考文件 |
| read_context / read_source | 分页读取当前步骤已获授权的确切消息、产物版本和捕获来源 |

`handoff_task` 使用发送步骤内稳定的 `request_id` 幂等去重，同一 ID 修改内容会被拒绝。不允许虚构成员、自我委派或跨空间派发。`context_refs` 最多 12 个，必须是完整消息 ID、来源 ID 或 `产物ID@版本号`；短 ID、步骤 ID 和越权引用被拒绝，独立复核也不能引用目标成员自己的作品作为待审对象。

平台接收任务不等于任务完成。当前 CLI 调用结束后，平台运行已提交子任务，依赖收敛后再调用发送者回传成功或失败结果。独立步骤可并行，嵌套委派会延后消费者；每轮最多 12 次交接、32 步、4 层委派。内置流程保持原计划。

共享技能唯一源为 `internal/skills/library/`，随程序嵌入。内置 task-orchestration、task-handoff、independent-review、synthesize-results、file-delivery。启动时提供 bootstrap 与索引，正文和参考文件按需读取，不安装到用户 CLI 配置目录。技能只描述运行时角色、能力及方法，不绑定具体成员、handle、CLI 或模型。

工作空间技能列表为 null 时默认全部启用，空列表表示全部停用。Run 记录启用项、内容版本与快照摘要；`skill_read` 表示返回了内容，不证明模型遵守了全部说明。

## 工具与执行边界

成员统一使用标准工具目录，有效操作由全局模式、当前任务与步骤角色、会话操作授权及适配器实际能力共同决定。全局成员和空间成员表单不再配置工具数组，旧数组和空间 Grant 保留为历史兼容，不参与新执行的隐藏交集。停用、移出成员、任务修订、只读和独立审核约束继续在派发及执行前验证。权限变化推进授权版本并使旧请求/持续授权失效；旧 Attempt 不能就地扩权，预算与不可变历史保持原样。

全局保存 `controlled / project_autonomous / full_access`。受控模式沿用标准工具及任务/角色规则，额外范围在执行前申请。项目内自主允许项目内读写、命令、测试、公共检索和项目内依赖准备；项目外文件、系统安装、发布和部署需要确切授权。完全访问保留原生 CLI 的本机信任执行。CLI 连接配置与正常运行依赖由适配器复用，不要求用户额外登录。没有绑定目录的文件任务使用自己的持久任务目录。

审批提供「仅本次允许」「本会话持续允许」「拒绝」；关闭只隐藏提示，保留请求与输入草稿。单次决定绑定完整调用身份、参数摘要和资源并持久消费，批准后只继续该次尚未执行的操作。持续授权由同一 Thread 的所有合格成员共享，仍限定工具、动作、范围和授权版本，跨刷新/重启有效；其他 Thread 不继承。撤销、切模式和会话删除会使授权失效，恢复回收站会话不复活授权。等待决定不持有数据库写事务，也不算 CLI 无响应或自动重试理由。

macOS 上的适配器按各自协议验证，具体版本与覆盖范围见验收记录；真实供应商任务单独验证。Claude 使用双向 stream-json，OpenCode 使用私有执行前插件，Gemini/Pi 使用私有原生工具 gate 与双向调用。Codex 项目内自主使用 app-server 与显式拒绝根目录的窄权限配置；当前原生审批不能表达按次外部范围，项目外操作由范围受限的宿主工具承接，不能为一次批准放开整轮权限或自动重放已发生部分效果的命令。原生及宿主命令采用实际执行约束，额外范围仅用于已批准操作；未验证的平台/协议失败关闭并报告能力缺口。Linux 构建兼容不代表命令隔离已实测。原生效果审计仍为 partial，保留无法强制的约束，不把工作目录、提示词或某条正例冒充所有操作的完整隔离。

| 工具 | 行为 |
| --- | --- |
| list_files / read_file / search_content | 在项目/任务范围内读取，或在批准后读取该次确切外部范围；搜索命中只作导航线索 |
| web_search / fetch_url | 发现公共资料、读取原文并捕获来源；搜索摘要不算已读原文 |
| read_source / read_context / read_task | 读取已授权快照和同一协作域的任务，支持有界分页，不扩大范围 |
| publish_file | 发布真实文件快照并返回成果下载入口，不接受仅路径文字冒充交付 |
| view_image | 通过已授权原件或任务路径返回实际图片像素；宿主解码支持 PNG、JPEG、GIF，并受大小与像素预算限制 |
| run_command | 项目内自主使用项目约束执行；受控或额外范围先申请确切操作，完全访问沿用信任执行；保存退出码与有界日志 |
| publish_artifact / save_claim / save_memory / save_dataset | 校验来源、生成执行披露范围和持久对象契约；accepted/supported 不自动降低资料可见性 |
| analyze_csv | 只分析已授权的不可变 CSV 原件，执行有界进程内统计并生成安全 SVG 图表与数据集版本，不启动 shell、网络或原文件读写 |
| handoff_task / send_task_message / delegate_task / yield_run | 分别处理 Run 内有界交接、持久 A2A、owned 子任务及有等待条件的执行段让出 |
| write_file / patch_file | 按任务/角色与全局模式执行，研究文件交付不要求切工程模式；检查确切路径、文件哈希、内容限制和操作授权 |
| run_test | 按任务/角色和操作范围通过支持的 OS 沙箱执行固定 Go/npm 测试命令；审核者不能调用直接写工具，但复测本身仍可能改写允许的工程路径 |

### 原生 CLI

Web 默认每个步骤使用新会话和独立配置，复用本机 CLI 现有 API Key、endpoint、provider、默认模型和允许的执行配置。平台不继承无关 hooks、插件或外部 MCP；权限 gate 是宿主生成的私有适配组件。受控执行不跨 Attempt 恢复原生会话；只有适配器证明确切 resume ACK 且模型、连接、角色、上下文及全局授权版本等指纹一致时，才复用宿主私有 session。模型错误按实际原因报告，不能用要求 CLI 登录代替配置转发诊断。

Claude 在受控模式可按有效范围启用 Read、Glob、Grep、WebSearch、WebFetch，其他工具通过可发现的执行申请路径请求。项目内自主与完全访问按真实适配能力启用原生文件、命令及图片工具；Cocogem 的 handoff、资料引用和成品发布继续经 scoped MCP。明确只读任务和独立 reviewer/critic 的写执行限制不会被会话持续授权绕过。

文件任务在持久任务工作目录处理输入副本和输出，无需切换其他模式。附件按原件接收，文本提取成功时直接可读；受支持的图片可通过 `view_image` 返回真正的 MCP image 内容；无法直接解析的文件可由已授权原生/宿主命令使用可用程序和库处理。每次最多 5 份附件、原件各不超过 8 MiB；交付文件各不超过 32 MiB。格式不决定能否上传或发布，解析失败不冒充已读。`publish_file` 捕获真实输出字节、文件名、类型和 SHA-256，并在成果中提供绑定确切版本的下载链接。项目内自主或可信完全访问的最终步骤成功时，若允许发布、未委派且尚未显式交付文件，还会尝试收集 `outputs/` 直属的本轮新增或改变的文件；受控模式需要显式调用 `publish_file`。旧轮未改变的输出不会冒充本轮成果，失败/取消不自动发布。下载不依赖临时目录继续存在。调用内的瞬态重试不会自动重放已记录的原生命令效果；重启恢复的限制见下文，外部副作用保持部分可观察。

OpenCode 复用用户配置目录（支持 JSON/JSONC、`OPENCODE_CONFIG`、`OPENCODE_CONFIG_CONTENT` 及连接字段的环境/文件变量）、有效凭据与 `provider/model` 默认选择。Web 每步只复制连接配置和有效凭据到临时目录，不复制用户数据库、会话历史、成员提示、插件或外部 MCP。连接检查冻结实际模型、供应商与端点；`provider/model#variant` 可指定供应商支持的变体，成员思考级别按当前模型声明的 variants 动态显示，可通过 thinking_level 显式选择；选择优先于模型标识中的 #variant，不支持的值在执行前拒绝。未知模型、认证失败、截断与缺失完成结果均按失败处理。

Codex 内置的 MCP 资源助手不等于宿主工具授权。平台不提供资源读取：仅将空资源发现结果或 scoped bridge 明确返回的“不支持该资源方法”视为可继续的反馈，并记录诊断通知，让模型继续使用本步已授权工具。非空资源结果、陌生服务器、未知工具及缺少完成结果的调用仍终止执行。

CLI 原生工具库存由 CLI 强制限制，解析器再核对调用和结果配对，只有匹配的结果可捕获为来源。原生网页结果是 CLI 处理后的观察，不等同于宿主抓取的原始网页；原生网络由 CLI/供应商策略约束，不承诺宿主的 URL/DNS/SSRF 校验覆盖该路径。

「设置 → 服务」区分安装、版本、调用适配、隔离状态及 CLI/模型连接验证时间。版本只作诊断和已知不兼容拦截，关键协议与工具隔离须实际探测。每次尝试及重启恢复前重新检查程序路径、大小、修改时间和 inode；程序变化不能复用旧结论。无法确认隔离时阻止执行并保留检查点。

### 候选执行目录与会话

正式服务在创建工程写分支时，可通过 SQLite 租约创建独立候选目录：Git 来源使用不共享对象硬链接的本地 clone，非 Git 来源使用有大小、文件数和敏感路径限制的副本，记录基线、树摘要、owner、lease epoch 和实际差异。过期租约或原 owner 未核实停止时拒绝接管，不以 TTL 到期证明进程已退出。目录互斥不是 OS 沙箱；候选结果不会自动合并或部署。

**当前限制：并非所有写入都会创建候选目录。** 会话提交路径仍用历史成员工具数组判断是否建立写分支，而新建成员的旧数组为空；未建立候选目录时执行根会回退到绑定的源目录。自由协作等其他可写路径也不能据此假定有候选目录。因此被授权的写入可能直接修改绑定目录；实际外部副作用也不能仅凭目录或树摘要认定已核实。

宿主模型与原生 CLI 的 Task Attempt 都持久化独立 ExecutionSession，保存成员/角色/连接/执行目录/授权/上下文指纹、已暴露引用和 visibility epoch。受控执行按 fresh-only 处理：一次性 session ID 不允许跨 Attempt resume。`full_access` 下仅当适配器报告 `session_resume_ack=supported`、Run 指纹与 visibility epoch 未变化且 runner 返回匹配的原生 session 身份时，才在 Cocogem 私有目录复用同一任务/成员/角色/执行分支的 session；没有可核对的 ACK 时仍从工作记录新建，跨线程、成员或 CLI 从工作记录继续。撤销关联资料权限后旧 session 不能继续派生发布。

### 受控工程写入与测试

`write_file` 创建或替换最多 32 KiB 的 UTF-8 文件。已有文件必须提供完整文件 `expected_sha256`；新建要求目标不存在。`patch_file` 对最多 1 MiB 的已有 UTF-8 文件执行一次精确替换：旧片段非空且恰好匹配一次，新旧片段合计最多 32 KiB，也须匹配完整文件哈希。两者按当前权限模式、任务与角色准入；项目内操作不一定逐次审批，项目外目标需获得相应的确切授权。

写入限定于执行根或已批准的确切范围；未绑定项目的文件任务以任务目录为根。工具拒绝符号链接、硬链接、敏感路径、非普通文件、非 UTF-8、过大内容和过期哈希。重复提交相同修改只在能证明已应用时幂等返回。成功写入生成实际 unified diff 来源；进程内写入与证据读取共享锁，但不提供针对外部编辑器并发写入的完整 compare-and-swap 保证。

工程协作的执行角色使用成员已获授权的 write_file、patch_file 和 run_test；复核者需要 publish_artifact，若也获 run_test 可独立复测，但不获得 write_file/patch_file。未获写权限的成员自然保持只读，不需要用户再选择分析或开发模式。

`run_test` 不启动 shell，只执行固定的 `go test -count=1 ./...` 或 `npm test`，默认 120 秒，上限 600 秒。macOS 使用 deny-default sandbox-exec，限制网络、系统路径、凭据、进程和 AppleEvents；Linux 当前明确阻止未实机验证的沙箱测试，其他不支持的平台也失败关闭。

测试本身仍能改写允许的工程路径。如果本次 Run 捕获了写入 diff，工程报告的已验证结论必须同时引用本次 Run 的最新 diff、最后写入之后退出码为 0 的测试，以及测试前后和当前一致的工程树摘要。测试改动交付树、证据缺失或已过期时，只能报告 insufficient_evidence，不能声称变更已验证；没有捕获 diff 的只读结果则按文件证据交付。

## 来源、上下文与交付

来源保存捕获内容、类型、标识、时间、完整性及截断信息。文件行号、网页正文、原生工具观察、diff 与测试记录各自保留来源性质。搜索结果和未读取的 URL 仅为线索，不能提升成已核实结论；没有公开搜索或原文时明确说明限制。

每个步骤只读取派发时冻结的可见范围，包括必要的共享历史和确切上游产物。未提交内容、失败消息正文、其他会话和未授权兄弟步骤的正文不能进入证据；最近失败轮次中已成功提交的回复仍可作为共享历史上下文，但不自动升级为交付或已验证结论。长消息、来源和产物支持基于确切引用的分页，模型输入预算不截断已保存的原始正文。最近失败、取消或中断的状态可作为诊断上下文，但不是研究依据。

ContextManifest 保存任务版本、scope digest、渲染 digest、真实宿主输入字节数及 inline/reference 条目数，并对相同政策、范围和渲染内容生成稳定复用键；这些值描述可复用条件和实际测量，不代表供应商缓存命中或模型已理解。当前没有基于真实对照任务集的后台摘要质量/成本结论，不默认宣称压缩节省费用。

### 资料、研究与披露

CSV 以内容寻址原件保存，解析最多 5000 行和 32 KiB/单元格，支持行列定位；本地 CSV 读取和附件上传各有 8 MiB 的入口限制。`analyze_csv` 对已捕获原件另设 32 MiB 的分析上限，统计有限数值的计数、缺失、非法、最小/最大/求和/均值，图表最多绘制前 100 个数值；统计覆盖所有数据行，图表不是全量散点。数据集 manifest 记录来源、schema、处理步骤和 digest，新版本不覆盖旧结果。SVG 由前端白名单重建，不直接注入原始 SVG/HTML。

文本 PDF 当前只支持恰好一页、非加密、无对象流且能提取文字的文件，保留原件和 `page:1` 定位。其他 PDF、扫描件/OCR 和复杂版式明确报告未支持，不能把空解析当作已读。

DOCX/XLSX/PPTX 通过统一的 OOXML 容器解析正文、表格单元格、幻灯片文本和共享字符串，保留原件并记录 `paragraph`/`sheet`/`slide` 定位；图片、图表、批注、修订痕迹和嵌入对象不进入正文。旧版 `.doc`、RTF、ODT 由本机 `textutil` 或 `pandoc` 转换，转换器不可用或转换失败时返回具体原因；旧版 `.xls/.ppt` 不支持。所有提取都有解压和文本预算，解析失败的原件仍可下载；仅尚未进入任务证据链的上传资料可以单独删除。不能把空解析或二进制原文当作已读证据。

Claim、MemoryRecord、ProjectRecord、DatasetManifest、Artifact 与 A2A 正文继承显式证据和生成 Attempt 的全部可证明暴露范围。没有 refs 的改写不是“干净房间”证明；私密派生资料跨 Task、跨协作域或跨角色发布会被拒绝。`handled` 回执只表示有关联回答或处置，不是 Task completed；跨独立根任务的答疑创建请求方预算下的内部 consultation，不重开原任务。

成功 Run 在同一事务中记录最终消息 ID 和确切 `产物ID@版本号`。会话的正式产物列表以该交付记录为准，不按最后时间戳或最新版本猜测。中间草稿保留为可追溯历史；旧记录没有 Delivery 时不推断、不回填，保留原有终态产物可见性。

产物类型包括 note、research_report、code_analysis、engineering_report、data_chart。发现需要相应来源、状态和限制；人工反馈独立保存，不改模型原始正文。界面可下载所选确切版本的 Markdown 报告，以及该版本实际交付的文件；版本数据也可通过接口查询。

## 状态、长任务与恢复

Run 可处于 queued、running、canceling、succeeded、failed、canceled、interrupted，以及新 Task 执行段使用的 yielded。yielded 保存 continuation、等待谓词和已知 effect 状态后释放执行约束，不是成功交付；唤醒创建关联 `continued_from_run_id` 的新 Run。等待登记与当前事实原子核对，事件先到可补配，重复事件、旧 wait generation 和旧 lease 不能推进新任务，重启会扫描未决条件。桌面服务关闭时不执行唤醒，定时 Schedule 尚未提供。

当前使用有界并发调度处理独立任务的 Run，默认服务最多同时执行 4 个，可用 `COCOGEM_MAX_PARALLEL_RUNS` 调整为 1–16；同一 Task、同一 Thread 各最多一个活跃 Run，独立任务和 Run 内独立步骤可并行。默认不设 Run 或步骤累计时长上限，不保证供应商 token、费用和存储有硬上限；可以通过环境变量启用期限。原生 CLI 默认等待首个有效响应 10 分钟：到一半先提示，到期限仍无响应则中断该步骤。取得首响应后，默认无有效进展 15 分钟时按 `COCOGEM_STALL_ACTION` 处理：`warn` 只报告，`stop` 才停止停滞步骤。0 关闭对应检测，非法或负数配置拒绝启动。

「设置 → 协作」统一配置未来根任务的默认预算：自动续办 20 次、并行分支 4、写分支 2、同问题修复 3 轮、连续无进展失败 2 次；工作空间不再覆盖，任务页没有预算编辑。每个根任务分别累计，其 owned descendants、修订、续办、重试和 consultation 共享所属账户。已有根账户的 policy、用量和预留不因全局修改或模式切换清零，也不因提高未来默认值自动解锁。持久 reservation、并发准入和有限修复继续生效。当前账本覆盖 Run、Run 内 Step 和 owned 子 Task；独立后台作业及逃逸后代没有可靠持久计数，不宣称完整并发、副作用审计或硬 token/美元上限。

网络、限流和供应商暂态错误最多自动重试 3 次，即最多 4 次尝试，使用有上限的退避；认证、未知错误、用户取消、期限、结果不确定或已提交交接不能盲目重放。失败尝试和重试原因独立持久化。

服务停止或异常退出后，先核对旧执行租约和进程归属，只处理本平台记录且身份匹配的进程。已完成步骤不重跑；进程归属或停止状态无法核实时保留中断并要求人工处理。若进程已退出或已确认终止，但结果尚未提交，当前恢复逻辑仍可能将未完成步骤重新排队，不能保证已发生而未记录的原生副作用不会再次发生。用户取消的协作不会自动复活。

显式「继续执行」会重新验证 CLI 程序、模型/连接、目录绑定和权限。模型、供应商或服务地址变化时保留检查点并要求新 Run；恢复是新的执行尝试，不等于恢复用户原生交互 session。失败的子任务仍可将缺口回传协调者，整轮保留真实失败状态。

成员回复失败或执行停止后，失败回复旁直接显示「重试 成员名」；输入框上方同时显示本轮失败成员的同一入口，每个用户轮次只提示一次，不持久记录弹出状态。界面不再提供「重试此轮」。手动重试只补跑选中的失败步骤，以及原计划中因它阻塞、尚未执行且依赖已满足的后续步骤。已成功成员不重跑，上游消息与产物用确切版本引用复用；其他独立失败成员仍可分别重试，后续流程可使用这些已成功补跑的结果。独立观点重试不会把同轮兄弟回复当作共享历史注入。

每次成员重试创建新的 queued Run，以 `retry_of_run_id` 和 `retry_of_step_id` 关联原记录；原 Run、步骤和尝试保持不变，不重复用户消息。受理重试时丢弃该步骤尚未完成的旧回复，按原步骤位置展示补跑产生的新回复，不追加重复消息；已完成同伴回复保持不变。新的执行沿用原任务版本与根预算，并核对当前成员、权限、目录、CLI 连接及旧进程状态。原 Run 已建立工程候选目录时，重试会复制已核实摘要的候选文件，保留作者成果；旧候选目录变化、来源越界或进程未核实时拒绝重放。未建立候选目录的限制见上文。部分成员补跑成功只表示其结果已交付，不等于原流程或 Task 已验收。

成员重试使用稳定 `Idempotency-Key`，重复请求或旧按钮再次触发返回该失败步骤已接受的重试，即使它已经完成也不重复执行；再次失败时重试新的失败步骤。关闭浮层保留草稿，失败回复旁的成员重试入口仍可用。旧版不带 `step_id` 的 retry API 保留整轮重建兼容，界面不再调用它。

Gemini 的顶层和嵌套错误均按实际协议读取，非终止警告会继续等待最终结果；终止失败保留已报告的用量，不因已有流式文字就视为成功。模型 SSE 流中的心跳注释会被跳过，流内明确的上游服务、额度或认证错误按安全类别报告，不展示上游原始内容；兼容处理不更改用户现有的 CLI 模型、服务地址或凭据。空、截断或无效响应显示对应说明；CLI 未提供底层详情时明确说明无法确定具体原因，不把它猜成认证失败。受控和项目自主模式的已安装 Gemini CLI 使用本地协议夹具验证，真实上游汇总也在隔离的数据副本上验证；这不代表所有上游或平台均已验证。

后续追问会带上会话内最近一轮已提交消息；即使该轮最终失败或中断，成员先前已完成并提交的回复仍作为共享历史进入上下文，失败、未完成或其他会话的正文不会进入。完整轮次优先于零散片段，四人讨论在常规长度内可整轮保留；更早的完整成功轮次在有界预算内继续保留，超长内容通过确切 ID 分页读取。

共享历史默认上限为 128 条消息 / 64,000 估算 tokens；成员显式设置 `context_size` 时，其历史预算按该输入 token 预算的 60% 缩放，其余留给当前任务、角色指令、上游交接、来源指针和工具定义。成员未设置 `context_size` 时使用服务默认值，可通过 `COCOGEM_HISTORY_MESSAGES` 和 `COCOGEM_HISTORY_TOKENS` 调整。token 数使用保守估算（ASCII 约 4 字节/token，非 ASCII 字符按 1 token/字符），不保证与供应商 tokenizer 完全一致；单条消息预览默认约 4K tokens，大上下文成员最高约 32K tokens，超出部分仍可通过 `read_context` 读取完整正文。

## 配置与启动

开发需要 Go 1.26 系列且至少 1.26.10、Node.js 22.12+ 和 npm，建议 Node.js 24 LTS。构建后的 Web 服务无需 Node.js；CLI 执行仍依赖本机可执行程序。

```sh
make setup
make dev                 # 前端 127.0.0.1:5173，代理本地服务
make build
./dist/cocogem-server     # 默认 127.0.0.1:8741
```

服务参数：

| 参数 | 默认与用途 |
| --- | --- |
| --listen | 127.0.0.1:8741，只接受回环 IP |
| --web-dir | 优先可执行文件同目录的 web/，否则使用 web/dist |
| --allow-root | 可重复；限制可绑定目录及其子目录 |

环境变量必须在启动时传入，程序不自动加载 `.env`；示例见 [`.env.example`](../.env.example)。

| 变量 | 默认与用途 |
| --- | --- |
| COCOGEM_DATA_DIR | os.UserConfigDir()/cocogem，保存 SQLite 与本地访问密码派生值 |
| COCOGEM_SEARCH_PROVIDER | auto；可选 brave、bing、duckduckgo、public、off |
| BRAVE_SEARCH_API_KEY | 可选，仅用于 Brave 在线搜索，无关模型连接 |
| COCOGEM_EXTERNAL_EGRESS_HOSTS | 默认未配置；逗号分隔的精确 host 或 host:port，启用宿主外部 HTTP 写入入口；权限与重定向限制见下文 |
| COCOGEM_WEB_PROXY | 默认直连；env 使用代理环境变量，system 读取 macOS 系统代理，也可指定 HTTP/HTTPS/SOCKS5 地址 |
| COCOGEM_RUN_TIMEOUT / COCOGEM_STEP_TIMEOUT | 0，关闭累计期限；支持 Go duration，如 2h |
| COCOGEM_MAX_PARALLEL_RUNS | 4；同时执行的独立 Run 数，范围 1–16；同一 Task 和 Thread 仍各自串行 |
| COCOGEM_HISTORY_MESSAGES | 128；默认共享历史消息条数，范围 1–1000 |
| COCOGEM_HISTORY_TOKENS | 64000；默认共享历史估算 token 预算，范围 1024–2000000 |
| COCOGEM_FIRST_RESPONSE_TIMEOUT | 10m；0 关闭首响应检测 |
| COCOGEM_STALL_TIMEOUT | 15m；0 关闭无进展检测 |
| COCOGEM_STALL_ACTION | warn；stop 才停止停滞执行 |

auto 优先使用已配置的 Brave，否则回退公共搜索（Bing RSS，再到 DuckDuckGo HTML）；搜索失败明确报告。`make dev` 在未设置代理变量时选择 system，显式空值表示直连。系统代理只读取 host/port，不处理 PAC、订阅或代理凭据；启用原生联网的 CLI 子进程可接收已解析代理，loopback MCP 保持直连并保留原 NO_PROXY。

配置 `COCOGEM_EXTERNAL_EGRESS_HOSTS` 后，宿主可提供外部发布、部署、发布版本或安装的 HTTP 写操作；受控和项目内自主模式仍按操作申请授权，完全访问在任务允许时可直接准入。当前实现只在首次请求前检查 HTTPS 和目标名单，默认 HTTP 客户端可能跟随重定向，后续目标未重新检查名单；不要将其视为对整个重定向链的范围保证。完全访问下的原生联网不受此宿主入口约束。真实公开发布与部署尚未验证。

### 本地访问与数据管理

网页使用首次初始化的密码，长度 12–128 字符。随机盐与 PBKDF2-HMAC-SHA256（600,000 次迭代）的派生值写入私有 auth.json，不保存明文。会话使用 HttpOnly、SameSite=Strict cookie，24 小时或服务重启后失效；变更请求检查 CSRF、Host 与 Origin，连续 5 次密码错误暂停 1 分钟。「锁定工作空间」撤销当前浏览器会话，后台协作继续。

数据目录权限为 0700，auth.json 为 0600。停止服务后整体备份数据目录，恢复前也先停止服务；不要遗漏 SQLite WAL 或密码文件。忘记密码时，停止服务并将 auth.json 移到安全备份位置，再启动重新初始化；数据库保留，网页不提供免密码重置。

本地存储的消息、捕获来源和工程内容可能敏感。模型服务会收到执行所需问题与片段，搜索服务会收到查询；只处理允许分享的数据。完整威胁边界与漏洞报告方式见 [SECURITY.md](../SECURITY.md)。

| --- | --- |

## 验证与验收

GitHub Actions 在 push 与 Pull Request 时只运行 test 任务：保留 Go 版本和操作系统矩阵，安装依赖后执行 `make test`。构建、契约、浏览器、安全扫描和候选包命令保留为本地验证入口；工作流不执行打包、发布或部署。

| 命令 | 验证范围 |
| --- | --- |
| make test | Node 脚本、gofmt、go vet、全包 race/shuffle、前端 Lint/类型/单元测试 |
| make check-contract | 重新生成 OpenAPI 和前端类型，并检查两文件相对 Git HEAD 是否有差异；未提交的预期改动也会导致失败 |
| make build | 前端生产包及 Web 服务可执行文件 |
